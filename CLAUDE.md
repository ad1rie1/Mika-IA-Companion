## Slow tests (backendv2) — 2026-10-04

Long tests are opt-in, to save time and tokens. `tests/conftest.py` deselects every test marked
`@pytest.mark.slow` unless asked:

- `python -m pytest -q` — the default run, slow tests left out (the summary says how many);
- `--slow` adds them; `-m slow` runs only them; naming a file (`pytest tests/unit/test_x.py`) runs its slow
  tests too.

Rules:

1. **Run without `--slow` by default.** Target the files you touched first, then the default suite. Run
   `--slow` only when the change touches what the slow tests exercise (full simulator scenarios, multi-week
   lives, performance, crash/replay), or before handing over a large batch — once, never in parallel.
2. **Mark a test `slow` when it takes more than ~3 s on its own** (`--durations=0 --durations-min=3` to
   find them): `@pytest.mark.slow` on the test, or `pytestmark = pytest.mark.slow` when the whole file is
   long. Never mark a fast test slow to hide it, and never delete or skip a slow test to save time.
   Measured 2026-10-04: the 33 slow tests took ~6 of the full suite's ~10.5 minutes.
3. Every full run (with or without `--slow`) goes through the memory-bounded wrapper
   (`~/recup-audit-v2-2026-10-01/outils/borne.sh`), one full suite at a time on the machine.

## Autonomy contract update — 2026-09-20

See [implementation and limits](docs/autonomie-implementation-2026-09-20.md) and [contract regressions](old/backend/tests/test_autonomie_contrat.py). User-confided frames are immutable to `update_project`; status, priority and schedule remain editable. Local project tools and allowed module tools are assembled through `projects/capabilities.py` for the runner and added for the recognized owner in private conversation, preserving ordinary life tools. External effects are queued when approval is required. Programs require bubblewrap; there is no fallback to server filesystem rights. Stagnation causes bounded backoff (`projects.stagnation_runs_cap`), not a permanent human-presence gate. Background cost is separately bounded by persistent daily credits (24 per project / 96 total by default), consumed before the model call.

Tool traces carry structured outcomes (`utils/tool_results.py`). Scheduled actions are reserved before execution, processed one at a time and retained as `uncertain` when effects need checking. Internal actions can run without audience/broadcast. Autonomous work can discover capabilities, prepare its next toolkit and become a SELF project. Social drive can initiate a contact-selection activity without chat. Relations use canonical identity keys after async hydration; transport IDs still route deliveries. Knowledge retains confidence, epistemic origin and backend-derived source message IDs. Re-extraction alone never increases certainty.

Four schema migrations accompany this change; run `python old/backend/manage.py migrate` before restarting the service. Runtime tests mock external calls. Historical sections below predate some of these changes; this contract and the implementation document take precedence where they differ.

## Architecture

VTuber engine: a 3D avatar driven by Claude AI responses with real-time emotion mapping, evolving self-concept, theory of mind, and intrinsic drives.

### Core model: Perception → Router → Pipeline

Every input entering Mika (chat text, Telegram, internal conscience initiatives, module notifications, future camera/audio/files) becomes a `Perception`. A central router dispatches it based on `Intent`; the processor does the AI call only when a response is needed. Silence is a valid outcome.

```
Sources (WebSocket, Telegram, Conscience, Modules, future: Camera/Audio/File/Sensor)
   │  each source builds a Perception
   ▼
pipeline.router.perceive(Perception)
   ├─ save raw media (if non-text)
   ├─ run modality preprocessors (vision/audio/files → text)
   └─ dispatch by Intent
        ├─ REQUEST_RESPONSE  → process_message(perception)  → broadcast answer
        ├─ INTERNAL_TRIGGER  → process_message(perception)  → broadcast, no event
        └─ OBSERVATION       → module_manager.emit_event    → conscience decides later
```

### Data Flow (text chat turn)

1. Client sends `{"type":"chat","message":"...","person_id":"...","attachments":[...]}` via WebSocket
2. `WebSocketConsumer.receive()` ([old/backend/communication/channels/web_frontend.py](old/backend/communication/channels/web_frontend.py)) validates, builds a `Perception` (text-only or mixed), calls `perceive()`
3. `pipeline.router.perceive()` saves any raw media, runs preprocessors to transform image/audio/file parts into text descriptions, then routes by intent
4. `pipeline.processor.process_message(perception)` runs the full pipeline:
   - **Context assembly** ([pipeline/context.py](old/backend/pipeline/context.py)): memory + emotion + drives + modules + self-concept + per-person context
   - **Prompt building** ([pipeline/prompt.py](old/backend/pipeline/prompt.py)): `build_chat_prompt()` → a structured `ChatPrompt` split along volatility boundaries — stable prefix (personality + self-concept + identity, cacheable), per-turn state (everything else), history as real `{role, content}` turns, current message alone
   - **AI call** ([pipeline/response.py](old/backend/pipeline/response.py)): routes to provider via `ai_router.chat`/`chat_with_tools`. **One time bound, the router's** (`_metered_call`, `ai.call_timeout_seconds`): the processor used to wrap the call in a second, equal `wait_for` that started earlier and therefore always fired first — the router received a `CancelledError`, never a `TimeoutError`, and `_record_partial_usage` never ran on a conversation turn, exactly the tool loop that dies at iteration six. The router now also counts usage on `CancelledError` (a shorter caller bound, a SIGTERM mid-turn). The budget (`ai/budget.py`) is computed for the role that will *serve* the turn — `CONVERSATION_TOOLS` when tools are present — not always `CONVERSATION`. **Every provider gets the structured form**, tooled and untooled — Claude, OpenAI, Ollama, Ollama Cloud, GLM and Gemini all implement `complete_chat` *and* `complete_chat_with_tools`. `ChatPrompt.legacy_pair()` survives only for the router's own character estimate; no provider consumes it (an AST guard pins that). The tool loop lives **once**, in `ai/providers/_tool_loop.py`, primed by one adapter per API family (see « One `Protocol`, one tool loop » below), so the tooled turn — the expensive one, where ~6 500 tokens of tool declarations would otherwise be rewritten on every iteration — keeps a stable cacheable prefix
   - **Emotion processing**: the `[EMOTION:name:intensity]` tag is **the turn's emotional truth**. `extract_emotion` returns `None` when nothing usable was declared — no tag at all, or a name outside the 29 (counted as a degradation) — and the processor then applies **no impulse**: a default `NEUTRAL` is a real target in PAD space, the origin, so a missing tag used to drag an angry state back *through* zero and out the other side, and a parsing miss was lived as a soothing. An explicit `[EMOTION:neutral:0.5]` still is an impulse: "nothing was declared" and "she declared neutral" are different facts. When a tag is present, `EmotionEngine.turn_emotion_view()` makes it what the `speech` frame carries and what `save_snapshot(declared=…)` persists, while the oscillator keeps describing the drift *between* turns
   - **Persistence**: user Message + assistant Message saved with `attachments_meta`, built from the parts carrying `original_kind` and **not** from a `kind != "text"` filter — preprocessing runs in the router *before* the processor and *replaces* the part (an image Part is already `Part(kind="text", content="[image: …]")` here), so that filter matches nothing and persists an empty list
   - **Broadcast**: the `speech` frame (response + emotion state + blend) goes out **first**; the `inner_state` follows as a separate `inner_state_update` frame on the same groups — assembling it (ten loaders + four per-person queries, in series on the shared executor) used to delay the sentence itself. The cosmetic « thinking » delay no longer sleeps inside the single turn worker: `_BroadcastChain` (processor.py) runs the delayed broadcasts detached, **in order** (a fast second reply never overtakes a slow first one), flushed at ASGI shutdown. `persist_user_message` / `persist_assistant_message` failures are isolated and counted: a locked DB no longer turns a real answer into « j'ai eu un petit bug ».
5. Frontend receives `{"type":"speech","text":"...","emotion":"excited","emotion_intensity":0.75,"emotion_blend":[...],"emotion_state":{...}}`, updates VRM blend shapes and chat UI

On AI error or timeout: fallback text returned, **no emotion impulse toward the user**, **no chat.message event**, **no `_turn.completed` announcement** — a failed exchange is not a real exchange. It *is* **persisted**, with the fallback reply flagged `is_internal`: what someone said happened whether or not the model replied, so the question stays in the history / on the person's fiche / in the consolidator's input, while the fallback never becomes a souvenir nor something Mika "said".

### Database — SQLite under permanent concurrent load

Six background loops write continuously (conscience 30s, consolidator 60s, sleep 60s, project runner 30s, module scheduler 1s tick, emotion snapshots), and `sync_to_async` calls interleave with them (the default `thread_sensitive=True` serialises them onto one shared executor thread, so `asyncio.gather` around several buys nothing). On the default `journal_mode=DELETE`, a single writer blocks every reader and Python's 5s busy timeout surfaces as `database is locked`.

[config/settings.py](old/backend/config/settings.py) therefore sets `OPTIONS`: **WAL**, `synchronous=NORMAL`, `foreign_keys=ON`, a 32 MB page cache, and a 30s lock timeout (`DB_LOCK_TIMEOUT`). Invisible in tests (pytest-django uses an in-memory DB where WAL is a no-op), so the regression test asserts the declared `init_command`, not the runtime PRAGMA.

### Backend layout

- **Entry point**: `run.py` (removed with the archive, see Development Commands) — added the backend to sys.path, configured Django, launched Uvicorn
- **ASGI** [config/asgi.py](old/backend/config/asgi.py): `LifespanWrapper` runs startup and a **supervised, budgeted shutdown**. Startup opens the port *before* the long-term memory loads: `memory_manager.initialize(differe=True, sur_echec_fatal=_arreter_le_serveur)` returns with the thread and the compactor ready, and `VectorStore()` (ChromaDB + the embedding model, seconds of CPU) loads in `asyncio.to_thread`; the consolidator, episodic indexer and retriever are built once it is ready. `MemoryManager.etat_memoire_longue` (`absent/starting/ready/degraded/failed`) and `config/readiness.py::etat_processus` (lifespan phase) feed **`/health`**, which is now a readiness probe: `{"status","ready","checks"}`, 200 when a turn can be taken, **503** while `starting`/`stopping`/`failed`; `degraded` (unmapped `conversation` role, dead or late loop, memory in explicit fallback) stays a 200 — the process answers, it only answers worse. A turn received while `starting` runs without recall (`recall_unavailable`). `MEMORY_REQUIRE_VECTOR_STORE=1` keeps its meaning: a refused deferred load logs CRITICAL, raises SIGTERM (clean shutdown) and `run.py` exited **3** (`RestartPreventExitStatus=3` in the unit). Shutdown runs twelve steps each under `asyncio.wait_for` (`BUDGETS_ARRET_S`, 45 s total, pinned below the unit's `TimeoutStopSec=60`): telegram → turn queue drained then stopped → **conscience, modules, project runner, sleep cycle, emotion sync** (before the final passes: a `notify_ai` or a conscience act runs off-queue and used to mutate the mood *after* it was saved) → memory → emotion → delayed broadcasts → `PRAGMA wal_checkpoint(TRUNCATE)`. An overrun is counted (`arret: <step> hors budget`) and never propagated. The consolidator's `stop()` grants an in-flight tick `STOP_GRACE_S` (5 s) then cancels it, and **checkpoints per tranche** (`_pointer_la_tranche`, same `_borne_extraite` rule with the not-yet-done tranches counted as unextracted, so an intermediate bound is always ≤ the final one and never below the current cursor): a stop between two tranches re-extracts nothing already stored; only a cancel landing inside one tranche's store leaves that single tranche to replay. `deploy/mika.service` + `deploy/README.md` (service, `/health`, backup, restore — both removed with the archive) and `scripts/backup.sh` (SQLite online-backup API, WAL-consistent, + Chroma tar + MANIFEST) ship with it; restore resyncs vectors on SQL with `python manage.py reindexer_vecteurs` then `backfill_episodic`. Quotas: every `AIRole` member has its `AI_QUOTA_ROLE_<ROLE>_DAILY/_MONTHLY` pair (a test derives the list from the enum and checks `.env.example`).
- **Communication channels** ([communication/](old/backend/communication/)): adapters that translate external inputs into `Perception` objects and hand them to `pipeline.router.perceive()`. Each channel builds its own Perception; no shared legacy handler.
  - [communication/channels/web_frontend.py](old/backend/communication/channels/web_frontend.py) — `WebSocketConsumer`, greeting routed through `perceive()` as `INTERNAL_TRIGGER`
  - [communication/channels/telegram.py](old/backend/communication/channels/telegram.py) — text AND inbound media: photos / voice notes / audio / documents downloaded (≤5 MB), lifted into a MIXED `Perception` with their caption, preprocessed like any frontend upload. **Bounded like the web path, and for the same reason**: a bot name is discoverable, and every inbound message costs a full pipeline turn. A sliding window per *account* (`tg_<id>`, 20/10 s — the web counts per connection, there is none here), an optional allow-list (`telegram.allowed_chats`, empty = everyone) checked **before** anything is written, so a stranger leaves behind no presence entry, no `IdentityHandle` and no `Message`, and a refusal said out loud rather than dropped. The turn goes through `turn_queue` like a browser's: `python-telegram-bot` dispatches updates in series, so awaiting the pipeline in the handler made the bot deaf for the whole turn (`/start` included) *and* short-circuited the queue — a Telegram message and a web message running as two concurrent LLM calls against a one-slot local backend. The reply therefore comes back through `broadcast_to_websocket` → `deliver()`, which is why dispatch **no longer skips the originating module**: nothing else sends any more. **A reply goes back to the chat that asked.** The presence entry carried « the last chat this account was seen in », which is the right address for a *proactive* act and the wrong one for a reply: a private question queued behind the single worker, then a message from the same account in a group, and the private answer — composed with its full context — was posted in the group. The turn now carries its origin as `metadata["reply_ref"]` → `SpeechOutput.reply_ref`, and `broadcast_to_websocket` hands the deliverer a copy of the target addressed to that chat (`_addressed`, registry entry untouched). Only **private** chat ids are stored as a delivery ref (a group message registers an empty one, which never overwrites a stored private one), so a group can never become the default target for her spontaneous speech. `test_telegram_routing.py` runs the real handler → processor → broadcast with a fake deliverer
  - [communication/routing.py](old/backend/communication/routing.py), [communication/urls.py](old/backend/communication/urls.py), [communication/views.py](old/backend/communication/views.py) — WS routing + HTTP health/personality endpoints
- **Pipeline** ([pipeline/](old/backend/pipeline/)):
  - [pipeline/perception.py](old/backend/pipeline/perception.py) — `Perception`, `Part`, `Modality`, `Intent`, constructors (`from_text`, `from_internal_trigger`, `from_mixed`)
  - [pipeline/router.py](old/backend/pipeline/router.py) — `perceive(Perception)` single entry point; saves media, runs preprocessors, dispatches by Intent
  - [pipeline/processor.py](old/backend/pipeline/processor.py) — `process_message(perception, *, context, broadcast, persist, emit_event)`; returns `SpeechOutput`
  - [pipeline/context.py](old/backend/pipeline/context.py) — `gather_context()` → `ConversationContext` (memory, emotion, drives, modules, history, tools, `self_concept`, `person_context`)
  - **Les trois orchestrateurs du pipeline sont courts, et un test les tient courts** (`test_pipeline_orchestrateurs.py`, AST : `gather_context` ≤ 80 lignes de code, `process_message` ≤ 100, `broadcast_to_websocket` ≤ 40, docstring exclue, plus l'ordre des étapes de `process_message` pinné sur les `lineno` des appels). Ils faisaient ~300, ~450 et ~130 lignes — des corps trop longs pour être lus alors que chacun n'est qu'une suite d'étapes dont l'ordre est porteur. Rien n'a été réécrit : le code a été **déplacé** en fonctions nommées par question. `gather_context` appelle `_lancer_le_rappel` / `_achever_le_rappel` (plan de préparation + spéculatif), `_humeur_et_pulsions`, `_contexte_modules`, `_fil_de_conversation`, `_etat_cognitif`, `_ton_de_la_personne`, `_reve_et_journal`, `_projet_du_tour`, `_outils_de_la_conversation` ; `process_message` enchaîne `_identifier_passivement` → `_contexte_du_tour` → `_ecrire_la_question` → `_interroger_le_modele` / `_texte_de_repli` → `_ressentir` → `_ecrire_la_reponse` → `_annoncer_le_tour` → `_vue_emotionnelle` → `_diffuser` ; `broadcast_to_websocket` fait `_cibles` → `_trame_speech` → `_decider_la_voix` → `_sans_cible` | `_livrer`. Deux modules voisins de `pipeline/context.py` portent ce qu'il orchestre : [pipeline/context_blocks.py](old/backend/pipeline/context_blocks.py) — les formateurs de blocs de prompt et les lecteurs par question (`_fetch_*_context`, `_format_*`, `detect_user_mood_hint`, les plafonds `_*_MAX_*` et `_clip`) — et [pipeline/context_history.py](old/backend/pipeline/context_history.py) — l'historique étiqueté et daté (`_label_history_speakers`, `own_handles`, `_stamp_history_gaps` et son mémo `_MESSAGE_DATES`, `_last_contact_gap`). La règle du découpage n'est pas la longueur mais la dépendance : ce qui lit un singleton vivant (`memory_manager`, `emotion_engine`, `drive_engine`, `module_manager`) reste dans `context.py`, où les tests le patchent ; les blocs passent par la couche de lecture, et le garde de `test_inner_state_read.py` (« jamais un `Model.objects` direct », désormais sur l'AST) couvre les trois modules. Les labels `degradations.record` du chemin chaud n'ont pas bougé d'un caractère — chacun vit dans exactement une fonction, ce que `test_degradation.py` continue d'exiger.
  - [pipeline/prompt.py](old/backend/pipeline/prompt.py) — `build_prompt_parts(context)` (stable/volatile split), `build_system_prompt(context)` (their recomposition, byte-identical to the pre-split rendering — a test re-implements the old algorithm as the oracle), `build_chat_prompt(context, message)` → `ChatPrompt`, and `format_conversation()` (legacy flattener, kept for compat). The `_LAYERS` table still runs the show — **the order is the table, and the table is what runs**; `_STABLE_LAYER_COUNT = 2` marks the cache boundary (self-concept + identity join personality in the stable prefix, everything from `person_context` on is per-turn). Footers stay deliberately inconsistent. `getattr` is strict, no default — a typo'd field name would otherwise silently drop a block from every prompt. `ConversationContext()` with no arguments is valid.
  - [ai/chat.py](old/backend/ai/chat.py) — `ChatPrompt`: the structured turn. `chat_messages()` renders history as real message turns (leading-assistant guard for the greeting-first buffer, alien roles dropped) and embeds the volatile state at the top of the **final user turn**, wrapped in `--- ETAT INTERNE --- / --- FIN ETAT INTERNE ---` — after every cache breakpoint, so per-turn state never invalidates the cached prefix. `legacy_pair()` reproduces the old two-string shape byte-for-byte for fallback providers. Lives in `ai/` because providers consume the type; never imports `pipeline`.
  - [pipeline/response.py](old/backend/pipeline/response.py) — `call_ai_and_parse()` builds the `ChatPrompt`, calls AI, extracts emotion
  - [pipeline/broadcast.py](old/backend/pipeline/broadcast.py) — `broadcast_to_websocket()`, `emit_communication_event()`, and persistence **split in two**: `persist_user_message(..., attachments_meta)` before the AI call, `persist_assistant_message(..., replying_to=)` after. The order is the point: the AI call is the long fragile part of a turn, and persisting afterwards meant a restart erased the *question* too. Writing first turns that into a merely-unanswered question, recoverable via `Message.awaiting_reply` (migration `memory/0015`). The user side is written *after* `gather_context` — `add_message` also appends to the short-term buffer that `gather_context` just read, so persisting earlier shows the model the current message twice. `persist_assistant_message` clears the flag **including for a failed turn**, or the same failing turn replays at every boot.
  - [pipeline/turns.py](old/backend/pipeline/turns.py) — `TurnQueue`, the pool that answers people. Channels dispatches a consumer's frames one at a time, and awaiting the pipeline inside `receive()` made the connection deaf for the whole turn (no pong, no catch-up), so liveness watchdogs reconnected mid-turn. A bare `create_task` per message would instead give out-of-order replies and concurrent LLM calls, which a one-slot local backend just queues. Hence a queue with a small fixed pool (`pipeline.turn_workers`, default **1**; raise only behind a hosted API). The reply finds its way back because `broadcast_to_websocket` sends to the *person's* group, never to the socket that asked — **a turn never needed the connection that started it**. Backlog past `MAX_PENDING` is refused out loud (`ack: overloaded`); one broken turn never takes the worker down (nothing supervises this pool). `resume_interrupted_turns()` runs at ASGI startup and re-queues what `awaiting_reply` marks, clearing the flag **as it re-queues, not on success**, so a turn that dies twice cannot form a crash loop. A replayed turn carries `original_message_id` and the processor **reuses that row instead of re-writing the question** (a second copy would show on the fiche, in the consolidator, and on screen). **It also replays with its transport's trust**: `persist_user_message` writes `{authenticated, is_public, reply_ref}` into `Message.transport_meta` (migration `memory/0018`, a second small `aupdate` so `add_message` stays transport-agnostic), and `resume_interrupted_turns` restores them — a rebuilt perception used to carry empty flags, so a Telegram *group* message interrupted by a restart replayed as a private ACCOUNT turn, cleared disclosure, and answered in the group. A row with nothing stored is fail-closed per channel (Telegram → public, web → unauthenticated). Deliberately not in scope: serialising every LLM call in the process — conscience, project runner and sleep cycle never pass through here; "never two calls at once on a one-slot backend" belongs to the AI router as a per-provider semaphore.
  - [pipeline/preprocessors/](old/backend/pipeline/preprocessors/) — modality-specific Part transformers. `vision.py` captions via `AIRole.VISION_CAPTION`. `audio.py` transcribes via the OpenAI provider's Whisper endpoint (`ai_router.provider_by_name("openai")` — router cache, so credential rotation applies; no other provider exposes STT). `files.py` extracts text locally: text-like MIME/extensions (utf-8 → latin-1 fallback), HTML tag-stripping, PDF via `pypdf`, DOCX via optional `python-docx`; parsing runs in a thread. Failures + timeouts produce a safe text placeholder — an error is never surfaced as content.
  - [pipeline/media.py](old/backend/pipeline/media.py) — attachment validation + raw media persistence. The knob is `ai.<provider>.max_concurrent_calls` (Configuration → *IA · Providers*), **declared for all six providers**, `0` = unbounded; only the *default* is provider-specific: **1 for `ollama`**, unbounded elsewhere. Declared everywhere because the reason to cap differs rather than disappears — on a hosted API the parallelism is real, but it is billed and rate-limited, and a burst of background loops can exceed a provider's rate limit on its own. A one-slot local server does not run two calls in parallel, it *queues* them, and that queue time is counted **inside** the same `ai.call_timeout_seconds` bound the generation gets: a conversation turn arriving behind two background generations returns the fallback text and looks exactly like a slow model. `TurnQueue` orders the *turns*; this orders the *calls* — the six background loops never pass through the queue. Wait and generation therefore **share one budget** and are **logged separately**: waiting for a slot is time spent inside the call, not time granted on top of it (the acquisition is bounded too, or a background loop — the caller with no `wait_for` of its own, the very reason the router took the bound over — would queue unbounded behind the loops ahead of it). An acquisition that never lands says so rather than vanishing. A nested call (an MCP tool re-entering the model from inside the tool loop, e.g. `files_analyze_image`) **reuses its caller's slot** via a ContextVar — otherwise it would wait for a slot its own caller holds, until the timeout.

This is the fix for the first of the two audit blockers: with the old parameters ζ=0.65, ω₀=0.23 the state returned to rest in **~27 s**, shorter than the gap between two turns (30–120 s), and the impulse only wrote *velocity* — so every reader of the position (prompt, snapshot, person fiche, gestures) read a state that had already gone home. - **Retention sweep** ([memory/retention.py](old/backend/memory/retention.py)): declarative ceilings on append-only tables, applied hourly from the consolidator tick (both paths). `Dream` (365 d / 2 000), `EmotionalSummary` (365 d / 20 000) and `SelfNarrative` (200 rows) joined the list; `Theme` and `Entity` deliberately have none (no date, and an orphan entity is cheap). `POLICIES` is a tuple of `Policy(app_label, model_name, date_field, keep_days, keep_rows, protect)`. `ConscienceLog` gets a row on **every** decision cycle (~2 880/day at 30s), plus `ConsolidationLog` (only the newest row is read), faded `Rumination`s (active/resolved protected — journals and digestion reference them), `ProjectLog`. - **Module plugin system**: [modules/base.py](old/backend/modules/base.py) (`BaseModule` ABC) + [modules/manager.py](old/backend/modules/manager.py) (`ModuleManager` singleton). Each module is a subfolder with its own `models.py`; `modules/models.py` re-exports for Django discovery.

Empty = every running module: right behind a hosted API, wrong behind a local one, since a tool declaration is *prompt* re-sent on every turn of the tool loop — the nine shipped modules weigh **~6 500 tokens against a ~1 500-token system prompt**. Measured on `gemma4:12b`, a greeting cost 76 s against a 60 s timeout; narrowing the list and raising `ai.call_timeout_seconds` (default now **120 s**) brought it to 14,6 s. The excluded modules' tools stay usable everywhere else — conscience, projects, background ticks; only the conversation is lightened.
- **`ModuleManager` is a façade, not the subsystem.** ~200 lines of one-line delegations (a method growing a second line belongs in a collaborator):
  - [modules/registry.py](old/backend/modules/registry.py) — who exists, who is active, what `ModuleState` says. Absorbs `config_schema()` **before** the availability check (the point of surfacing a schema is to configure a module that can't run yet).
  - [modules/lifecycle.py](old/backend/modules/lifecycle.py) — start/stop/enable/disable/uninstall, table install, and the **only** place a module is attached to or detached from the bus. A module whose `instantiate()` raised is never subscribed.
  - [modules/scheduler.py](old/backend/modules/scheduler.py) — `CronScheduler`, 1s tick, per-module `CRON_INTERVAL` or `modules.cron_tick_interval`. Ticks run **detached** (awaiting inline made the scheduler as slow as its slowest module, forever on a hung socket). One tick per module at a time; an overlap is **skipped, not queued**. `stop()` reaps in-flight ticks.
  - [modules/collectors.py](old/backend/modules/collectors.py) — tools / capabilities / prompt context / routes / views, plus the tool cache (invalidated by the lifecycle via an `on_change` callback) and `is_owner()`, the per-person visibility rule for `get_context()`.
  - [modules/notify.py](old/backend/modules/notify.py) — the notify_ai bridge.
- **Event bus** ([utils/eventbus.py](old/backend/utils/eventbus.py)) — a real registry, replacing an `emit_event` that named two of its three consumers in its own source:
  - Lives in `utils/` with **zero dependencies** and never imports `modules`: a subscriber only needs an event carrying `event_type` + `source_module` (structural `Event` Protocol — `ModuleEvent` satisfies it).
  - **Patterns**: `*`, `email.*` (namespace prefix), or exact. Trailing star only, deliberately.
  - **Reserved internal namespace** — an event type starting with `_` is engine plumbing and a wildcard does **not** reach it; it must be named explicitly. Wildcard subscribers are the norm here (the conscience subscribes `*`, the Forge relays `*` to sandboxed modules), so without the reserve one lifecycle signal would file an Observation, burn an interpretation LLM call and wake every forged module once per turn.
  - **Two delivery modes**: `AWAIT` (emitter waits — correct when ordering is observable) and `SPAWN` (detached). Modules declare theirs via `EVENT_PATTERN` / `EVENT_MODE` / `EVENT_PRIORITY` / `EVENT_TIMEOUT` on `BaseModule`.
  - **Priority bands** — `PRIORITY_OBSERVER` (10) / `DEFAULT` (50) / `LATE` (90).
  - **A subscriber never receives its own events** (`receive_own=False`). The Forge depends on this: it fans an event out to sibling forged modules itself, excluding the emitter.
  - **Failures are counted, not swallowed.** One broken subscriber never stops the fan-out and `emit()` never raises, but `event_bus.stats()` reports per-subscriber `delivered` / `failed` / `last_error`. `timeout=` bounds an AWAIT subscriber.
  - **Duplicate name replaces** rather than raising or appending (a hot-reloaded forged module re-subscribes under the same name).
  - Core subsystems **declare their own interest**: `ConscienceEngine.initialize()` subscribes `observe` (and `shutdown()` unsubscribes), `projects/apps.py::ready()` subscribes the `event:<type>` waker. `module_manager.set_conscience()` survives as a one-line shim for ASGI startup.
- **notify_ai vs emit_event** — `emit_event` = "this happened": fan-out, no reply, nobody obliged to care. `notify_ai` = "answer this": one `INTERNAL_TRIGGER` Perception through the full pipeline, returning what she said. Modules reach the latter through the injected callback so they never import the pipeline.
- **Email module** ([modules/email/](old/backend/modules/email/)): IMAP/SMTP. Polls inbox (60s), triages with Haiku, stores `ProcessedEmail`, creates souvenirs/connaissances, notifies via `notify_ai`. Exposes `list_recent_emails`, `send_email` tools. Disabled gracefully if no config.
- **Forge** ([modules/plugins/forge/](old/backend/modules/plugins/forge/)): AI-self-managed modules. One host plugin (`forge`) loads N sandboxed mini-modules that **Mika writes herself** into `data/forge_modules/` (`FORGE_DIR`). See dedicated section below.

### Admin interface — access control and payload safety

The dashboard reads the entire conversation history and writes the config, including provider API keys. Three layers stand between that and the network:

- **`ALLOWED_HOSTS` is not wildcarded** — `*` disables Host-header validation, which is what stops `Host: evil.test` from making the app generate absolute URLs pointing at an attacker's domain. Defaults to the loopback names actually served, plus the machine's own hostname/IP when `API_HOST` is not loopback; override with `ALLOWED_HOSTS` in `.env` behind a reverse proxy.
- **Loopback by default** — `API_HOST` defaults to `127.0.0.1`. Set `API_HOST=0.0.0.0` to serve the LAN; `run.py` (removed) then logged a `SECURITY:` warning if `DASHBOARD_REQUIRE_AUTH` is off.
- **Optional auth gate** — [GestionSysteme/middleware.py](old/backend/GestionSysteme/middleware.py) `GestionAuthMiddleware` covers the whole `/gestion/` prefix when `DASHBOARD_REQUIRE_AUTH=1`: HTML redirects to `LOGIN_URL` (default `/admin/login/`) with `?next=`, API requests get 401 JSON. Staff-only, so a chat-frontend account doesn't inherit the config editor. **Off by default** — a fresh install has no superuser, and locking the owner out before `createsuperuser` is worse than loopback exposure. One middleware rather than 66 decorators.
- **Three account levels, one definition** ([identity/roles.py](old/backend/identity/roles.py)): a *chat account* (`user_<pk>`, any login) talks to Mika over the WebSocket and touches only its own files; an *operator* (`is_staff` + `is_active`) administers her — `/gestion/`, the `/api/*` administration routes, every uploaded file; an *owner* — operators **plus** `OWNER_PERSON_IDS` (handles with no Django account, e.g. your `tg_<id>`) plus Mika's internal channels (`conscience*`, `module_*`) — reads the private module context and gets a chantier's full récit. Operators are owners by construction: `/gestion/` already shows them the whole conversation and configuration. `is_owner` used to return true for **every** `user_*`, so a login created in *Accès · Comptes* to chat could approve an email send, erase a forged app, launch a workshop tool loop (python/node with the server's rights), read the raw AI prompt history and everyone's uploads. `modules.collectors.is_owner` is now a re-export of `identity.roles.is_owner` (the name `files/service.py`, `conscience/travaux.py` and the tests' patches use). The operator set is a RAM `frozenset` of staff pks — `is_owner` runs synchronously inside coroutines (context assembly, every `files_*` op, the confident choice) — invalidated by `post_save`/`post_delete` on `User` (wired in `identity/apps.py`), expired after 60 s for out-of-process edits, filled from a helper thread when called on the loop (the ORM refuses a sync query there), and **fail-closed** on a failed read, memoised 5 s so a locked DB is not re-hit on every turn. The *Accès · Comptes* `is_staff` field is labelled « Opérateur » and `whoami` reports `operator`.
- **The JSON API requires an operator** — the same middleware gates `/api/*` on `CONSUMER_REQUIRE_AUTH`: an anonymous request gets **401 JSON**, an authenticated non-staff account **403 JSON**, never a redirect (the caller is `fetch`). The default is operator on the whole prefix, so a route added tomorrow is born gated; `CHAT_API_PREFIXES` (empty — nothing « conversation » lives under `/api/`, the SPA speaks over the socket) declares what stays open to any account. Covers projects (create/detail/delete/advance/tasks/pending approve-reject/history `?full=1`), `/api/modules/forge/*` and `/api/modules/wake/*`, `/api/ai/quota/*`, `/api/dev/sleep/*`. `/auth/*`, `/health` and `/personality` stay public; `/gestion/api/*` keeps its staff gate. Tests: `test_roles_comptes.py` (78), `test_api_auth_gate.py`; the endpoint-logic tests still run with the flag off.
- **CORS is not wildcarded** — `CORS_ALLOW_ALL_ORIGINS` defaults to `False` with the dev frontend origins allow-listed. It previously followed `DEBUG`, so any visited page could read the history and rewrite the config cross-origin.

**Panel payloads** ([GestionSysteme/panel_payload.py](old/backend/GestionSysteme/panel_payload.py)) — one JSON contract, `{"version": 2, "blocks": [...]}`, decoded to typed blocks and rendered by autoescaped Django templates. Unknown blocks and keys are rejected, links are restricted to HTTP(S) and local navigation, and composition depth and size are bounded. `utils/sanitize.py` and its Forge re-export were deleted: no payload key becomes raw markup. Only native Python plugins may declare a `Template` block pointing to a template shipped with their code.

**Access accounts are editable from the dashboard** ([GestionSysteme/config_schema.py](old/backend/GestionSysteme/config_schema.py) + [config_backend.py](old/backend/GestionSysteme/config_backend.py)) — Configuration → *Accès · Comptes* (`order=10`, first: it decides who reads every other section). A `record_list` whose backend is Django's `User` table, so nothing lands in `ConfigRecordItem` and the dashboard never becomes a second source of truth about who may log in. Three rules the generic backend can't express: a **password is never read back** (reads report presence only; writes go through the same `validate_password` as bootstrap); **no lockout** — deleting, deactivating and demoting the last active admin are all refused, compared *before vs after* rather than "after ≥ 1" so a DB with no admin yet isn't frozen; and refusals are **loud** (4xx, French message). `person_id` (`user_<pk>`) is surfaced `readonly`. The section is only as protected as the dashboard itself. Tests: `test_comptes_acces.py` (34).

**Config write path** — record-list rows go through the same `_coerce` + `_validate` as scalar items, row CRUD invalidates the cache before notifying subscribers, `registry.register_replace()` invalidates each replaced key, and `config_service.set()` on a blank sensitive field returns a **redacted** marker rather than the decrypted current secret. **A blank `int`/`float`/`select` is refused** (French message pointing at « réinitialiser »): `_coerce` turned `""` into `None` and `_validate` skipped `None`, so a cleared number field wrote a row holding NULL that `config_service.get()` returned verbatim to direct callers, past every min/max. **Row CRUD is audited with the row**: `add_row`/`update_row`/`delete_row` record the real `row_id` and a scrubbed `before` snapshot — a deleted login account used to leave « row_delete on accounts.users » and nothing else (`test_config_ecritures.py`).

**CSRF is enforced.** `CsrfViewMiddleware` is installed, **no endpoint is `@csrf_exempt`** (24 decorators removed — a middleware every view opts out of protects nothing), and a test asserts the string never comes back. It matters because sessions gained authority: with a logged-in owner session, a forged POST to the configuration form rewrites provider API keys.

- Token plumbing: `/auth/whoami` carries `@ensure_csrf_cookie` (the client's *first* call) and the SPA reads it in `postJson()`. GestionSystème needs none of that: every write is a server-rendered form carrying `{% csrf_token %}`.
- `CSRF_TRUSTED_ORIGINS` mirrors `CORS_ALLOWED_ORIGINS`; `CSRF_COOKIE_HTTPONLY=False` because the SPA must read the token. The cookie is not the secret — the *matching pair* is what a cross-site page cannot produce.
- Tests use `Client(enforce_csrf_checks=True)`: the default test client disables CSRF entirely.

**WebSocket origin validation** — `OriginValidator` wraps the socket stack ([config/asgi.py](old/backend/config/asgi.py)), allow-listed against the same CORS origins. Necessary because **CORS does not apply to WebSockets**: any visited page could open `ws://…/ws` and the browser would attach the session cookie. A missing `Origin` header is rejected.

### GestionSystème — the server-rendered admin ([GestionSysteme/](old/backend/GestionSysteme/))

Mounted at `/gestion/`. The `dashboard` app, `ModuleView`, legacy payload adapters and HTML sanitizer are deleted. Pages use shared Django components, reading cards, inspectable rows and dedicated record pages; the API contract is documented in [docs/gestion-interface.md](docs/gestion-interface.md), and the full page inventory, pagination choices and limits in [docs/gestion-audit-pages.md](docs/gestion-audit-pages.md).

- **Rendering is Django templates.** Autoescaping is on and there is nothing left to sanitize.
- **Writes are forms + POST + redirect.** No `fetch` to sign; `{% csrf_token %}` does it.
- **URL is the state.** Tab, page, filters and sort live in the address — shareable, bookmarkable, back-button-correct.
- **9 destinations instead of 23.** The old menu mirrored the DB schema; the seven memory views are seven tabs. A test caps top-level entries.
- **Three JSON routes**: `/gestion/api/vitaux` feeds the top bar; `/gestion/api/panneaux/schema` publishes the v2 panel schema, including manifest views, actions and fields; `/gestion/api/suggestions/<source>` searches four closed native sources (themes, history handles, Forge log apps and project-owner persons), with at most 20 results and a `more` flag. All use the same operator gate as the rest of `/gestion/`. Suggestions are uncached and progressively fill native datalists; manual input still works without JavaScript. `gestion.js` adds themes, confirmations, collapsible mobile filters, navigation aids and vitals refresh; it never injects data with `innerHTML`.

**Layout**: `nav.py` (menu + tabs spec), `shell.py` (page context, badge counts, vitals — every read isolated, since this is the screen you open *because* something is broken), `tables.py` (pagination/filters; cell markup stays in the page template), `forms.py` (ConfigItem → HTML and back), `panels.py` (module spaces), `formatting.py` + `templatetags/gestion.py` (text only, never markup).

**Page logic and pagination.** A missing filter applies its default; an explicit empty “Tous” value disables it. `FilterSet.preserve()` keeps independent lists and repeated parameters. `paginate()` breaks object-order ties with the primary key, without changing aggregate groups. Growing native lists are paginated, including tasks, project logs/files/AI traces, config record lists (one shared `record_lists` builder), module/app catalogs, tools, bus subscribers and emotional archives. Live snapshots and config backends still provide full in-memory collections before slicing. Fixed role/provider/drive/policy references stay together. Forge handlers own their data pagination; the renderer cannot fetch omitted rows.

**Project fiches show their description first, then progress and pending decisions**, followed by a readable task plan with direct status buttons and collapsible execution settings. The guardrail comes from `projects.runs_since_input_cap` on both list and detail. Each history has its own page parameter; `ProjectPromptHistory` is exposed through the closed `prompt-projet` record type. Text disclosures and record prose are capped at 100,000 characters, record JSON at 200,000, always with an explicit truncation marker. Project owners are restricted to persons in both lookup field and model validation, suggested by name and displayed as “Name (#id)” in edit forms. Status values derive from the task model. The schedule page defaults to pending intentions, orders retries by their effective next attempt and displays both relative and absolute dates. Empty states distinguish normal inactivity from unmatched filters. Health keeps all failing subscribers and loops visible; the paginated full bus list preserves delivery order.

**Social and night-time reading.** Person/identity messages reuse the Memory reading cards, including attachments and conversation links. Person live moods are independently paginated (3 in the overview, 12 in Affect); handle previews link to the full list, whose principal handle stays first. Commitments put pending deadlines before recent history. The closed `journal` and `reve` record types expose night-time sources, with source pagination and missing-reference notices. Drive screens describe the current growth curves and persisted state, not a zero linear rate or a reset at boot. Camera panels distinguish a stopped module from an authorized analysis loop.

**Configuration is three spaces.** *Fixed* (`/gestion/configuration/`) holds the core sections, *dynamic* lives in each module's own space, *forged* in each app's own space. `core_sections()` draws the line by excluding the `module_` and `forge_` prefixes; old section URLs redirect rather than 404. Nothing in the view knows any module — the registry describes the fields and the same form engine renders them, so a new `ConfigItem` appears with no code change. Secrets **never reach the browser**: the field ships empty, blank means unchanged. A `__champ` marker per rendered field distinguishes an unchecked box (absent from POST but on screen → save `False`) from a setting simply not in the form (don't touch).

**All three spaces render the same two partials** — [partials/reglages.html](old/backend/GestionSysteme/templates/gestion/partials/reglages.html) (toolbar, table of contents, blocks, save bar) and [partials/listes.html](old/backend/GestionSysteme/templates/gestion/partials/listes.html) (record-list tables), fed by `views/config.py::contexte_reglages()`. They each carried their own copy before, so an improvement reached one screen and a fix left the other two behind. A module or a forged app now gets search, collapsing and the modified badge without knowing they exist.

**Projects are the one thing you *create* here** ([project_forms.py](old/backend/GestionSysteme/project_forms.py)) — plain Django `ModelForm`s, deliberately **not** the `ConfigItem` engine (a project is a real ORM model with relations, choices and JSON fields). Three rules the form adds: an **invalid schedule rule is refused** (`schedule.parse_rule` never raises — right for LLM-supplied text, but from a form `interval:5min` would silently mean "manual" forever); `allowed_modules` is a **closed multi-select** of registered modules (a typo quietly *closes* access); and `next_run_at` is **recomputed on every save**. List fields (`instructions`, `keywords`, …) are one-value-per-line textareas. Tasks are added from the project fiche, with the task id checked against its project.

### Declaring a configuration screen

A settings page is **entirely declarative**: no view, no template, no CSS. You describe what exists; the same engine renders the core, a module's space and a forged app's space identically. Everything below except `ConfigItem` is optional, and a schema that declares none of it renders as a plain field list — the way every section did before this existed.

```python
from configs.types import ConfigFamily, ConfigGroup, ConfigItem, ConfigSection

CONFIG_SCHEMA = [
    ConfigSection(
        key="mon_truc", label="Mon truc", icon="◈", order=55,
        family="vie_interieure",                     # intertitre de la barre latérale
        summary="Une ligne, affichée en infobulle.", # ~90 caractères
        description="Un paragraphe, affiché en encadré en haut de la page.",
    ),
    ConfigGroup(
        section="mon_truc", key="Cadence", order=10,
        description="Ce que ce bloc pilote dans le système qui tourne.",
    ),
    ConfigGroup(
        section="mon_truc", key="Bornes internes", order=20, advanced=True,
        description="Replié par défaut — on ne l'ouvre qu'en diagnostic.",
    ),
    ConfigItem(
        key="mon_truc.intervalle", type="int", section="mon_truc",
        group="Cadence",                              # doit valoir le `key` d'un ConfigGroup
        label="Intervalle (s)", default=30, min=5, max=3600, hot_reload=True,
        hint="Ce qu'il faut savoir avant de changer la valeur.",
    ),
]
```

**The four organizing primitives.**

- **`ConfigFamily`** — a sidebar heading. Declared once in [GestionSysteme/families.py](old/backend/GestionSysteme/families.py) (`acces`, `personnage`, `intelligence`, `vie_interieure`, `conversation`, `canaux`, `travail`, `systeme`); a module may declare its own. Sections *say* which family they belong to. The previous arrangement **guessed** it from the key prefix (`comm_`, `ai_`) and dropped everything else into a bin called « Cœur » — fine at four sections, a flat list with a label on it at fifteen. A section that declares nothing falls back to the prefix heuristic, so a migration never breaks the screen; a test asserts nothing lands in « Non classé ».
- **`ConfigGroup`** — metadata for a `ConfigItem.group`. `key` is the **exact string** used in `group=`, not a parallel identifier to keep in sync. It buys three things a bare string cannot: a chosen order, a sentence saying what the block controls, and `advanced=True`.
- **`advanced=True`** collapses the block into a `<details>`. Collapsed is not hidden: it stays searchable, Ctrl+F opens it, and **it opens by itself when it contains a modified value** — hiding from the operator what the operator changed is the one way to make collapsing harmful.
- **`summary` / `description`** on the section — one line for the sidebar tooltip, one paragraph for the page header.

**Writing a group description** is most of the work, and the rule is: say what the block does *in the running system*, not what the field name already says; when a failure mode is known, name it. « Quand le fil devient trop long, les vieux échanges sont repliés en un résumé. Le verbatim, lui, ne bouge pas » beats « Réglages de compaction ».

**A section splits into tabs by itself.** Its content has two natures: *settings* (a form you skim and save in one go) and *lists* (`record_list` — a table whose rows are each created, edited and deleted on their own). Stacked, they gave the Email module a five-field form followed with no transition by a table of accounts and its buttons — two different gestures in one screen. Each `record_list` therefore becomes its own panel, the scalars share a « Réglages » panel, and the tab bar appears **only past two panels**: a single choice is not a choice. Nothing is declared — the split follows what the section already contains, so a module that adds a list gains its tab without the interface knowing its name. The open panel lives in the URL (`?panneau=`), and an unknown value falls back to the first panel rather than rendering an empty page.

**What the renderer then gives you for free**, on all three spaces: the tab split above, a table of contents above 3 blocks, accent-insensitive multi-word search (`?q=`), a « modified only » filter (`?vue=modifies`), a per-section count and modified badge in the sidebar, a « modifié » pill on every field carrying a stored value, a sticky save bar, and a reset disclosure that only appears when something is actually modified. Filters live in the URL, so a filtered screen is shareable and the back button undoes it.

**Value types**: `str`, `text`, `int`, `float`, `bool`, `secret`, `select`, `multiselect`, `list`, `lines`, `record_list`, `yaml_block`. Two are easy to confuse — `list` splits on commas (keywords), `lines` splits on newlines (sentences). Character traits, instructions and any prose list want `lines`; `list` would cut « Curieuse de tout, pas juste de tech » into two entries.

**Forged apps get the same treatment.** A manifest `config:` field accepts `group:` and the `lines` type, and [forge/module.py](old/backend/modules/plugins/forge/module.py)`::_build_config_entries` turns those into real `ConfigGroup`s under a section carrying `family="systeme"` — so an app Mika writes at runtime lands in the same organized screen as the core, with no interface code aware of it.

**Field layout, three tracks.** A field emits *label*, *control*, *notes* — always the three, so `.form-grid`'s subgrid can give each track the height of the tallest in the row and align every input. The order matters and is not the original one: the description used to sit **between** label and control, so a field with no description inherited the hole dug by a neighbour with three lines of it. All prose — description, hint, input format, secret status, error — now lives in the last track, under the control, where an empty track pushes nothing. For the same reason the control track carries **only** the input: the secret status line lived there and set the row's control height for everyone. The grid also follows the field count (`cols-1` / `cols-2` / auto), because `auto-fill` reserves a column whether or not anything occupies it.

Guarded by [test_config_rapatriement.py](old/backend/tests/test_config_rapatriement.py): every section declares a family and a summary, every non-`record_list` setting sits in a declared and described group, any section past 30 settings collapses at least one block, no prose precedes its control, the grid matches the field count, the Email module splits in two panels, and no template hardcodes a `max-width` in an inline style.

**Dynamic choices** ([choices.py](old/backend/GestionSysteme/choices.py)) — a field whose options depend on *another field* plus a network call, which the registry cannot express. A `DynamicField` names the driving field and a loader; `ai.models`/`model_id` is driven by `provider` and dispatches to the provider's own `list_models()`. Three properties: **loading is explicit** (a button, not every page render), it is a **plain server round-trip** carrying the in-progress input in the POST (no JS, and `__charger` never writes a row), and the field **stays typeable when loading fails** — an unreachable provider is exactly when you come to repair the config. A current value missing from the loaded list is re-injected as an option.

**Module spaces.** Each module owns `/gestion/modules/<name>/`: state, lifecycle, configuration and panels under one sub-nav, present as soon as the module is **registered** (not only while running — the settings of a broken module must stay reachable).

### Forge — AI-self-managed modules ([modules/plugins/forge/](old/backend/modules/plugins/forge/))

Confined space where **Mika creates/edits/tests/deletes her own mini-modules** at runtime (hot reload, no restart). Full doc: [modules/plugins/forge/README.md](old/backend/modules/plugins/forge/README.md).

- **Layout**: each forged module lives in `data/forge_modules/<slug>/` — `manifest.yaml` (title, `schedule`, `events` patterns, `views`, `config` fields, `allowed_domains`, `context`) + `module.py` (sandboxed code) + `state.json` (host-managed: enabled, disabled_reason) + `_versions/` (auto-snapshots, rollback); erased modules go to `_trash/`.
- **Sandbox** ([sandbox.py](old/backend/modules/plugins/forge/sandbox.py)): AST validation at write time (no `import`, no async, no `_`-prefixed attribute access, no `eval/exec/open/getattr/type/...`, no `.format`), curated builtins + read-only safe modules (`math json re datetime random statistics collections itertools functools hashlib base64 uuid copy string`) at exec time, per-handler deadline via `sys.settrace` in a dedicated 2-worker thread pool. Handlers are sync; the host wraps them async.
  - **Two escapes closed**, both verified exploitable: *frame walk* — `f_* / gi_* / cr_* / ag_* / tb_*` attributes are not `_`-prefixed, so `gen.gi_frame.f_back` climbed into host frames whose `f_builtins` holds the real `__import__` → RCE; those prefixes are now `FORBIDDEN_ATTR_PREFIXES`. *Catchable deadline* — `ForgeTimeout` derived from `Exception`, so `while True: try: … except Exception: pass` swallowed its own timeout and pinned a worker forever; it now derives from `BaseException`, and the validator rejects bare `except:` plus references to `BaseException`/`ForgeTimeout`/`SystemExit`/`KeyboardInterrupt`/`GeneratorExit`.
  - **A third escape closed**, verified as full RCE: *transitive modules* — a safe module exposes the modules it imports under plain names (`uuid.os`, `json.codecs`, `re.enum`, `statistics.sys`), each hop is a non-underscore attribute the validator cannot object to, and `FrozenModule.__getattr__` returned the raw object, so `uuid.os.system('…')` passed validation and ran. The proxy now refuses any attribute whose *value* is a module (a safe module reached this way comes back as its own proxy); a BFS over source-legal attribute chains found no dangerous callable reachable once module-typed hops are cut. Pinned by `test_forge_sandbox.py::TestModulesTransitifs`.
  - **The worker pool heals itself.** The `settrace` deadline cannot interrupt a C-level call (a pathological regex ran 4 s, a giant integer power 6 s, under a 0,2 s deadline, without ever raising `ForgeTimeout`), and a pinned thread keeps its semaphore token until its real end — correct, but with every thread pinned no token ever came back, so every later caller (tick, event, and `forge_test_module` mid-conversation) waited forever and the breaker never fired since nothing ran any more. `_submit` now bounds the token acquisition by the deadline (a refused caller says « aucun fil libre » and the module's breaker counts it), and when the last thread pins itself the executor is **replaced** (`_heal_pool_if_pinned`, generation counter so a zombie finishing later releases its own pool's token, never the new one). Tests: `test_forge_pool.py`.
  - Hot reload calls `_unregister_config()` before re-registering (`register_replace` can only add/replace, so a dropped config field lingered until restart). `_trash/` capped at `MAX_TRASH_KEPT = 20`. `ForgeLog` pruning amortized every 50 inserts per module.
- **Capability API** ([api.py](old/backend/modules/plugins/forge/api.py)): `api.storage` (per-module JSON KV by collections in the shared `ForgeRecord` table, quotas — forged modules never get DDL), `api.config` (reads `forge.<module>.<key>` from the standard config service, dashboard-edited, secrets decrypted, `record_list` supported), `api.log/warn/error` + `print` → `ForgeLog`, `api.notify_ai` (rate-limited by `forge.notify_cooldown_s`), `api.emit` → `forge.<module>.<type>` on the bus, `api.http_get` (manifest `allowed_domains` only, redirects off, private/loopback IPs blocked, size-capped), `api.state` (RAM dict).

Registered **from the manifest, before any load**, so a disabled or broken app keeps editable settings — without a registered section `config_service.set` refuses the key and the form would render but write nothing. - **Views**: each app's declared-and-implemented views become panels of *its own* space (`panels_for_app`), not of the host's. Payloads go through typed cells — `html`/`js`/`template` keys are never read.
- **MCP tools** (in every tools-enabled conversation): `forge_list_modules`, `forge_read_module`, `forge_write_module` (create/update: manifest merge + AST validation + version archive + hot reload; on failure the old version keeps running), `forge_command` (`enable|disable|reload|rollback|erase|reset_storage`), `forge_test_module` (run any handler NOW, returns result + logs — the iteration loop), `forge_read_logs`.
- **HTTP routes**: `GET /api/modules/forge/`, `POST /api/modules/forge/command`, `GET /api/modules/forge/source?name=`, `GET /api/modules/forge/logs`.
- **Two screens, deliberately** ([GestionSysteme/views/forge.py](old/backend/GestionSysteme/views/forge.py)): the *workshop* at `/gestion/modules/forge/` (all apps at a glance, filterable journal, storage by collection, reload-all) and the *apps* at `/gestion/forge/` — a menu entry **"Forge apps" immediately below "Forge"**, the only sidebar entry in the Espaces group that is not a module (apps are written at runtime, so no destination can be declared per app in `nav.py`). One space per app (`/gestion/forge/<app>/`) carrying state, source, journal, commands, configuration and pages. The per-app fiche and its commands **moved** there from the workshop's `?module=…` query string: a destructive button should not depend on an invisible parameter. ### Emotion + Drives + Rumination (the "inner life")

Three complementary systems feed the conscience scoring and the system prompt:

- **Emotion** (`emotion/`): physics-based affective state. Two separate prompt blocks — `emotion_context` = Mika's **global mood** only + drives descriptions; `person_context` = her **affective stance toward the current person** (`get_person_affect_context`), alongside her semantic profile and pending commitments.
- **Drives** (`drives/`): intrinsic motivational tensions (CURIOSITY, SOCIAL, EXPRESSION, REST). Grow with time, assuaged by actions. Contribute signed to the conscience score (REST subtracts). Inject a French description into the prompt.
- **Rumination** (`conscience/models.py::Rumination`): short-term persistent thoughts — signals that were pertinent but unactioned. Decay, bleed emotion into global mood, and can push the conscience to eventually speak up.

**What she declared is what the prompt reports back.** `process_emotion` stores the tag alongside the position, and `PersonMood.to_prompt_description` prefers it for `DECLARED_WINDOW_S` (1 200 s — the time the position really takes to come back under `REST_TOLERANCE`; at 700 s, the nominal τ, the label still read a third emotion) before falling back to the PAD label — read as a deviation from the person's own rest, see the emotion engine. The impulse only travels ~51 % of the way to the declared anchor, so the blended vector's nearest neighbour is frequently a **third** emotion: measured over five realistic starting stances, `embarrassed` came back as *effrayée*, `amused` as *love*, `grateful` as *excited* — and the intensity collapsed from a declared 0.8 to « à peine ». The oscillator still speaks, but as the undertow (« et en dessous, tu te sens aussi un peu … »), never by renaming the feeling. **Rest is measured from home, not from the origin**: `_home_vector` carries a circadian bias of norm 0,27–0,50, so the resting label was never `default_mood` and the block said « légèrement joueuse, alors que normalement tu es plutôt contente » all day, while every stranger loaded twenty minutes got a stance. `GlobalMood.to_prompt_description(default, home=)` and `get_person_affect_context` (`_at_rest_toward`) now compare against home with `REST_TOLERANCE` 0,1: at rest she is « contente, comme d'habitude », and a never-provoked stranger gets `""`.

**A stance toward someone heals with time, and survives a restart.** `_heal_anchor` pulls the personal anchor toward the shared circadian home on a 3-day half-life, and `_anchor_from_snapshots` ages its result the same way so an eviction + rehydration cannot restore a stance that time had erased. Two writers moved the anchor — a snapshot, a rehydration — and neither ever brought it back toward neutral: forty turns of mild frustration installed a resting `frustrated` measured *identical* after 1 h, 6 h and 24 h of complete silence, undoable only by ~14 warm turns. Healing is deliberately slow next to words (α = 0.15 per turn), which is what gives both grudge and forgiveness. `ensure_person_loaded` also backfills a missing anchor instead of returning early on « already in RAM » — `_restore_state` repopulates `person_moods` without one, so a restart used to wipe what distinguishes a friend from a troll for the whole process lifetime. **The first snapshot no longer installs a stance at full weight**: `_note_anchor` seeded a `None` anchor at the raw position (clamped to the 0,7 cap) and only applied α from the second write, so one `[EMOTION:angry:0.8]` toward a newcomer read « légèrement en colère » an hour later and still tinted after three days of silence — it now seeds at `_home_vector()` and applies α on the first write, and `_anchor_from_snapshots` blends home↔recency-mean with weight `1 − (1 − α)^n` (measured distance from home after one angry turn: 0,72 → 0,14). **And rehydration ages the position with the oscillator itself** (`_aged_position`: `_advance` from the snapshot, velocity 0, snapped to home past 10 τ — integration rather than `exp(−t/τ)` because the global is underdamped): the newest snapshot carries the *declared* intensity (0,8) while the live position had only reached ~0,38, and the old two-day linear ageing re-read it at 0,73 after an hour and 0,56 after twelve — a tab closed after a tense exchange reopened on an angry face the live oscillator had long relaxed. A snapshot always wins over the daily summary now (falling back to it resurrected yesterday's dominant).

### Identity & trust ([identity/](old/backend/identity/))

Who Mika is talking to, **how sure she is**, and what that certainty allows her to say. Everything per-person downstream — theory of mind, commitments, emotional history, concern-based routing — resolves through this layer.

**The bug it replaces**: `Identity.entity` was never populated, and per-person memory was looked up with `PersonProfile.filter(entity__name=person_id)`. That only matches when a person's memory Entity happens to be named after their transport handle, which never happens (the consolidator names entities "Thomas" while handles are `web_6f3e22ccb0ae`). The whole theory-of-mind layer returned `""` on every turn, silently.

**Two orthogonal notions** ([identity/trust.py](old/backend/identity/trust.py), pure functions, no DB):

- **`ChannelTrust`** — what the *transport* proves. `AUTHENTICATED` (verified Django session) > `ACCOUNT` (stable platform id: a Telegram DM proves the same account came back, not who holds it) > `PUBLIC` (group chat, unknown transport) > `INTERNAL` (not a person). Each grants a **floor** and imposes a **ceiling**.
- **`Certainty`** — how sure she is that *this handle is that person*: `UNKNOWN` 0.0 → `SUSPECTED` 0.25 → `CLAIMED` 0.45 → `CORROBORATED` 0.70 → `BOUND` 0.85 → `VERIFIED` 1.0. Moves with evidence, clamped by the channel ceiling. **No amount of talking makes a public-room claim as good as a login.**

**Three ways an identity gets established:**

1. **Authenticated** — `bind_authenticated()` on connect. The memory Entity is created eagerly under the account's display name so profile/commitments resolve from the first turn.
2. **Passive** — [identity/detection.py](old/backend/identity/detection.py) reads "moi c'est Thomas" off an ordinary turn (pure regex, no LLM: it runs on *every* inbound message). Files an `IdentityClaim` as `PENDING` and **binds nothing**. `_NOT_NAMES` rejects states and roles ("je suis fatigué", "je suis développeur"), and a greedy two-word capture falls back to one word so "je ne suis pas Thomas en fait" still reads as a denial.
3. **Active** — Mika's own MCP tools. Accepting a claim is what actually binds the handle to an Entity.

**Se laisser convaincre** — on a channel with no login, recognition is earned. `EVIDENCE_WEIGHTS` is calibrated against the disclosure bar (0.70): `self_declared` 0.20 alone never clears it, `shared_memory` 0.50 alone never clears it (knowing a fact about Thomas doesn't make you Thomas), but **claim + corroboration lands exactly on it**. `corroboration_score()` measures lexical overlap between what was just said and what memory holds about the claimed person (≥3 distinct content words). Counter-evidence subtracts: `contradicted` −0.35, `denied` −0.50, `revoked` −1.0.

**Disclosure gating** — `may_disclose_private_context()` decides whether per-person memory reaches the prompt at all: authenticated → always; account channel → needs `CORROBORATED`; **public room → never, at any certainty** (the risk in a group isn't mistaken identity, it's the audience — she can greet someone warmly, she just doesn't read out their file). `_fetch_person_context()` returns only the affective stance below the bar — her own feeling toward the handle is hers, the other person's history is not.

**Disclosure is graded, not binary, for what she knows about *others*** ([identity/divulgation.py](old/backend/identity/divulgation.py), pure; [memory/sensibilite.py](old/backend/memory/sensibilite.py)). `may_disclose_private_context` keeps gating the interlocutor's *own* file (profile, commitments, their verbatim). Every `Souvenir` / `Connaissance` carries a `sensibilite` ∈ {`anodin`, `personnel`, `confidence`} (migration `memory/0021`), **rated by the extractor** as a fourth line of `EXTRACTION_PROMPT_TEMPLATE` (default `personnel` when a person is linked — a row we know nothing about is never anodine — `anodin` when nobody is), raised at read time to `confidence` when the concerned person's `PersonProfile.sensitive_topics` lexically touches the content (never lowered, never rewritten). The turn carries one `Divulgation` computed once at the edge (`context_blocks.divulgation_du_tour`, `ConversationContext.niveau_divulgation`) from five facts: effective certainty and channel (unchanged), `closeness`, the warmth of the affective anchor (`emotion_engine.chaleur_envers`, moved there so `pipeline` never imports `conscience`), and — per row, free — whether the interlocutor is among the row's entities (`avec_temoin` facet). Rules: internal → `confidence`; public room → `anodin` whatever else; under 0.70 → `anodin`; from 0.70 → `personnel` if friend/close OR warm anchor (`identity.divulgation.chaleur_min` 0.3) OR witness; `confidence` only private, ≥ 0.85 (`identity.divulgation.certitude_confidence`) AND (close OR the concerned person themselves). The retriever, `memory_search` and `memory_recent_souvenirs` **remove** rows above the level and **tag** what is below but not anodin (« (confié en privé par Alice — pas à répéter à n'importe qui) », « (une confidence d'Alice — seulement parce que tu es en confiance) ») so Mika arbitrates, as she already does for the shared buffer; nothing about the interlocutor or about nobody is ever tagged. The episodic lane stays all-or-nothing: her own verbatim follows `fiche_ouverte` (= `may_disclose`), the plan's cross-person exchanges only at `confidence`. Yesterday's journal redacts third parties under `personnel`. `FERME` (nothing about anyone else — the old `disclose_others=False`) is the fail-closed edge value (identity failure, act with no recipient); `TOUT` is an internal turn. The person fiche shows the level the person would get today and the five inputs; souvenir/connaissance lists show the sensitivity badge. `test_divulgation_graduee.py` (63): the level × relation × channel matrix, « l'anecdote sort chez l'ami proche à 0,70 », « la confidence ne sort pas chez l'ami proche en salle publique », all three lanes, the tool, the journal, the edge, and an AST guard that `disclose_others` / `sans_confidences_d_autrui` / `rows_mentioning_others` exist nowhere.

**Denial applies immediately**, without waiting for deliberation: if she's calling a stranger by a friend's name, everything downstream is already wrong. It unbinds when it targets the current binding.

**Recognition is earned server-side, and a denial only counts against a name she knows the person by.** Four holes closed together (`test_identity_durcissement.py`, 35): (1) an *authenticated* binding named its memory Entity after the `identify` frame's `display_name`, so any logged-in account could send `display_name: "Thomas"` and be bound to Thomas's Entity at VERIFIED, profile and journal injected — the name now comes from the Django account through the same rule as `/auth/whoami` (`_auth_display_name`, full name else username), the client hint is ignored on a verified session, and `_bind_authenticated_sync` **refuses to rebind** an identity already bound to a different Entity (warning, existing binding kept). (2) The denial detector matched any « c'est pas X » — « c'est pas grave » docked −0.50 and filed a `denied` row for « Grave » — `_apply_denial` now files nothing unless the denied name matches the bound Entity, the display name or a pending claim (`detection.same_name`, case- and accent-folded, a first name matching the full name). (3) Certainty earned for one Entity was carried into a claim binding another (« moi c'est Alice » on a handle bound to Thomas at 0.70 → 0.85 on Alice): `_accept_claim_sync` restarts from the channel floor when the Entity changes, and `record_evidence` answers `ok: False` for a name that is not the bound one. (4) `identify` accepted `__global__` (chatting under Mika's global-mood key, whose snapshots are read back at boot as *her* mood) and `anon_*` ids minted for other sockets — both refused with the reserved prefixes. And **a display name is data, not instructions**: `trust.clean_display_name()` (whitespace collapsed, control/bidi/zero-width and quotes dropped, 40 chars) applies at `link_handle` for every channel and at read for pre-existing rows, and `describe_fr` renders it quoted « … » — a Telegram `full_name` carrying `--- CONSIGNE ---` used to land verbatim in the stable prefix.

- **Models** ([identity/models.py](old/backend/identity/models.py)): `Identity` (+`certainty`, `bound_at`, `bound_via`, `binding_reason`), `IdentityHandle` (+`trust`, `is_ephemeral`), `IdentityClaim` (audit ledger: every reason to believe or stop believing, with what it was worth). Migrations `identity/0002`, `identity/0003`.
- **MCP tools** ([identity/module.py](old/backend/identity/module.py), registered via `identity/apps.py`): `identity_whoami_with`, `identity_check_story`, `identity_accept_claim`, `identity_reject_claim`, `identity_record_evidence`, `identity_forget_binding`. The current person is ambient via a ContextVar ([pipeline/tracing.py](old/backend/pipeline/tracing.py)).
- **Prompt**: `--- QUI TU AS EN FACE ---` sits immediately before `--- CE QUE TU SAIS DE CETTE PERSONNE ---`, because it qualifies it. Never prints a number — prompt text reads as a feeling, or the model starts quoting percentages back at the user.
- **Consolidator**: souvenirs are linked to the *interlocutor's* entity, not only to entities the extractor happened to name; connaissances that name nobody are linked to the single identified interlocutor, and the extractor is told the interlocutor's first name.
- **Retention**: ephemeral `anon_*` handles expire after 7 days, orphan `Identity` rows are swept, resolved claims kept 180 days (pending ones protected).

**One definition of "is this a person?"** — `identity/trust.py` owns `INTERNAL_PERSON_IDS`, `is_internal_person()`, `is_ephemeral_person()` (`anon_*`) and `is_identifiable_person()`. The rule used to be stated in three places and had already drifted (only one excluded `anon_*`).

**Frontend is authenticated** — `CONSUMER_REQUIRE_AUTH` defaults to `True`; the WebSocket refuses anonymous connections. Three pieces have to line up, each silently breaking the whole app on its own:
1. **`AuthMiddlewareStack`** on the WebSocket router ([config/asgi.py](old/backend/config/asgi.py)) — it populates `scope["user"]`. Without it the key is *absent*, so every connection is refused with 4401.
2. **`CORS_ALLOW_CREDENTIALS=True`** — the SPA sends `credentials: "include"`; without `Access-Control-Allow-Credentials: true` the browser discards the response (login failed with "invalid credentials" even when correct).
3. **`@ensure_csrf_cookie` on `/auth/whoami`** — the first call plants the token the subsequent POSTs echo.

Tested through the real ASGI stack (`TestAsgiAuthWiring`), including that a **valid session is accepted** — asserting a door is locked proves nothing about the key. `GET /auth/whoami` reports `auth_required` + `needs_bootstrap`; `POST /auth/bootstrap` creates the **first** account (409 forever after). `AUTH_PASSWORD_VALIDATORS` is configured — without it `validate_password` was a no-op.

### Self-concept and theory of mind

Two layers built on the memory system, regenerated during consolidation:

- **Self-narrative** (`memory/narrative.py` → `SelfNarrative`): first-person paragraph "Je suis quelqu'un qui…" synthesized from recent souvenirs + connaissances + emotional summary. Every ~24h if ≥5 new souvenirs. Injected between personality and person-context.
- **Person profile** (`memory/person_profile.py` → `PersonProfile` + `Commitment`): per-person model — summary, closeness (stranger/acquaintance/friend/close), preferred tone, topics of interest, sensitive topics, pending commitments. Regenerated per active person (seen in last 14 days, ≥3 new souvenirs, ≥24h since last).

Commitments are a 3rd type of extraction produced by the same consolidator LLM call.

### Sleep Cycle ([memory/sleep.py](old/backend/memory/sleep.py))

Counterpart to the Conscience. The consolidator runs all day doing maintenance; the Sleep Cycle runs **only at night** doing creative, narrative and healing work the reactive pipeline cannot.

**Double gate** — both must pass:
1. Night, per `_is_night(now, start_hour)` — **both bounds derive from the circadian profile** (`phase_hours[NIGHT]` → nominal start, `phase_hours[MORNING]` → end; reader guards [12, 23] / [0, 12], historical 23h/6h as fallback of an unreadable profile). The `memory.sleep_night_*` keys are removed, not doubled — same rule as the conscience's greeting windows: the profile is the character, a nocturnal one sleeps *her* night
2. `conscience.get_idle_seconds() ≥ 900` (15 min) — an interaction always wakes her mid-night

**REST no longer forbids sleeping; it only moves bedtime earlier.** The gate used to require
`drive_engine.states[REST].tension ≥ 0.5` and that threshold was unreachable in real use: REST grows
only on activity (`growth_rate=0.0`, ~0.05–0.08 per reply), decays 0.36/h, and the gate imposes 15
minutes of idle *first* — during which REST can only fall. A conversation from 18h to 20h30 left
0.010 at 23h15, so Mika stayed AWAKE all night: no journal (`--- TON FIL D'HIER ---` empty forever
for that date), no dream, ruminations undigested, avatar eyes open. The one profile that did sleep
was cancelled by an evening reboot, REST being RAM-only. Now `_night_start_hour()` returns
`23 − round(1 × REST)`, floored at 22h (`EARLY_NIGHT_MAX_ADVANCE_HOURS`, 1 — two hours put an
adult to bed at 21 h after an evening of conversation, and REST is now a measure of hours of
sustained activity): tired means *earlier*, never *never*. Drives also survive a restart (`drives/models.py::DriveSnapshot`, one row per drive,
overwritten in place) — `restore_state()` replays the elapsed time rather than restoring tensions
verbatim, so REST falls and the positive drives climb as if the process had never stopped. The
gate's `except` no longer forces `rest_tension = 0.0` (fail-*closed*, and silent); it counts.

**Three phases** (invoked by `run_if_due()` from its **own dedicated loop** started at ASGI lifespan — `memory.sleep_check_interval`, default 60s; decoupled from the consolidator so a 45s sleep LLM call never delays consolidation):

1. **Light sleep** — `_write_journal_if_due()`. One LLM call produces a `DailyJournal` for the date just ended: 1st-person recap (2-4 sentences), key moment ids, dominant emotion, persons interacted, unresolved rumination snapshots. One row per date; re-runs refresh in place.
2. **REM** — `_maybe_dream()`. Picks 2-3 souvenirs of **distinct themes** (greedy anti-duplicate) + optionally one active rumination ≥ 0.3. Classifies: `nightmare` (dominant negative or strong negative rumination), `pleasant`, `associative` (mixed), `mundane` (weak signal). `DREAM_PROBABILITY = 0.6`, `MAX_DREAMS_PER_NIGHT = 2`.
3. **Deep sleep** — `_digest_ruminations()` (03h-06h, once per night). The window is `[max(0, min(3, morning − 1)), morning)` (`_deep_sleep_window`), not a hardcoded 03h: MORNING is a dashboard field clamped to [0, 12], and a profile with MORNING ≤ 3 made digestion and the nightly reorg never run, silently; an empty window is counted as a degradation. For active ruminations older than 120min: decay ×3, forced emotion drift via `DIGESTION_DRIFT` (`frustrated → relieved`, `anxious → relieved`, `angry → thinking`), intensity ≥ 0.4 → a **reflective Souvenir** ("Après y avoir repensé cette nuit: …") — **once per rumination** (`Rumination.reflechie_le`, migration `conscience/0018`, marked in the same write; a thought still active the next night used to yield a twin every night), intensity < 0.15 post-decay → marked `faded`.

**Observable phase state** (`SleepPhase`): `awake | light_sleep | rem | deep_sleep`. Transitions call `_set_phase()`, pushing a `broadcast_inner_state_update` so the frontend reacts immediately. Singleton `sleep_cycle` at module level. A phase is entered **only when it has work to do**, and the tick ends by settling into `DEEP_SLEEP` (announcing LIGHT_SLEEP then REM every tick made the frontend replay its 1.2–1.8s eases twice a minute all night). REM attempts are spaced by `DREAM_ATTEMPT_INTERVAL_S` (45 min).

**Prompt integration** — morning recall (6h-14h): a non-recalled `Dream` with `vividness ≥ 0.6` for last night is injected as `--- CE QUE TU AS REVE CETTE NUIT ---`, then auto-marked `recalled_at`. Framed as "tu peux le mentionner si ça tombe". Yesterday's `DailyJournal` is injected all day as `--- TON FIL D'HIER ---`; any journal is re-readable via `memory_read_journal`. The journal is dated the day it **covers**, so readers query most-recent-of-{today, yesterday}.

**Frontend integration** (end-to-end, live):
- `sleep_phase`, `today_journal`, `last_dream` in every `inner_state` payload
- `AnimationMixer.setSleepPhase()` — eyes close (0.85-1.0), breath × 0.45-0.7, REM flicker, head tilt 0.12-0.25 rad, 1.2s eased transitions
- `Environment.setSleepPhase()` — lights × 0.22-0.55, background tint toward dark blue, 1.8s eased
- `TTSService.requestWakeUpDelay(ms)` — first reply after waking gets 1.3s of silence
- `InnerLifePanel` — "Rêve de cette nuit" + "Journal d'aujourd'hui", sleep badge when not awake

**Debug endpoints** ([communication/debug_views.py](old/backend/communication/debug_views.py)) — all gated by `settings.DEBUG`:
- `POST /api/dev/sleep/phase {phase}` — force a phase, bypasses gates
- `POST /api/dev/sleep/journal` / `dream` / `digest` — run that LLM call NOW
- `POST /api/dev/sleep/wake` — reset to AWAKE
- `GET  /api/dev/sleep/status` — phase + today's journal + last dream

**Metaphor recap**: Conscience = waking state (observe + act). Consolidator = maintenance bookkeeper. Sleep Cycle = dreaming state — creativity (dreams), narrative coherence (journal), emotional healing (digestion).

### Projects ([projects/](old/backend/projects/))

Standalone Django app. Mika as an **agent with explicit work engagements**: projects have a title, a frame of execution (tone, emotion policy, instructions, out-of-scope), allowed resources (modules, paths, contacts), a schedule, and a task list. User-confided or self-initiated.

**Critical default** — projects have **`emotion_policy = OFF`** out of the box. When a project is active and matches the current turn (or runs on schedule), Mika drops her [EMOTION:] tag, variability block, and all affective reasoning. She's in professional mode. Turn this back on explicitly (`muted` or `full`) only if the user asks.

**Models** ([projects/models.py](old/backend/projects/models.py)):
- `Project` — title, description, origin (user/self), status, priority, `tone_directive`, `emotion_policy`, `instructions[]`, `out_of_scope[]`, `requires_approval`, `allowed_modules[]`, `resource_paths[]`, `contacts[]`, `test_command`, `schedule_rule`, `next_run_at`, `runs_since_user_input`, owner (FK Entity). **`resource_paths` means read-only paths *outside* the workshop** — the work itself lives in the project's own directory; `allowed_modules` scopes executable capabilities through `projects/capabilities.py`
- `ProjectTask` — per-project work (`todo`/`in_progress`/`done`/`blocked`) with `order`, `result`, `blocked_reason`
- `ProjectLog` — audit trail, one row per advance/report/error
- `ProjectPendingAction` — side-effect actions awaiting user approval (payload dispatched on approve)
- `ProjectPromptHistory` — rolling buffer of (system_prompt, user_prompt, raw_response, parsed_output, outcome, duration_ms) per project. `PROJECT_PROMPT_HISTORY_SIZE` (default 30, `0` disables). Pruned after each insert by `_prune_history`. Admin-visible, read-only.

**Schedule rules** ([projects/schedule.py](old/backend/projects/schedule.py)):
- `""` / `"manual"` — advance only on explicit push
- `"interval:5m"` / `"interval:30s"` / `"interval:2h"` — recurring (floor 5s)
- `"cron:0 9 * * MON-FRI"` — uses `croniter` if installed, falls back to a minimal 5-field parser supporting DOW names + ranges
- `"idle:30m"` — fires when conscience idle seconds ≥ window **and** `next_run_at` has passed (without the second condition an `idle:` project advanced on every runner tick)
- `"event:email.received"` — `projects/apps.py::ready()` subscribes a `PRIORITY_LATE` bus handler calling `runner.notify_event(event_type)`, setting `next_run_at = now` on exact-matching active projects

**A project is a workshop: a folder, a toolkit, and bounded execution** ([projects/workspace.py](old/backend/projects/workspace.py), [projects/toolkit.py](old/backend/projects/toolkit.py), [projects/execution.py](old/backend/projects/execution.py)) — the exact mirror of the Forge, and its deliberate opposite. **The Forge is confined *because* it is coupled** (it `exec`s inside Mika's process to extend her, so imports, filesystem and subprocesses are all forbidden); **a workshop is capable *because* it is separate** (it touches nothing of the engine, so it writes real files and runs real programs). Each project gets `data/projects/<id>-<slug>/` (`projects.workspace.root`, relative = from the repo root), created lazily — a project that never writes has no directory, so nothing migrates.

- **Path containment is one control applied everywhere**: resolve, *then* check membership (`is_relative_to`). String comparison catches `../..` and misses the symlink pointing out of the folder, which is the classic escape. It bounds **the toolkit**, not a program once launched.
- **`run_bounded` is the workshop process boundary.** Commands use bubblewrap namespaces, a writable workshop mount, read-only system directories, ephemeral `/tmp`, a reconstructed environment and optional network isolation. Failure to isolate never falls back to execution on the host. Output is drained with bounded memory; timeout and cancellation kill the process group. Dependencies must be installed in the isolated system or workshop, not in the server user's home.
- **Git per workshop**: `git init` seals its own state with a seed commit (without it the untracked `.gitignore` made the *first* tick sign the setup), then one commit per tick that actually changed something — no empty commits, because a history where every tick leaves a trace stops being readable, and readability is the whole point: it turns "approve an opaque JSON payload" into "read a diff". `project_diff` also lets her re-read her own work.
- Deleting a project **moves its workshop to `_corbeille/`** rather than erasing it, as the Forge does for its modules: deleting a project used to delete rows, it now deletes work.

**Runner** ([projects/runner.py](old/backend/projects/runner.py)): `project_runner` singleton with its **own dedicated loop** (`projects.runner_interval`, default 30s; decoupled from the consolidator so `interval:30s` actually fires at 30s). Per tick: lists due projects, advances up to 3 in priority order, builds a scoped context (no emotion/ruminations/circadian — just project frame + tasks + recent logs + resources), opens the workshop and calls **`chat_with_tools`** with that workshop's toolkit, parses a structured JSON output (`summary`, `task_updates`, `new_tasks`, `report_to_user`, `proposed_action`), writes DB changes, commits the work, logs the tick, bumps `next_run_at`.

**The runner acts; it no longer only describes.** It called `ai_router.complete` — a plain text completion, no tools ever — so `allowed_modules` and `resource_paths` were *sentences printed in the prompt* and read by nothing, and its only channel to the world was `proposed_action`, of which exactly one `kind` was wired (`send_email`). A software project therefore ended on correct code sitting in a `JSONField` that nothing executed, while the prompt actively ordered *« écrire un fichier doit être soumis à validation, n'exécute RIEN directement »*. Three consequences of the change:

- **A dedicated role**, `AIRole.PROJECT_WORK`. The runner borrowed `MEMORY_EXTRACTION` under the comment "re-use light model": a small model fills a JSON, it does not hold a tool loop. **Unmapped falls back to `MEMORY_EXTRACTION`** — requiring the mapping would break every existing install at the exact moment its projects start working.
- **`ChatPrompt(system_stable=…)`** puts the project frame (which doesn't move between ticks) on the cacheable side of the breakpoint, for free.
- **Approval changed meaning, and that is what repairs it.** Inside the workshop she acts freely; `requires_approval` now gates only what *leaves* the machine (an email, a write outside the root). `allowed_modules` stays a proposal scope on purpose: handing those tools directly would short-circuit the very airlock. Bounded by `projects.max_tool_turns_per_advance` (12; providers default to 10, and reading a file before editing it already costs two turns).

Side-effect actions on `requires_approval=True` projects queue as `ProjectPendingAction`. **An approved action with no executor stays `approved`** — it was marked `executed`, contradicting the rule `_execute_pending_payload` states in its own docstring, so the API answered `ok: true` and the badge went green while no file existed.

**Runner safeguards**: `runs_since_user_input` is statistical only. `stalled_runs`, `progress_signature`, `retry_after` and `pause_reason` govern automatic backoff (5 minutes to 6 hours by default, configurable). `MAX_ADVANCES_PER_TICK = 3`. **`next_run_at` is bumped whatever the model answered**: a malformed inner shape (`"task_updates": "aucune"`, `{"1": "done"}`) raised outside the guarded path, `_advance` propagated, `_tick_inner` never bumped, and the LLM was re-called on every 30 s tick with no cap and the history row already stamped `ok`. ### Voice output — a routed modality ([pipeline/voice.py](old/backend/pipeline/voice.py))

Speech is **not** a frontend detail: text and audio leave Mika through the *same* channels, and whether she speaks is a routing decision made backend-side.

**Presence is per connection, not per person** ([communication/presence.py](old/backend/communication/presence.py)). The registry is keyed `(person_id, channel)`, but an entry carries the set of live connections backing it, and `unregister(..., connection_id=)` only drops the entry when the last one goes. Without that, the key *was* the bug: two tabs shared one entry, so closing the first erased it and the second went permanently silent (`broadcast_to_websocket` deliberately says nothing when an identifiable person resolves to no target). The single-tab version is worse: `reconnectNow()` opens the replacement socket before the dying one's `disconnect` is dispatched, so the stale unregister killed the new registration — and the client's own liveness watchdog triggers that path. Modules pass no `connection_id` (their reachability is a stored handle, not a socket), so their unregister still evicts outright.

**Delivery registry** ([communication/delivery.py](old/backend/communication/delivery.py)) — `presence_registry` says *where* a person is reachable; this says *who can send* there. Needed because a communication channel isn't necessarily a module: `TelegramChannel` is never registered with `module_manager`, so `get_module("telegram")` always returned `None` and the caller fell back to a global broadcast (leaking a message composed for one person to every browser). `get_channel(name)` resolves registered channels first, then modules. Targeted messages that cannot be delivered are **logged and dropped**, never broadcast.

**Three sinks**, with genuinely different context rules:

| Sink | Where | Policy |
|------|-------|--------|
| `SCREEN` | frontend app (browser TTS) | speaks by default; silent with no client connected |
| `MESSAGE` | async voice note (Telegram voice, SMS) | time of day is irrelevant — the recipient plays it when they choose. Only an explicit mute suppresses it |
| `SPEAKER` | open-air speaker in a shared room | strictest: silent during quiet hours (22h–8h), while Mika sleeps, and (for addressed speech) when nobody's in the room |

`decide_voice(sink, *, hour, sleep_phase, person_present, muted, persona) -> VoiceDecision(speak, reason)` is a **pure function** — the whole policy is unit-testable without a running system. The reason string is logged and shipped to the frontend so silence is never mysterious.

**Two voice personas** — `VoicePersona.SPEAKING` (addressed to a person) and `VoicePersona.INNER` (thinking out loud). Her inner monologue gets its own vocal identity via `VOICE_PROFILES`: quieter (gain 0.45), slower (rate ×0.9), slightly lower (pitch ×0.94). Two policy consequences: an inner thought is **never** sent as a voice note, and it **may** be spoken to an empty room. `persona_for_source(source, addressed=)` classifies a turn: `INNER_SOURCES = {conscience, drive, rumination}` unless the turn deliberately targets a person.

**Audible inner monologue** ([pipeline/inner_voice.py](old/backend/pipeline/inner_voice.py)) — when Mika acts on her own she murmurs *"oh tiens, si j'envoyais un message à Alice..."*. That murmur is **generated, not reused**: `generate_inner_thought(action, result, *, mood)` makes a dedicated small-model call (`AIRole.INNER_VOICE`, 12s timeout) from *what she's about to do* + *what just came back*. Output is cleaned (quotes/prefixes stripped) and capped at 160 chars. Every failure path returns `None`: **silence is a valid outcome**, an error is never surfaced as a thought. Wired into `project_runner._murmur()`; broadcast with `source="conscience"` so the INNER persona applies.

**Pluggable synthesis** — `register_synthesizer(synth)` installs a `SpeechSynthesizer` (Piper, edge-tts, an API). **None is registered by default**: the frontend does its own TTS, so `MESSAGE`/`SPEAKER` delivery falls back to text until one is installed. `synthesize()` never raises. Telegram declares `VOICE_SINK = MESSAGE` and implements `deliver_voice()` (OGG/Opus → `send_voice`, anything else → `send_audio`, captioned with the text).

**Frontend contract** — the `speech` payload carries `speak` (bool), `voice_reason`, `voice_persona`, `voice_profile` ({pitch, rate, gain}). [main.ts](frontend/Web/src/main.ts) honours `speak: false` by showing the text and animating without speaking; `TTSService.speak(text, emotion, profile)` applies the persona multipliers **on top of** the emotion modulation, clamped to the Web Speech API ranges.

### System prompt structure

Assembled by `build_system_prompt()` ([pipeline/prompt.py](old/backend/pipeline/prompt.py)) in this order — the *reading* order is unchanged on every provider; what varies is the *transport*: on chat-native providers (Claude, OpenAI-compatibles, Ollama) layers 1–2bis stay in the system prefix (cached/prefix-reusable) while layers 3+ travel inside the final user turn (wrapped `--- ETAT INTERNE ---`); only the providers without a chat method (GLM, Gemini) keep everything in the system string as before:

1. **Personality** (from the `personality.*` config keys) — includes a `--- VARIABILITÉ NATURELLE ---` sub-block encouraging variable response length, backchannels ("hmm", "attends"), hesitations, selective echo, non-mandatory relances, and prosodic tokens (`[SIGH]`, `[LAUGH]`, `[PAUSE:ms]`, `[BREATH]`). *Stripped* when an active project has `emotion_policy=OFF`.
2. **`--- QUI TU ES DEVENUE ---`** (self-concept, evolving paragraph)
2bis. **`--- QUI TU AS EN FACE ---`** (identity certainty + pending claims). Qualifies the block below; silent for internal person_ids.
3. **`--- CE QUE TU SAIS DE CETTE PERSONNE ---`** (person profile + affect + weekly trend + commitments). **Gated on identity certainty**: below the disclosure bar only the affective stance is injected.
4. **`--- CE QUE TU PERCOIS DE SON ETAT ---`** (heuristic read of the user's tone: caps, punctuation, lexique, emojis, length — `detect_user_mood_hint` in `pipeline/context.py`)
5. **`--- TON RYTHME ---`** (circadian phase + energy level)
6. **`--- ETAT COGNITIF ---`** (fatigue fog: 4 tiers below energy 0.5 shaping the TONE, not just the act/wait threshold)
7. **`--- CE QUI TE TROTTE DANS LA TETE ---`** (active ruminations, every turn)
7bis. **`--- CE QUE TU AS EN TRAIN ---`** (her chantiers — up to 3 live + 2 completed today; no machine numbers, "presque au bout" rather than "pas 4/5". Injected for every person_id including her own conscience turns — an act that ignores what she already undertook reopens it. Muted in professional mode like the ruminations)
8. **`--- CE QUE TU AS REVE CETTE NUIT ---`** (non-recalled dream, vividness ≥ 0.6, 6h-14h only, auto-marked recalled)
8bis. **`--- TON FIL D'HIER ---`** (yesterday's `DailyJournal`, capped ~450 chars + dominant emotion; skipped for internal person_ids). **Gated on disclosure like the person block**: below the bar she keeps her thread but names nobody — third-party names are redacted out of the narrative and the `persons_interacted` line is dropped. Its only guard used to be `is_internal_person`, so an unidentified handle received, on its first « salut », a first-person account of her evening naming who confided what — in the very prompt where the identity block tells her to say nothing personal about anyone, and while `memory_read_journal` already refused.
9. **`--- PROJET EN COURS ---`** (matching engagement — title, tone_directive, instructions, out_of_scope, emotion_policy, todo tasks). When `emotion_policy=OFF`, suppresses the emotion block below.
10. **`--- CONTEXTE MODULES ---`** (email backlog, RSS unread, etc.)
11. **`--- TON ETAT EMOTIONNEL ACTUEL ---`** (global mood with ambivalent blend phrasing + drives). *Suppressed* in professional mode.
12. Memory context (semantic retrieval of relevant souvenirs/connaissances)

Personality + self-concept + person-context + circadian are the "slow" layers; module/emotion/memory/user-mood/fatigue/ruminations/dream/project are recomputed every turn. Recency bias places the latter last.

### Frontend (Vite + Three.js + VRM)

- **Entry**: [frontend/Web/src/main.ts](frontend/Web/src/main.ts) — initializes the 3D scene, loads VRM, connects WebSocket, wires TTS + lip-sync + face emotions + a single `AnimationSystem` facade for ALL body animation

These types are NEVER re-declared per file.
- **The room is an authored GLB** (`public/models/room.glb`, 6.35 MB, ~103 k triangles), built by script in Blender — `frontend/Web/assets-src/room.blend`, `assets-src/blender/run_final.py` rebuilds the whole pipeline, Poly Haven CC0 textures credited in `assets-src/README.md`. Ambient occlusion is baked (Cycles, CPU — the CUDA bake writes a black image on this machine) into one 2048² atlas exported as `occlusionTexture` on `TEXCOORD_1`, so GLTFLoader maps it to `aoMap` with no code; lighting stays dynamic. `RoomModel.ts` loads it and binds named objects (`Window_Sky` sky shader, `Monitor_Screen`, clock hands on the real time, `LightAnchor_*` empties placing the point lights, `DeskChair`, emissive `M_*` materials scaled by the sleep multiplier); `ProceduralRoom.ts` is the fallback with the same `RoomParts` interface. `Daylight.ts` interpolates the real local hour continuously (dawn → night keyframes; sky, window light, a sun/moon spot through the window, a floor light patch) — the outside light does not dim with sleep. `SceneManager` renders through an `EffectComposer` (RenderPass on a 4× MSAA half-float target → UnrealBloomPass, threshold 1.0 so only lamps/neon/LEDs bloom, never her MToon skin → OutputPass, which applies ACES + sRGB exactly once).
- **3D**: `src/scene/` — `SceneManager` (render loop; `clock.getDelta()` clamped to 50ms so tab-restore spikes can't explode the spring bones), `Environment` (`setSleepPhase()` light dimming + bg tint; `getAnchor()` v2 locomotion seam), `CameraController` (orbit target follows the avatar root via `setFollowTarget(object3d, offset)`)
- **VTuber**: `src/vtuber/` — `VTuberModel` (VRM under an `AvatarRoot` group at (0,0,-0.5) rot Y-π — v2 locomotion moves this root, clips animate in model-local space), `EmotionController` (FACE only: 29 emotions → blend shapes with rich-model fallback)
- **Body animation**: `src/vtuber/animation/` — Mixamo-clip-based layered system:
  - `AnimationSystem` — facade main.ts wires; per-frame order: `humanoid.resetNormalizedPose()` + `applyRestPose()` → state machine → `THREE.AnimationMixer` (rooted at `normalizedHumanBonesRoot`) → `AttentionDirector` (pure: where her attention is this frame) → additive overlays (breathing spine, sleep neck tilt, emotion head pose, **attention head turn** — quaternion compose, never absolute Euler writes) → `HandAnimator` (30 finger bones, absolute — finger tracks stripped from clips) → `GazeController` (eye bones, absolute — Mixamo has no eye bones; runs **after** every head writer so the eyes point at the residual) → `BlinkController` (gaze-evoked blinks read `ctx.gazeShift`) → `FaceIdleController`. `init(vrm, { root, camera })` — the camera is the viewer.
  - **One rig convention, derived, never assumed** (`vrmVersion.ts::forwardSign`). three-vrm's normalized rig faces **+Z on a VRM 1.0 and −Z on a VRM 0.x** (the library's own words: "VRM 0.0 models are facing Z-"), and the user's model is a 0.x. Every hand-written rotation of the layer — head/neck tilts (`OverlayContext.addRotation`), eye pitch (`gazeMath`), the A-pose arm drop (`applyRestPose` / `buildRestClip`), the finger curl (`HandAnimator`) — is now authored ONCE in the 1.0 convention and conjugated by Ry(π) for a 0.x: (x, y, z) → (−x, y, −z), the exact transform `mixamoRetarget` already applies to every clip quaternion. Before, the overlays wrote +Z-convention pitches onto the −Z model: `sad` raised the chin, `proud` lowered it, and the sleep doze tilted the head *back*; while the rest pose and the hands, hand-tuned on the 0.x, would have raised both arms into a V and curled the fingers backward on a 1.0. `gaze.test.ts` / `rigSign.test.ts` assert **geometry** on both rigs (the head's forward vector tips down, the arm points down, the eye lands on the camera) — never a sign constant, since a comment is what got it wrong.
  - **Attention & gaze** (`attention.ts`, pure; `GazeController`, `overlays/HeadAttentionOverlay.ts`, `gazeMath.ts`) — she looks at the person in front of her. The `AttentionDirector` is conversational gaze as the literature describes it: a listener keeps her eyes on the speaker (`contact`), a speaker looks away at the *start* of an utterance to plan it (`ONSET_AVERSION_P`, up-and-to-the-side) and comes back, someone composing a reply looks up and to the side with brief check-ins (`thinking` — driven by the `ack: accepted` frame, cleared by the `speech` frame, capped at `THINKING_MAX_S`; **speech outranks it**: one finishes one's sentence first), someone being typed to rests her eyes on the typist (`listening`, `LISTENING_HOLD_S` after the last `input` event), a person murmuring to herself does not look at you (`inner` persona → low contact, down-side), and per-emotion aversion profiles (embarrassment, sadness, anxiety avert *down*; retrieval and reverie go *up*; love and gratitude barely avert at all). **Every gaze change is a step, never an ease** — eye movements are saccades, an eye that slides reads as drunk — followed with a ~30 ms ease; the head, which really is slow, eases in its own overlay (`HEAD_TAU`). **Head–eye coordination falls out of the frame order**: `HeadAttentionOverlay` measures the viewer in the head frame *as the clip posed it* (before adding its own turn — open loop, no feedback) and eases `HEAD_FOLLOW` of the angle past a dead zone onto neck + head, bounded; `GazeController` then measures the viewer in the *final* head frame and points the eyes at the residual, unfiltered — that is the vestibulo-ocular reflex: when a talk clip swings the head, the eyes counter-rotate and contact holds. Semantic angles throughout (pitch > 0 down, yaw > 0 her left); the eye range is conservative (`EYE_MAX_*`, ~17°: past it a VRM eye shows white), a viewer beyond `HEAD_REACH_*` (behind her) yields `away` — forward gaze, no twist. Large saccadic jumps (`GazeIntent.shift`) trigger a quick blink about a third of the time (`GAZE_BLINK_P`), the way eyelids ride a gaze shift. No camera → `contact` 0 → the historical forward gaze with bias and saccades.
  - **What the voice says, the face shows — at the moment it sounds.** A `speech` frame updates the readouts at once but applies the avatar's emotion (face, body one-shot, gaze bias, hand mood) through `tts.speak(…, { onStart })`, i.e. when *that* utterance actually starts — after the wake-up silence, after the replies queued before it; the same fix the lip-sync got via `onUtteranceStart`, extended to the rest of the body. `speak()` now resolves to `"played" | "skipped"` when the item is done or dropped (mute, stop) so main.ts knows a voiced reply is in flight; while one is, the backend's `emotion_update` drift — often a *third* emotion, see the emotion engine — is **held** (newest wins) and applied when the voice ends (`onSpeakEnd` with an empty queue, or the promise; `VOICED_HOLD_MAX_MS` is the valve for a Web Speech utterance that never fires `onend`). A skipped reply still shows its emotion: the text is on screen. **The state machine holds the talking stance a beat after the voice stops** (`SPEECH_SETTLE_S` 0.7 s): people keep their posture past the last word, and two queued replies start the next utterance ~300 ms after the previous ends — the immediate return to idle flip-flopped the whole body between them.
  - **The voice/drift/sleep state lives in one testable object** ([ui/SpeechPresenter.ts](frontend/Web/src/ui/SpeechPresenter.ts)). `main.ts` used to hold it all in a 435-line `init()` closure — `voicedInFlight`, `voicedSince`, `pendingDrift`, `lastAsleepAt` — the subtlest logic of the front with zero tests. `SpeechPresenter` now owns the rules above (readouts at the frame, avatar at `onStart`, drift held while a voiced reply is in flight with newest-wins, `skipped` still shown, `speak:false`/mute immediate, `ambient: true` down the same `applyAvatar` path, the wake-up delay, the sleep fan-out with `resolveSleepPhase` at entry — that guard moved to `types/sleep.ts` next to `isSleepPhase`, since the panel and the presenter both use it). It talks to its collaborators through minimal ports (`VoicePort`, `FacePort`, `BodyPort`, `StagePort`, `ReadoutsPort`) with an injectable clock and timers, imports neither Three.js nor the DOM, and `main.ts` is wiring only: it builds the objects, points `TTSEvents.onSpeakStart/End` and every WS frame at the presenter, and keeps the stateless lip-sync hooks. One refinement on the way: `VOICED_HOLD_MAX_MS` used to only let the *next* drift through, so a drift already held behind an utterance whose `onend` never fires stayed held until the mood moved again (`emotion.sync` only emits on change); the presenter now arms a timer at the first in-flight reply, disarmed when the voice ends in time, that releases the held drift at the deadline. `SpeechPresenter.test.ts` (28) pins every rule with hand-driven fakes.
  - **Lip-sync follows the voice, not the estimate.** `TTSService.onSpeechProgress(charIndex)` reports where the voice is in the reply text: at `utterance.onstart` (the sound really begins — the plan used to start at enqueue, ahead of the audio by the whole synthesis latency) and at each `onboundary` word event where the browser provides them (Chrome/Edge local voices, Firefox). `LipSyncController` frames carry the **original** character index (`SpeechPlanSegment.start` + offset, whitespace collapsed without shifting indices) and `seekToChar` re-seats the cursor — forward or back, and it revives a plan that ran out early. The estimate between resyncs scales with the utterance's effective rate (`msPerCharForRate`): at 60 ms/char fixed, an excited reply at rate 1.15 left the mouth moving after the voice, a bored one at 0.8 closed it with a fifth of the audio to go.
  - **Affect-aware base pools** (`affect.ts`): `EMOTION_VALENCE` / `EMOTION_AROUSAL` mirror the P and A of the backend's PAD anchors (never re-invented). A manifest clip may declare `arousal` / `valence` (−1…1); `clipAffinity` multiplies its pick weight (bounded `AFFINITY_MIN…MAX` — a mismatched clip is rare, never impossible), so `talk_heated` (Standing Arguing, arousal 0.8) is favoured for an angry reply and rare for a dreamy one, and `idle_happy` (valence 0.7) is barely drawn when she is sad; undeclared clips keep the historical uniform rotation. The base clip's **tempo** eases toward `affectTimeScale` (±15 % max) and its **hold** toward `affectHoldScale`. `setAffect` never triggers a transition by itself.
  - **Sleep edges have gestures**: awake → sleep plays `gesture_yawn` first (only from a base pool, never mid-sentence, never for a phase change while already asleep) and dozes when it ends; sleep → awake plays `gesture_stretch` over the wake fade unless she is already answering someone (then straight to talking). Both optional — a manifest without them keeps the plain crossfades. Woken mid-yawn, the yawn finishes into idle.
  - **Expressions arrive at their own speed and leave more slowly** (`EmotionController::ONSET_SPEED`, `OFFSET_RATIO`): a startle in ~100 ms, a smile in ~300 ms, sadness and reverie over most of a second; every shape's offset is `OFFSET_RATIO` of its emotion's onset (floored at `MIN_OFFSET_SPEED`), decided per shape since a leaving shape and an arriving one coexist. One speed for all 29 was a mask that lit up and switched off.

Amplitudes stay small: VRM expression binds ACCUMULATE (`+=`) and the custom emotion shapes already bind some of the same morph targets. Shapes are resolved once, so a VRM without perfect-sync degrades to blink + emotions.

    - **The model's groups drew manga symbols.** `Shocked` (surprise) = swirl eyes + sweat drop, `Sad1`/`Sad3`/`Angry1`/`LMAO` = a tear at ANY intensity, `Healthy` (determined) = dark circles, `BadSmile2` (jealous) = black eyes, `Numbly` (thinking) = swirl eyes, `Hau` (confused) = `><` eyes; `Shy`/`Disgust` also rolled the irises against the gaze controller. Energy from `inner_state` reaches the avatar (`FacePort/BodyPort.setEnergy`): heavy lids (`clean:Sleepy`), slower breath, stiller body, heavier blinks, an occasional yawn when tired and idle.

## Key Conventions

- **29 emotions**: `neutral` | `happy`, `excited`, `love`, `proud`, `grateful`, `playful`, `amused`, `hopeful`, `relieved` | `sad`, `angry`, `scared`, `disgusted`, `frustrated`, `lonely`, `anxious`, `bored`, `jealous` | `surprised`, `thinking`, `confused`, `embarrassed`, `nostalgic`, `dreamy`, `determined`, `mischievous`, `curious`, `melancholic` — in `emotion/types.py::Emotion`
- **Emotion tag**: `[EMOTION:name:intensity]`. Legacy `[EMOTION:name]` = intensity 0.7. `extract_emotion` strips the tag; **`strip_prosody` strips `[PAUSE]` / `[SIGH]` / `[LAUGH]` / `[BREATH]` everywhere the text is not going to a voice** — persistence and Telegram. Those tokens are for the frontend, which cues them onto the audio; they used to reach the DB, the person fiche, the model's own rehydrated history and the nightly extractor, which built souvenirs containing stage directions.
- **WebSocket protocol** — a *synchronised* protocol, not fire-and-forget. `group_send` drops silently when a group has no member, and nothing ever replayed it: every reply produced while a tab was disconnected was recorded in the database and **invisible in the UI forever**, while the user's own message stayed on screen because it is painted *before* it is sent. Frames:
  - Client → server: `{"type":"chat","message":"...","person_id":"...","client_msg_id":"...","attachments":[...]}`
  - Server → client (reply): `{"type":"speech","text":"...","emotion":"...","emotion_intensity":0.75,"emotion_blend":[{"emotion":"...","weight":0.x}, ...],"emotion_state":{...},"source":"...","inner_state":{...},"speak":true,"voice_reason":"screen_ok","voice_persona":"speaking|inner","voice_profile":{"pitch":1.0,"rate":1.0,"gain":1.0}}` — voice fields from [pipeline/voice.py](old/backend/pipeline/voice.py); `speak:false` means show the text but stay silent. Additionally carries `message_id` / `user_message_id` / `client_msg_id`, so the cursor advances during a normal conversation and an optimistically-painted bubble can be bound to its server row.
  - Client → server (identity handshake, first frame): `{"type":"identify","person_id":"...","display_name":"..."}`. A `person_id` smuggled in a later `chat` frame is **ignored** — identity is bound at connect/identify time only
  - Server → client (state refresh, no TTS): `{"type":"inner_state_update","inner_state":{...}}` — pushed by `broadcast_inner_state_update()` when inner state changes outside a turn (sleep transitions, project action queued). Goes to the **global** group because it is about Mika, not about anyone; passing a `person_id` sends it to *that person's* group instead, since `_collect_inner_state` then attaches their profile and commitments.
  - Server → client (emotion refresh, no TTS): `{"type":"emotion_update","person_id","emotion","emotion_intensity","emotion_blend":[...],"emotion_state":{...}}` — pushed to that person's group by `emotion.sync`. Applied as ambient drift (face + gaze + hand mood + idle posture, never a body one-shot, never TTS).
  - Server → client (project report, no TTS): `{"type":"project_report","project_id","project_title","text"}`
  - **Server → client (history)**: `{"type":"history","mode":"initial"|"catchup","messages":[{id, role, text, ts, source, emotion, emotion_intensity, attachments}],"last_id":N,"truncated":bool}` — sent unprompted at connect and in answer to a `sync`. Served by [communication/history.py](old/backend/communication/history.py), which asks two deliberately **separate** questions: `recent_for` ("what should I show a client that just opened?") and `after_for` ("what did this client miss?"). Ordered by `pk`, never `created_at` (`auto_now_add` collides on rapid inserts and a cursor must be totally ordered). Internal scaffolding excluded by the same `is_internal` rule the model's rehydrated buffer applies. `truncated` is reported rather than hidden: a silent cap would advance the cursor past messages never rendered.
  - **Client → server (catch-up)**: `{"type":"sync","after_id":N}` — the cursor is the highest `Message.pk` actually *rendered*, derived from the displayed thread, so it can never claim delivery of a frame a throwing handler dropped. `0` = "I have nothing trustworthy" → recent window instead of a diff.
  - **Keepalive**: `{"type":"ping","t":…}` → `{"type":"pong","t":…}`. A browser cannot send or observe protocol-level ping frames, and a socket killed by a sleeping laptop or a proxy often **never fires `onclose`**: it sits at `readyState === OPEN` and silently swallows everything written to it. The client pings every 20s and force-reconnects after 50s of silence (two missed pongs), and also on `visibilitychange`/`online`/`focus`.
  - **Server → client (ack)**: `{"type":"ack","client_msg_id":"…","status":"accepted"|"rate_limited"|"empty"|"overloaded"|"too_long"|"attachments_rejected"}` — emitted **after the submission and before the answer**. "The server has it" and "she answered" are different facts; but `turn_queue.submit` does not block, so acking *before* it bought nothing and cost a lie. Every refusal is said out loud and says **which** one. `too_long` and `attachments_rejected` exist because those messages used to disappear: the text was silently cut to `MAX_MESSAGE_LENGTH` (browser and DB then held two different sentences), and the empty-message guard tested the *raw* attachment list, so five oversized files with no caption passed it, validated down to zero, and sent `User: ` into the pipeline while the sender was told "accepted". **An `accepted` may carry `rejected_attachments: [{name, reason}]`** (`too_many` / `too_large` / `invalid`, capped at `MAX_REJECTED_REPORTED` so the ack cannot amplify a tiny frame into a large one): the all-or-nothing refusal only covers the case where *nothing* survives, and a partial send left the same divergence one rung lower — three captures typed, two described, and both sides believing they agreed. `validate_attachments` therefore returns `(retenues, écartées)` rather than the survivors alone, and the client paints the missing files under the bubble.
  - `inner_state` payload shape: `{person_scope, drives, energy, circadian, sleep_phase, today_journal?, last_dream?, projects?, pending_project_actions?, self_narrative?, ruminations, identity?, person_profile?, pending_commitments?}`. **`person_scope` says which question the payload answers.** A section with nothing to report is *omitted*, so "she knows nothing about you" and "this frame is not about anyone" arrived byte-identically — and the panel clears a section it is handed nothing for, which is right for the first and wrong for the second (every sleep transition wiped the identity block from every browser). `false` means the per-person keys carry no information and must be left alone.
  - **A targeted reply is never dumped on the global group.** "No presence entry" means *they are not connected*, not *there is no recipient* — and the payload carries that person's `inner_state`, so falling back to `BROADCAST_GROUP` landed a message composed for Adrien in every other open browser. An identifiable person offline now gets silence; nothing is lost, since the turn is persisted and their client pulls it by cursor. The global group stays right for what belongs to no one — an `anon_*` socket with no durable thread, `conscience_mika` thinking out loud.
- **Perception Intent**:
  - `REQUEST_RESPONSE` — user/channel expects an answer (default)
  - `OBSERVATION` — passive stimulus (camera frame, ambient audio, file drop). No forced response; conscience observes.
  - `INTERNAL_TRIGGER` — Mika-driven (conscience `_act`, module `notify_ai`, drive overflow, rumination resurfacing). Broadcasts; `emit_event=False`.
- **Person identification**: transport handles (`user_{pk}`, `web_*`, `tg_{user_id}`, `anon_*`) are resolved to memory `Entity` rows **through the identity layer**, never by name equality. Internal IDs `conscience_mika`, `__global__`, `anonymous` are reserved and never identified.
- **Personality is dashboard-driven**: Configuration → *Personnalité* (identity, tone, greetings), *Personnalité · Caractère* (traits, quirks, vulnerabilities, values, interests, speech patterns) and *Personnalité · Rythme* (circadian). The **temperament** sits apart, under *Émotion · Tempérament*, because those five are sliders rather than prose. The character lists use the `lines` value type — one entry per line, **not** comma-separated: a trait is a sentence, and « Curieuse de tout, pas juste de tech » split on the comma into two traits, one of them starting with « pas ».
- **Singletons** (module-level, imported throughout): `ai_router` (`ai.router`), `ai_client` (`ai.client`), `memory_manager` (`memory.manager`), `emotion_engine` (`emotion.engine`), `drive_engine` (`drives.engine`), `personality` (`config.personality`), `module_manager` (`modules.manager`), `conscience_engine` (`conscience.engine`), `narrative_generator` (`memory.narrative`), `person_profile_generator` (`memory.person_profile`), `sleep_cycle` (`memory.sleep`), `project_runner` (`projects.runner`). Circadian is pure-function only — any caller passes the current `datetime` + the personality's `CircadianProfile`.
- **Background loops**: the four dedicated loops (consolidator, sleep cycle, project runner, emotion sync) share [utils/periodic.py](old/backend/utils/periodic.py)::`PeriodicLoop` — idempotent `start`/`stop`, first tick after one interval (never during startup), and a tick failure logged rather than propagated. That last property is load-bearing: **nothing supervises these loops**, so an escaping exception ends one for the lifetime of the process. Deliberately minimal — no jitter, no backoff, no supervision tree; the module cron scheduler has different needs (per-module intervals, detached ticks) and does not use it.
- **Django settings** in [config/settings.py](old/backend/config/settings.py): `PROJECT_ROOT` = `BASE_DIR.parent` (where `.env` lives — the repo root before the archive, `old/` since), `BASE_DIR` = `old/backend/`
- **INSTALLED_APPS**: `ai`, `communication`, `emotion`, `drives`, `memory`, `conscience`, `modules`, `projects`, `identity`, `files`, `GestionSysteme`, `configs`
- **Adding a new input source** (Discord, webhook): write an adapter that builds a `Perception` and calls `pipeline.router.perceive()`. No pipeline changes needed.
- **Adding a new modality** (ultrasound sensor): add a preprocessor in [pipeline/preprocessors/](old/backend/pipeline/preprocessors/) and register its dispatch entry. Router + processor pick it up automatically.

**API Key only**: `ai.claude.api_key` (starts with `sk-ant-api`), encrypted at rest (`configs/secrets.py`) and redacted in every read path. There is no second way in.

**The OAuth path is gone, and it is not coming back.** `ai.claude.oauth_token` (an `sk-ant-oat01-` token lifted from a Claude.ai login) was the *recommended* mode, because the raw Messages API rejects such a token with a 401 — so the provider carried a `claude_agent_sdk` CLI subprocess as an auto-fallback, flipping `_force_agent_sdk_tools` for the instance's lifetime on that 401. Anthropic no longer supports that usage and it stopped working. Keeping a transport that cannot authenticate would only convert a clear failure into a silent one, so the whole path was removed: the CLI loop, the MCP server built for it, the `CLAUDE_CODE_OAUTH_TOKEN` plumbing, the 401 switch, and the config item. A test walks the AST of every module under `old/backend/` and fails on any `import claude_agent_sdk`; `requirements.txt` no longer pins it.

Consequences worth knowing: a 401 now **propagates** — before a tool ran or after — instead of replaying the turn on a second transport, and a turn that cannot authenticate serves the fallback text like any other provider outage. The native Messages API tool loop is the only path, for tooled and untooled turns alike. An install still holding an OAuth token in its database gets a French `ValueError` naming the screen where to paste an API key; the stored value is never read again.

A credential alone is not enough: declare a model under *IA · Modèles* and map the roles under *IA · Rôles*, or every turn answers "Mon IA n'a pas de modèle associé".

## Configuration

**Everything applicative is configured in the dashboard** (`/gestion/` → Configuration), stored in `ConfigValue`, read at runtime through `config_service.get("<key>")`. `.env` holds infrastructure only — the things Django needs before a database exists.

The `ConfigItem.env_fallback` **field** and `seed_from_env()` have been removed, along with ~31 `settings.py` constants that existed only to feed them. Reasons, in increasing severity:

1. **Two declared defaults per knob.** The settings one always won at seed time, so the registry default — the one a reader looks at — was decorative and free to drift.
2. **The bridge silently didn't work for seven keys** because it read a *settings attribute* nobody had declared: `GEMINI_API_KEY`, `GLM_API_KEY`, `AI_ROLE_VISION_CAPTION`, `AI_ROLE_INNER_VOICE`, `EMOTION_DECAY_RATE`, `SLEEP_CHECK_INTERVAL`, `PROJECT_RUNNER_INTERVAL`. Five were documented as supported.
3. **`AI_ROLE_*` could only ever seed a broken value** — they carried the legacy `provider:model` string while `AIRouter._resolve` looks the value up as an **internal name** from the `ai.models` record list, so the seeded value raised `UnconfiguredRoleError`.
4. Once seeded, `.env` was inert forever with no feedback.

**The two seed-on-first-boot paths are gone with it**, for the same reason wearing a different hat. `IMAP_*`/`SMTP_*` created an `EmailAccount` row and `RSS_FEEDS` created `RSSFeed` rows — both only against an *empty* table, so after the first boot the variable was inert with no feedback, and a credential rotated in `.env` silently did nothing. Accounts and feeds are ORM rows edited in the dashboard; there is no second way to declare one. Nothing migrates: an install that had been seeded already holds its rows in the database and is unaffected.

A fresh clone therefore starts **unconfigured, on purpose**. Every non-role knob carries a working registry default, so the background loops run regardless.

Guarded by tests: `ConfigItem` cannot even *declare* an `env_fallback` (the dataclass field is gone, so re-adding it is a deliberate edit rather than a line slipped into one schema), no `settings.py` constant shadows a config key, no `AI_ROLE_*` constant survives, no credential or module-config constant survives (asserted on prefixes — `POP3_USER` would be the same mistake under a new name), and every operational knob has a default.

### Operational constants live in the dashboard, each in its own section

The tuning values that used to be module-level constants — sleep hours, oscillator time constants, drive growth rates, the eleven conscience scoring factors, retrieval and context caps, per-module poll intervals and retention ceilings — are `ConfigItem`s, **28 sections** / ~385 items, rendered under Configuration and, for a module, inside that module's own space. `drives`, `identity`, `files`, `communication` and `pipeline` gained a `config_schema.py`; `pipeline` is not a Django app, so `configs/apps.py` registers it explicitly through `_SCHEMAS_HORS_APPS` rather than promoting the package for one file.

**The constant does not leave the module — it becomes the fallback.** Read sites go through [configs/runtime.py](old/backend/configs/runtime.py) (`cfg_int` / `cfg_float` / `cfg_bool` / `cfg_str` / `cfg_list`), which coerces, bounds-checks and never raises: a knob read from an unreachable registry (import before `migrate`, locked DB, test collection) yields the value the code ran on before it was configurable, not an exception inside an unsupervised loop. Two consequences worth knowing: a constant read as a **`def` default argument** is frozen at import, so those became `None` sentinels resolved in the body; and a value captured at construction (`asyncio.Queue(MAX_PENDING)`, a `deque(maxlen=…)`, an executor's worker count, an MCP tool *description*) is declared `restart_required=True` rather than pretending to hot-reload.

**One declared default per knob, verified.** The fallback and the `ConfigItem.default` are the same value written twice, which is exactly the shape `env_fallback` had — the difference is that here they must be *equal*, and [test_config_rapatriement.py](old/backend/tests/test_config_rapatriement.py) walks the AST of every `cfg_*` call site to prove it, plus the four tables the AST cannot read (`ScoringTuning`, `TrustTuning`, `DEFAULT_PARAMS`, `VOICE_PROFILES` — f-string keys and attribute fallbacks). It also pins the two calibrations that stop being self-evident once they are individually editable: the conscience caps (+0.30 idle, +0.50 drives, −0.30 ignored) summing *exactly* to `act_threshold`, and `self_declared + shared_memory` landing *exactly* on the identity disclosure bar. Non-vacuous by mutation on four paths.

**Pure functions stayed pure.** `conscience/scoring.py`, `identity/trust.py` and `emotion/circadian.py` read no config: each grew a frozen tuning dataclass (or an optional parameter) whose defaults *are* the module constants, resolved at the boundary by the engine. The reason is not aesthetic — `config_service`'s cache is primed from the real `data/vtuber.db`, so a config read inside them would make the calibration tests measure the developer's database instead of the declared policy.

**What deliberately did NOT move**: the Forge sandbox's allow/deny surface (`FORBIDDEN_*`, `SAFE_MODULES`, `ALLOWED_DUNDER_DEFS`, `MAX_SOURCE_BYTES`, `HANDLER_PREFIXES`) — forged code is written by the model and `exec`'d in-process, so a config write there is arbitrary RCE; the channel floors and ceilings in `identity/trust.py` (that a public-room claim can never equal a login is not a preference); `eventbus` priority bands and `INTERNAL_PREFIX`; prompt templates, PAD anchors and mapping tables; numerical-integration steps; third-party facts (`_PRICING_PER_MILLION`, `_KNOWN_WINDOWS`); coupling tables a test already pins (`_TRIM_ORDER` against `_LAYERS`); and the constants that are *already* the fallback for an existing key — a second key for the same knob is the bug, not the fix.

**The character came along, and `personality.yaml` is gone.** Name, description, language, the three tones, the greeting and its three mood variants, the five character lists, the speech patterns and the whole circadian profile are `personality.*` keys across three sections (*Personnalité*, *· Caractère*, *· Rythme*). The file was deleted rather than emptied — a blank file is an invitation to paste a block back into it, and the temperament had already left for the same reason. The declared defaults reproduce its contents word for word, so a fresh clone gets the same Mika; a test asserts the file never comes back. This also needed a new value type: `lines`, a textarea split on newlines, because `list` splits on commas and these entries are sentences.

**The dashboard reads what the engine reads.** Five screens were still reading module constants and would have displayed the declared defaults while the prompt ran on the configured values: the identity fiche and its *Politique* tab (`views/social.py` → `politique_confiance()`), the drives panel (`views/inner.py` → `params_for`), the project fiche's `runs_cap`, `pipeline/prompt.py`'s history weight, and the retention sweep's claim TTL (which must agree with the resolver, or an expired claim stays counted as pending). That divergence is the thing those pages exist to prevent.
