# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development Commands

**First run** — nothing is configured until you say so. Start the backend, open
`http://localhost:8000/gestion/` → Configuration, then:

1. *IA · Claude* — paste an OAuth token (recommended, from your Claude.ai login)
   or an API key. Stored encrypted in the database, never in `.env`.
2. *IA · Modèles* — declare a model (internal name + provider + model id).
3. *IA · Rôles* — map at least `conversation` to that internal name.

Until step 3, every turn answers "Mon IA n'a pas de modèle associé". `.env` holds
infrastructure only (see Configuration).

**Backend** (Django + Channels on Uvicorn):
```bash
pip install -r backend/requirements.txt
python run.py                    # http://localhost:8000, ws://localhost:8000/ws
```

**Frontend** (Vite + Three.js + TypeScript):
```bash
cd frontend && npm install
npm run dev        # http://localhost:3000
npm run build
```

**Database migrations**:
```bash
cd backend && python manage.py migrate
```

**Tests** (pytest + pytest-django):
```bash
python -m pytest backend/tests/                    # full suite
python -m pytest backend/tests/test_perception.py  # single file
```

## Architecture

VTuber engine: a 3D avatar driven by Claude AI responses with real-time emotion mapping, evolving self-concept, theory of mind, and intrinsic drives.

### Core model: Perception → Router → Pipeline

Every input entering Mika (chat text, Telegram, internal conscience initiatives, module notifications, future camera/audio/files) becomes a `Perception`. A central router dispatches it based on `Intent`; the processor does the AI call only when a response is needed. Silence is a valid outcome.

```
Sources (WebSocket, Telegram, Conscience, Modules, future: Camera/Audio/File/Sensor)
   │  each source builds a Perception
   ▼
pipeline.router.perceive(Perception)
   ├─ save raw media (if non-text)
   ├─ run modality preprocessors (vision/audio/files → text)
   └─ dispatch by Intent
        ├─ REQUEST_RESPONSE  → process_message(perception)  → broadcast answer
        ├─ INTERNAL_TRIGGER  → process_message(perception)  → broadcast, no event
        └─ OBSERVATION       → module_manager.emit_event    → conscience decides later
```

### Data Flow (text chat turn)

1. Client sends `{"type":"chat","message":"...","person_id":"...","attachments":[...]}` via WebSocket
2. `WebSocketConsumer.receive()` ([backend/communication/channels/web_frontend.py](backend/communication/channels/web_frontend.py)) validates, builds a `Perception` (text-only or mixed), calls `perceive()`
3. `pipeline.router.perceive()` saves any raw media, runs preprocessors to transform image/audio/file parts into text descriptions, then routes by intent
4. `pipeline.processor.process_message(perception)` runs the full pipeline:
   - **Context assembly** ([pipeline/context.py](backend/pipeline/context.py)): memory + emotion + drives + modules + self-concept + per-person context
   - **Prompt building** ([pipeline/prompt.py](backend/pipeline/prompt.py)): personality → self-concept → person-context → modules → emotion → memory
   - **AI call** ([pipeline/response.py](backend/pipeline/response.py)): wrapped in `asyncio.wait_for(timeout=AI_CALL_TIMEOUT)`; routes to provider via `ai_router`
   - **Emotion processing**: `[EMOTION:name:intensity]` tag extracted, applied as an impulse on the person's PAD oscillator
   - **Persistence**: user Message + assistant Message saved with `attachments_meta`, built from the parts carrying `original_kind` and **not** from a `kind != "text"` filter — preprocessing runs in the router *before* the processor and *replaces* the part (an image Part is already `Part(kind="text", content="[image: …]")` here), so that filter matches nothing and persists an empty list
   - **Broadcast**: response + emotion state + blend to all WebSocket clients
5. Frontend receives `{"type":"speech","text":"...","emotion":"excited","emotion_intensity":0.75,"emotion_blend":[...],"emotion_state":{...}}`, updates VRM blend shapes and chat UI

On AI error or timeout: fallback text returned, **no emotion impulse toward the user**, **no chat.message event**, **no `_turn.completed` announcement** — a failed exchange is not a real exchange. It *is* **persisted**, with the fallback reply flagged `is_internal`: what someone said happened whether or not the model replied, so the question stays in the history / on the person's fiche / in the consolidator's input, while the fallback never becomes a souvenir nor something Mika "said".

### Database — SQLite under permanent concurrent load

Six background loops write continuously (conscience 30s, consolidator 60s, sleep 60s, project runner 30s, module scheduler 1s tick, emotion snapshots), and `sync_to_async` calls interleave with them (the default `thread_sensitive=True` serialises them onto one shared executor thread, so `asyncio.gather` around several buys nothing). On the default `journal_mode=DELETE`, a single writer blocks every reader and Python's 5s busy timeout surfaces as `database is locked`.

[config/settings.py](backend/config/settings.py) therefore sets `OPTIONS`: **WAL**, `synchronous=NORMAL`, `foreign_keys=ON`, a 32 MB page cache, and a 30s lock timeout (`DB_LOCK_TIMEOUT`). Invisible in tests (pytest-django uses an in-memory DB where WAL is a no-op), so the regression test asserts the declared `init_command`, not the runtime PRAGMA.

### Backend layout

- **Entry point**: [run.py](run.py) — adds `backend/` to sys.path, configures Django, launches Uvicorn
- **ASGI** [config/asgi.py](backend/config/asgi.py): `LifespanWrapper` runs startup (memory → emotion → conscience → modules) and shutdown
- **Communication channels** ([communication/](backend/communication/)): adapters that translate external inputs into `Perception` objects and hand them to `pipeline.router.perceive()`. Each channel builds its own Perception; no shared legacy handler.
  - [communication/channels/web_frontend.py](backend/communication/channels/web_frontend.py) — `WebSocketConsumer`, greeting routed through `perceive()` as `INTERNAL_TRIGGER`
  - [communication/channels/telegram.py](backend/communication/channels/telegram.py) — text AND inbound media: photos / voice notes / audio / documents downloaded (≤5 MB), lifted into a MIXED `Perception` with their caption, preprocessed like any frontend upload. **Bounded like the web path, and for the same reason**: a bot name is discoverable, and every inbound message costs a full pipeline turn. A sliding window per *account* (`tg_<id>`, 20/10 s — the web counts per connection, there is none here), an optional allow-list (`telegram.allowed_chats`, empty = everyone) checked **before** anything is written, so a stranger leaves behind no presence entry, no `IdentityHandle` and no `Message`, and a refusal said out loud rather than dropped. The turn goes through `turn_queue` like a browser's: `python-telegram-bot` dispatches updates in series, so awaiting the pipeline in the handler made the bot deaf for the whole turn (`/start` included) *and* short-circuited the queue — a Telegram message and a web message running as two concurrent LLM calls against a one-slot local backend. The reply therefore comes back through `broadcast_to_websocket` → `deliver()`, which is why dispatch **no longer skips the originating module**: nothing else sends any more
  - [communication/routing.py](backend/communication/routing.py), [communication/urls.py](backend/communication/urls.py), [communication/views.py](backend/communication/views.py) — WS routing + HTTP health/personality endpoints
- **Pipeline** ([pipeline/](backend/pipeline/)):
  - [pipeline/perception.py](backend/pipeline/perception.py) — `Perception`, `Part`, `Modality`, `Intent`, constructors (`from_text`, `from_internal_trigger`, `from_mixed`)
  - [pipeline/router.py](backend/pipeline/router.py) — `perceive(Perception)` single entry point; saves media, runs preprocessors, dispatches by Intent
  - [pipeline/processor.py](backend/pipeline/processor.py) — `process_message(perception, *, context, broadcast, persist, emit_event)`; returns `SpeechOutput`
  - [pipeline/context.py](backend/pipeline/context.py) — `gather_context()` → `ConversationContext` (memory, emotion, drives, modules, history, tools, `self_concept`, `person_context`)
  - [pipeline/prompt.py](backend/pipeline/prompt.py) — `build_system_prompt(context)` + `format_conversation()`. Takes the `ConversationContext` object itself. The twelve near-identical `if x: system += "--- TITRE ---" …` blocks are the `_LAYERS` table — **the order is the table, and the table is what runs**. Footers stay deliberately inconsistent (`--- FIN PROJET ---`, `--- FIN ETAT EMOTIONNEL ---`, `--- FIN ---`): the refactor is byte-for-byte output-preserving, and unifying them changes what the model reads. `getattr` is strict, no default — a typo'd field name would otherwise silently drop a block from every prompt. `ConversationContext()` with no arguments is valid.
  - [pipeline/response.py](backend/pipeline/response.py) — `call_ai_and_parse()` builds prompt, calls AI, extracts emotion
  - [pipeline/broadcast.py](backend/pipeline/broadcast.py) — `broadcast_to_websocket()`, `emit_communication_event()`, and persistence **split in two**: `persist_user_message(..., attachments_meta)` before the AI call, `persist_assistant_message(..., replying_to=)` after. The order is the point: the AI call is the long fragile part of a turn, and persisting afterwards meant a restart erased the *question* too. Writing first turns that into a merely-unanswered question, recoverable via `Message.awaiting_reply` (migration `memory/0015`). The user side is written *after* `gather_context` — `add_message` also appends to the short-term buffer that `gather_context` just read, so persisting earlier shows the model the current message twice. `persist_assistant_message` clears the flag **including for a failed turn**, or the same failing turn replays at every boot.
  - [pipeline/turns.py](backend/pipeline/turns.py) — `TurnQueue`, the pool that answers people. Channels dispatches a consumer's frames one at a time, and awaiting the pipeline inside `receive()` made the connection deaf for the whole turn (no pong, no catch-up), so liveness watchdogs reconnected mid-turn. A bare `create_task` per message would instead give out-of-order replies and concurrent LLM calls, which a one-slot local backend just queues. Hence a queue with a small fixed pool (`pipeline.turn_workers`, default **1**; raise only behind a hosted API). The reply finds its way back because `broadcast_to_websocket` sends to the *person's* group, never to the socket that asked — **a turn never needed the connection that started it**. Backlog past `MAX_PENDING` is refused out loud (`ack: overloaded`); one broken turn never takes the worker down (nothing supervises this pool). `resume_interrupted_turns()` runs at ASGI startup and re-queues what `awaiting_reply` marks, clearing the flag **as it re-queues, not on success**, so a turn that dies twice cannot form a crash loop. A replayed turn carries `original_message_id` and the processor **reuses that row instead of re-writing the question** (a second copy would show on the fiche, in the consolidator, and on screen). Deliberately not in scope: serialising every LLM call in the process — conscience, project runner and sleep cycle never pass through here; "never two calls at once on a one-slot backend" belongs to the AI router as a per-provider semaphore.
  - [pipeline/preprocessors/](backend/pipeline/preprocessors/) — modality-specific Part transformers. `vision.py` captions via `AIRole.VISION_CAPTION`. `audio.py` transcribes via the OpenAI provider's Whisper endpoint (`ai_router.provider_by_name("openai")` — router cache, so credential rotation applies; no other provider exposes STT). `files.py` extracts text locally: text-like MIME/extensions (utf-8 → latin-1 fallback), HTML tag-stripping, PDF via `pypdf`, DOCX via optional `python-docx`; parsing runs in a thread. Failures + timeouts produce a safe text placeholder — an error is never surfaced as content.
  - [pipeline/media.py](backend/pipeline/media.py) — attachment validation + raw media persistence. Disk writes go through `asyncio.to_thread` (5 MB × 5 synchronous writes would freeze all WS traffic and every loop).
  - **Inner-state reads go through one layer** ([memory/read.py](backend/memory/read.py), [conscience/read.py](backend/conscience/read.py)) — one function per *question*, returning rows, never formatted output. Three consumers (system prompt in French prose, WebSocket `inner_state` JSON, dashboard JSON) each used to carry their own copy, and one had drifted into "the newest dream **ever**" presented as last night's.
    - `latest_journal()` and `journal_for(yesterday())` are deliberately **not** the same call (pinned by tests): a journal is dated the day it *covers* and light sleep writes it late that evening, so between ~23h and midnight the newest row is today's — right for a "journal du jour" panel, wrong for a "ton fil d'hier" prompt block.
    - **One clock.** Everything dates from naive local (`date.today()`), matching the writer (`memory.sleep` stamps from `datetime.now()`). `timezone.localdate()` reads Django's `TIME_ZONE` and drifts by a day between midnight and dawn; a test asserts it never comes back.
  - [pipeline/signals.py](backend/pipeline/signals.py) — `_turn.completed`, what the processor *announces* about a finished turn. Replaces a tail of hardcoded reactions (`drive_engine.on_reply`, `conscience_engine.post_action_audit`) that made the processor the carrefour obligé of the engine. Subsystems subscribe themselves (`drives/apps.py`, `ConscienceEngine.initialize`) **carrying their own skip rules** ("an internal trigger isn't answering someone" is drive policy; "professional mode produces no self-doubt" is rumination policy). Emitted only on success.
    - **What deliberately did NOT move**: the emotional impulse (`emotion_engine.process_emotion`) and passive identification (`identity_resolver.ingest_message`) stay inline — they are *steps*, not listeners, and their effects are read later in the same turn. The rule: **a step changes the turn, a listener merely learns about it.**
  - [pipeline/tracing.py](backend/pipeline/tracing.py) — `request_id` ContextVar + logging filter
- **AI (multi-provider)** ([ai/](backend/ai/)):
  - `ai/providers/` — `ClaudeProvider`, `OpenAIProvider` (OpenAI-compatible via `base_url`), `OllamaProvider`. Lazy-instantiated. All accept an `attachments=[MediaAttachment]` kwarg with image support: Claude uses `{"type": "image", "source": {...}}` blocks, OpenAI `image_url` data-URIs, Ollama base64 via the `images` message field (silently ignored if the model isn't vision-capable).
  - **Ollama generation policy** — without it a local model never answers. Two knobs in Configuration → *IA · Providers* → Ollama. `ai.ollama.thinking` (default **False**): gemma4/qwen3/deepseek-r1 reason by default, before the first word of the reply — measured on gemma4:12b (RTX 3060, ~30 tok/s), "coucou" took 1.5 s off vs 27.1 s on, and with a real prompt + 34 tool declarations it blew past the 120 s timeout every turn. `ai.ollama.max_reply_tokens` (default **768**) caps `num_predict` (was 4096 → 219 s at the ~19 tok/s a long context degrades to). Both read defensively: an unreadable config yields thinking-off and the cap, never the unbounded behaviour. A server or model rejecting `think` is retried without it.
  - **Ollama Cloud is a separate provider** (`ollama_cloud`, [ai/providers/ollama_cloud_provider.py](backend/ai/providers/ollama_cloud_provider.py)) — two machines, two catalogues, two budgets; a declared model row names one or the other, so a small local model can run `inner_voice` while a hosted 400B runs `conversation`. Sharing `ai.ollama.*` would let the local 768-token belt truncate a hosted model (its default is **2048**). Implemented as a *subclass*: `CONFIG_PREFIX` / `DEFAULT_HOST` / `FALLBACK_MAX_REPLY_TOKENS` class attributes + a `_headers()` hook; the tool loop is not duplicated. The two evict independently because prefix matching is a plain `startswith` and `ai.ollama_cloud.api_key` does not begin with `ai.ollama.` (a test pins it; `ai.ollama.cloud.` would have coupled them). Measured against the live endpoint: **`GET /api/tags` is public** (so "charger la liste" works before any key — and why `test()` is overridden, the inherited probe being `list_models()` would call an uncredentialed provider healthy); **`GET /api/ps` answers 401 with a bad key, 200 with a good one**, so only 401/403 counts as a rejection (404 = host doesn't serve the probe); **hosted model ids carry no `-cloud` suffix** (`gpt-oss:120b`, `kimi-k3`, `glm-5.2`). Both variants price at **$0/token** in `ai/quota.py`, matched on the `ollama` *prefix* so a future variant can't fall through to the pricing table.
  - `ai/router.py` — `AIRole` enum (8 roles incl. `VISION_CAPTION` and `INNER_VOICE`) + `AIRouter` singleton. Each role maps to a declared model. `attachments=[MediaAttachment]` forwarded for multimodal calls. `provider_by_name(name)` gives cached-provider access for capability-specific call sites outside the role system (Whisper STT in the audio preprocessor, `files_service.op_transcribe`) — same cache + credential eviction, never a fresh instance pinning an old key.
  - Provider instances are cached but **evicted when their credentials change**: `_PROVIDER_CONFIG_PREFIXES` subscribes to `ai.<provider>.*`, so rotating a leaked key actually takes effect. Those items are `hot_reload=True`.
  - **One semaphore per provider** — `_metered_call` reserves a slot before every routed call. The knob is `ai.<provider>.max_concurrent_calls` (Configuration → *IA · Providers*), **declared for all six providers**, `0` = unbounded; only the *default* is provider-specific: **1 for `ollama`**, unbounded elsewhere. Declared everywhere because the reason to cap differs rather than disappears — on a hosted API the parallelism is real, but it is billed and rate-limited, and a burst of background loops can exceed a provider's rate limit on its own. A one-slot local server does not run two calls in parallel, it *queues* them, and that queue time is counted **inside** the same `ai.call_timeout_seconds` bound the generation gets: a conversation turn arriving behind two background generations returns the fallback text and looks exactly like a slow model. `TurnQueue` orders the *turns*; this orders the *calls* — the six background loops never pass through the queue. Wait and generation therefore **share one budget** and are **logged separately**: waiting for a slot is time spent inside the call, not time granted on top of it (the acquisition is bounded too, or a background loop — the caller with no `wait_for` of its own, the very reason the router took the bound over — would queue unbounded behind the loops ahead of it). An acquisition that never lands says so rather than vanishing. A nested call (an MCP tool re-entering the model from inside the tool loop, e.g. `files_analyze_image`) **reuses its caller's slot** via a ContextVar — otherwise it would wait for a slot its own caller holds, until the timeout.
  - `ai/client.py` — `complete()` simple text completion
  - `ai/tool_client.py` — `complete_with_tools()` (Claude-only, MCP tool loops)
- **Emotion system** ([emotion/](backend/emotion/) — standalone Django app):
  - `emotion/types.py` — 29 emotions in 4 categories, `EmotionData`, `extract_emotion()`
  - `emotion/pad.py` — PAD (Pleasure/Arousal/Dominance) anchors, `pad_to_label()`, `pad_to_blend()` (top-K ambivalence)
  - `emotion/dynamics.py` — damped harmonic oscillator (semi-implicit Euler)
  - `emotion/state.py` — `PersonMood`, `GlobalMood`, `Temperament`, `MessageEmotion` (`blend` tuple + `is_ambivalent`), plus `load_temperament()` — the **only** reader of the temperament, sourced from `emotion.temperament.*` in the config registry (not `personality.yaml`)
  - `emotion/circadian.py` — pure functions: `current_phase()`, `current_state()`, `phase_bias()`, `energy_level()`. 4 phases (morning/afternoon/evening/night), cosine energy curve peaking ~14h. `CircadianProfile` from `personality.yaml::circadian_profile`, so a nocturnal character is a YAML edit.
  - `emotion/engine.py` — `EmotionEngine` singleton: PAD oscillators per person + global mood. `_home_vector()` = default_mood × 0.15 + phase_bias × 0.35. Two context accessors: `get_global_mood_context()` (Mika alone) and `get_person_affect_context(person_id)` (relational).
  - `emotion/sync.py` — `EmotionSync`, its own `PeriodicLoop` (`emotion.sync_interval`, default 3s). The only frame carrying an emotion used to be `speech`, so the face and readout froze between turns — worse than it sounds, because `process_emotion` applies an impulse as *velocity*: the position `compute_message_emotion` reads only moves over the following seconds, so a message's emotional consequence is **never** in the `speech` frame reporting it. The loop pushes `emotion_update` per connected consumer, per person (the value is her stance *toward that person*), and only when it moved (different dominant emotion, different ambivalence pair, or ≥`MIN_INTENSITY_DELTA` 0.04). Load-bearing details: it **hydrates before reading** (a read creates the mood at the origin, so reading first would lose the stored mood of a silently reconnecting client), and it **forgets a person on disconnect** — but only when the *last* connection goes. The consumer pushes one frame itself on connect and calls `note_pushed()`. That initial push is skipped for a not-yet-identified `anon_*` socket (a uuid minted seconds ago cannot have history, and reading its mood would create an oscillator for an id about to be discarded). Frontend applies the frame as *drift*: expression, gaze, hand mood and idle postures follow it, body one-shots do not (`decideGesture`'s `ambient` gate).
- **Drives system** ([drives/](backend/drives/) — standalone Django app):
  - `drives/state.py` — `DriveKind` (CURIOSITY, SOCIAL, EXPRESSION, REST), `DriveState`, per-drive parameters
  - `drives/engine.py` — `DriveEngine` singleton: tension grows over time, satisfied by actions, contributes signed to conscience scoring. REST pressure rises with activity, falls during idle. `energy_level()` combines circadian energy (70%) with REST drive (30%) → conscience Factor 11 (fatigue penalty), system prompt, frontend. All in-RAM (ephemeral across restarts).
  - **Every drive has a real relief path**: `on_conversation` (SOCIAL+CURIOSITY, incoming), `on_act` (EXPRESSION full, spontaneous speech), `on_reply` (EXPRESSION ×0.4 + activity, on every successful reactive answer), and **sleep relieves REST** (`SLEEP_REST_RECOVERY` per sleeping tick).
  - **Who calls them is drive policy, declared in `drives/apps.py`** — `on_reply` *and* `on_conversation` both hang off `_turn.completed`. `on_conversation` used to be called by `conscience.observe()`, gated on a literal `("chat.message", "telegram.message")`: it was the only caller in the repo, so SOCIAL's only relief path depended on the *name* an input channel gave its event (`telegram.message` is emitted by nobody — Telegram goes through `emit_communication_event`, like every channel). A channel not producing that exact name left SOCIAL pinned at 1.0 while the conversation was happening, and the prompt kept declaring a need for contact. The internal-person filter is `identity.trust.is_internal_person`, not a second list. `conscience.observe()` keeps `_last_activity` (idle detection) and `on_observation` (relief proportional to *interpreted pertinence*, a value only the conscience holds).
- **Personality**: [config/personality.py](backend/config/personality.py) — loads [personality.yaml](personality.yaml) (name, description, tone, traits, quirks). `personality.temperament` survives as the accessor everyone calls but reads the config registry, not the file.
- **Memory** ([memory/](backend/memory/)):
  - `memory/manager.py` — `MemoryManager` singleton: short-term (RAM deque, `MEMORY_SHORT_TERM_LIMIT` messages) + ORM persistence + consolidator lifecycle. **Survives restarts**: `initialize()` reattaches to the conversation in progress when the last message is under `resume_window_minutes` (120) old, then `_rehydrate_short_term()` reloads the tail into the RAM buffer. `get_conversation_context()` is the *only* history the LLM sees. Internal scaffolding (`is_internal`) is skipped.
    - **The short-term buffer is one thread, shared by everyone, and that is deliberate.** No `person_id` filter, in either `add_message` or `_rehydrate_short_term`: a person in a room hears what is said in it, and the arbitration belongs to Mika, from the certainty and closeness she has toward whoever is in front of her (`--- QUI TU AS EN FACE ---` sits immediately before what she knows of them precisely to qualify it). A `WHERE person_id = …` would make her structurally incapable of saying "Alice asked me the same thing this morning".
    - The distinction with the gated blocks: `PersonProfile`, commitments and emotional history are a **file** — assembled behind someone's back, never said in her presence — so disclosure is gated mechanically (`may_disclose_private_context`, never in a public room at any certainty). **What was said to her is hers to weigh; what was compiled about someone is not hers to read out.** Tightening happens in the prompt, not by filtering the buffer.
  - `memory/models.py` — `Conversation`, `Message` (with `attachments_meta` JSONField), `Theme`, `Entity`, `Souvenir`, `Connaissance`, `EmotionSnapshot`, `EmotionalSummary`, `ConsolidationLog`, `SelfNarrative`, `PersonProfile`, `Commitment`, `DailyJournal`, `Dream`
  - `memory/storage/` — `vector_store.py` (ChromaDB) + `consolidator.py` (background loop: extraction → indexing → decay → emotion aggregation → narrative regen → person profile regen → sleep cycle)
    - **Decay is relative, not absolute**: `importance *= decay_rate ** days_since(Souvenir.decayed_at)`. `decayed_at` only advances when a write happens, so sub-threshold elapsed time accumulates instead of being dropped (migration `memory/0012`). The old absolute form wiped conscience boosts and inflated fresh low-importance souvenirs.
    - **`Connaissance` is anchored on `decayed_at` too** (migration `memory/0014`). It used `updated_at` (`auto_now`), which Django only refreshes when the column is written — never under `save(update_fields=["confidence"])` — so every pass re-subtracted the entire elapsed decay (a 30-day-old fact hit the 0.2 floor in ~10 min of ticks).
    - **The decay sweep is throttled and narrowed**: `_apply_decay` runs hourly (`DECAY_INTERVAL_S`), selects only rows whose anchor is older than `DECAY_MIN_AGE` (1h), caps the batch at `DECAY_BATCH` (500) since every write re-embeds into ChromaDB. Nothing is lost — a skipped row keeps its anchor. Commitment expiry keeps its own cadence.
    - **Checkpoint reads the ceiling first**, then messages `id__lte` it; the reverse let a turn persisted between the two queries be counted but never extracted.
    - **Internal scaffolding is excluded by a flag, not a source denylist**: `Message.is_internal` (migration `memory/0013`) marks machinery — the "user" prompt of an `INTERNAL_TRIGGER` perception (greeting brief, module `notify_ai` text) and the fallback *reply* of a failed turn. Her real replies stay included. The exclusion is `.exclude(is_internal=True)`, not `.exclude(role="user", is_internal=True)`: the flag says "nobody said this", a property of the message, not of the side it sits on.
    - **The flag also keeps it out of the RAM buffer** — `add_message` and `_rehydrate_short_term` now agree, or a run of timeouts hands the model a history full of sentences she never said. The dashboard is the one reader that deliberately shows them, muted and badged `interne`.
  - `memory/extraction/extractor.py` — AI extraction of 3 types: souvenirs (1st-person episodes), connaissances (3rd-person facts), commitments (promises Mika made). The call also receives the current **pending commitments** and can return `commitment_resolved` entries.
  - **Commitment lifecycle closes** three ways: (1) consolidator marks `honored`/`dropped` from `commitment_resolved`, (2) Mika resolves mid-chat via `memory_resolve_commitment`, (3) `_expire_commitments` drops anything past `due_at` or pending > 30 days (`COMMITMENT_MAX_AGE_DAYS`).
  - `memory/module.py` — **memory_tools** SYSTEM module (registered in `memory/apps.py`): active recall via MCP tools `memory_search` (semantic, souvenirs+connaissances), `memory_recent_souvenirs`, `memory_read_journal`, `memory_list_commitments`, `memory_resolve_commitment`.
  - `memory/retrieval/retriever.py` — semantic search + person_id boost + recency bias + confidence
  - `memory/narrative.py` — `NarrativeGenerator`: regenerates `SelfNarrative` when ≥24h old AND ≥5 new souvenirs
  - `memory/person_profile.py` — `PersonProfileGenerator`: theory of mind per person-entity (closeness, preferred tone, topics of interest, sensitive topics). Gated (≥24h + ≥3 new souvenirs mentioning them); capped at 3 persons/cycle
  - `memory/sleep.py` — `SleepCycle` singleton. See "Sleep Cycle" below.
- **Conscience** ([conscience/](backend/conscience/)): Mika's waking brain. See dedicated section below.
- **Degradation ledger** ([utils/degradation.py](backend/utils/degradation.py)): the engine swallows failures on purpose — a background loop has no supervisor, and not knowing who someone is must never cost someone their answer. But collectively a partial failure becomes indistinguishable from normal operation (a prompt block empty because its query throws looks exactly like one with nothing to say). This does not change *whether* failures are swallowed, it **counts** them: `degradations.record(label, exc)` replaces a `logger.debug` one-for-one with no control-flow change, and `degraded(label)` is the context-manager form for bare-`pass` sites. Per site: count, `first_seen`, last error, distinct error types. In-RAM, process-scoped. **72 sites wired**, chosen where silence costs most: the conversation hot path (`pipeline/`, including `_merge_section` covering ten inner-state loaders) and the four unsupervised loops (`projects/runner`, `conscience/engine`, `memory/sleep`, `memory/storage/consolidator`). **Two label conventions**: curated prose (`prompt: journal context`) for hot-path sites, machine-derived `module.function` for the AST sweep. A test asserts no label covers two different functions (deriving from the enclosing *class* made five `EmotionEngine` handlers indistinguishable), and another that every `record()` sits inside an `except`. Surfaced at `GET /gestion/systeme/sante/` alongside `event_bus.stats()`.
- **Retention sweep** ([memory/retention.py](backend/memory/retention.py)): declarative ceilings on append-only tables, applied hourly from the consolidator tick (both paths). `POLICIES` is a tuple of `Policy(app_label, model_name, date_field, keep_days, keep_rows, protect)`. `ConscienceLog` gets a row on **every** decision cycle (~2 880/day at 30s), plus `ConsolidationLog` (only the newest row is read), faded `Rumination`s (active/resolved protected — journals and digestion reference them), `ProjectLog`. A broken policy is logged and skipped, never fatal.
- **Module plugin system**: [modules/base.py](backend/modules/base.py) (`BaseModule` ABC) + [modules/manager.py](backend/modules/manager.py) (`ModuleManager` singleton). Each module is a subfolder with its own `models.py`; `modules/models.py` re-exports for Django discovery.
- **Module capabilities** — **a module is required to have a name; everything else is opt-in.** `instantiate`/`shutdown` default to no-ops (three of the nine concrete modules are pure tool facades over subsystems the ASGI lifespan already owns). Opt-in surface: `is_available`, `worker_cron`, `return_tools`, `get_capabilities`, `get_context`, `get_routes`, `get_views`, `config_schema`, `get_models`, `on_event`, `get_status`.
- **`deliver()` is not a module capability.** It lived on `BaseModule` returning `False` and no module ever implemented it — the sole implementer is `TelegramChannel`, which is not a module. It is now the `Deliverable` protocol in [communication/delivery.py](backend/communication/delivery.py), duck-typed via `can_deliver()`.
- **AI tools**: `ModuleManager` collects tools from all modules, builds an MCP server via `create_sdk_mcp_server()`, injected into `ClaudeAgentOptions.mcp_servers` when `complete_with_tools` is used.
- **How many tools a conversation carries is configurable** (`ai.conversation_tool_modules`, Configuration → *IA · Outils*). Empty = every running module: right behind a hosted API, wrong behind a local one, since a tool declaration is *prompt* re-sent on every turn of the tool loop — the nine shipped modules weigh **~6 500 tokens against a ~1 500-token system prompt**. Measured on `gemma4:12b`, a greeting cost 76 s against a 60 s timeout; narrowing the list and raising `ai.call_timeout_seconds` (default now **120 s**) brought it to 14,6 s. The excluded modules' tools stay usable everywhere else — conscience, projects, background ticks; only the conversation is lightened.
- **`ModuleManager` is a façade, not the subsystem.** ~200 lines of one-line delegations (a method growing a second line belongs in a collaborator):
  - [modules/registry.py](backend/modules/registry.py) — who exists, who is active, what `ModuleState` says. Absorbs `config_schema()` **before** the availability check (the point of surfacing a schema is to configure a module that can't run yet).
  - [modules/lifecycle.py](backend/modules/lifecycle.py) — start/stop/enable/disable/uninstall, table install, and the **only** place a module is attached to or detached from the bus. A module whose `instantiate()` raised is never subscribed.
  - [modules/scheduler.py](backend/modules/scheduler.py) — `CronScheduler`, 1s tick, per-module `CRON_INTERVAL` or `modules.cron_tick_interval`. Ticks run **detached** (awaiting inline made the scheduler as slow as its slowest module, forever on a hung socket). One tick per module at a time; an overlap is **skipped, not queued**. `stop()` reaps in-flight ticks.
  - [modules/collectors.py](backend/modules/collectors.py) — tools / capabilities / prompt context / routes / views, plus the tool cache (invalidated by the lifecycle via an `on_change` callback) and `is_owner()`, the per-person visibility rule for `get_context()`.
  - [modules/notify.py](backend/modules/notify.py) — the notify_ai bridge.
- **Event bus** ([utils/eventbus.py](backend/utils/eventbus.py)) — a real registry, replacing an `emit_event` that named two of its three consumers in its own source:
  - Lives in `utils/` with **zero dependencies** and never imports `modules`: a subscriber only needs an event carrying `event_type` + `source_module` (structural `Event` Protocol — `ModuleEvent` satisfies it).
  - **Patterns**: `*`, `email.*` (namespace prefix), or exact. Trailing star only, deliberately.
  - **Reserved internal namespace** — an event type starting with `_` is engine plumbing and a wildcard does **not** reach it; it must be named explicitly. Wildcard subscribers are the norm here (the conscience subscribes `*`, the Forge relays `*` to sandboxed modules), so without the reserve one lifecycle signal would file an Observation, burn an interpretation LLM call and wake every forged module once per turn.
  - **Two delivery modes**: `AWAIT` (emitter waits — correct when ordering is observable) and `SPAWN` (detached). Modules declare theirs via `EVENT_PATTERN` / `EVENT_MODE` / `EVENT_PRIORITY` / `EVENT_TIMEOUT` on `BaseModule`.
  - **Priority bands** — `PRIORITY_OBSERVER` (10) / `DEFAULT` (50) / `LATE` (90).
  - **A subscriber never receives its own events** (`receive_own=False`). The Forge depends on this: it fans an event out to sibling forged modules itself, excluding the emitter.
  - **Failures are counted, not swallowed.** One broken subscriber never stops the fan-out and `emit()` never raises, but `event_bus.stats()` reports per-subscriber `delivered` / `failed` / `last_error`. `timeout=` bounds an AWAIT subscriber.
  - **Duplicate name replaces** rather than raising or appending (a hot-reloaded forged module re-subscribes under the same name).
  - Core subsystems **declare their own interest**: `ConscienceEngine.initialize()` subscribes `observe` (and `shutdown()` unsubscribes), `projects/apps.py::ready()` subscribes the `event:<type>` waker. `module_manager.set_conscience()` survives as a one-line shim for ASGI startup.
- **notify_ai vs emit_event** — `emit_event` = "this happened": fan-out, no reply, nobody obliged to care. `notify_ai` = "answer this": one `INTERNAL_TRIGGER` Perception through the full pipeline, returning what she said. Modules reach the latter through the injected callback so they never import the pipeline.
- **Email module** ([modules/email/](backend/modules/email/)): IMAP/SMTP. Polls inbox (60s), triages with Haiku, stores `ProcessedEmail`, creates souvenirs/connaissances, notifies via `notify_ai`. Exposes `list_recent_emails`, `send_email` tools. Disabled gracefully if no config.
- **Forge** ([modules/plugins/forge/](backend/modules/plugins/forge/)): AI-self-managed modules. One host plugin (`forge`) loads N sandboxed mini-modules that **Mika writes herself** into `data/forge_modules/` (`FORGE_DIR`). See dedicated section below.

### Admin interface — access control and payload safety

The dashboard reads the entire conversation history and writes the config, including provider API keys. Three layers stand between that and the network:

- **`ALLOWED_HOSTS` is not wildcarded** — `*` disables Host-header validation, which is what stops `Host: evil.test` from making the app generate absolute URLs pointing at an attacker's domain. Defaults to the loopback names actually served, plus the machine's own hostname/IP when `API_HOST` is not loopback; override with `ALLOWED_HOSTS` in `.env` behind a reverse proxy.
- **Loopback by default** — `API_HOST` defaults to `127.0.0.1`. Set `API_HOST=0.0.0.0` to serve the LAN; [run.py](run.py) then logs a `SECURITY:` warning if `DASHBOARD_REQUIRE_AUTH` is off.
- **Optional auth gate** — [GestionSysteme/middleware.py](backend/GestionSysteme/middleware.py) `GestionAuthMiddleware` covers the whole `/gestion/` prefix when `DASHBOARD_REQUIRE_AUTH=1`: HTML redirects to `LOGIN_URL` (default `/admin/login/`) with `?next=`, API requests get 401 JSON. Staff-only, so a chat-frontend account doesn't inherit the config editor. **Off by default** — a fresh install has no superuser, and locking the owner out before `createsuperuser` is worse than loopback exposure. One middleware rather than 66 decorators.
- **CORS is not wildcarded** — `CORS_ALLOW_ALL_ORIGINS` defaults to `False` with the dev frontend origins allow-listed. It previously followed `DEBUG`, so any visited page could read the history and rewrite the config cross-origin.

**Payload sanitization** ([utils/sanitize.py](backend/utils/sanitize.py)) — the old dashboard renderer injected `html` keys via `innerHTML`, so `sanitize_payload` strips `html`/`js`/`template` recursively from a module's payload. GestionSystème removed that path rather than filtering it (typed cells, no key reaches markup), so the sole live caller is the Forge, which re-exports the shared implementation as defence in depth over payloads the AI writes at runtime. **There is no opt-out**: the `ModuleView.allow_raw_html` derogation went with the `dashboard` app, and a panel that owns its own markup declares a `Template` block instead.

**Access accounts are editable from the dashboard** ([GestionSysteme/config_schema.py](backend/GestionSysteme/config_schema.py) + [config_backend.py](backend/GestionSysteme/config_backend.py)) — Configuration → *Accès · Comptes* (`order=10`, first: it decides who reads every other section). A `record_list` whose backend is Django's `User` table, so nothing lands in `ConfigRecordItem` and the dashboard never becomes a second source of truth about who may log in. Three rules the generic backend can't express: a **password is never read back** (reads report presence only; writes go through the same `validate_password` as bootstrap); **no lockout** — deleting, deactivating and demoting the last active admin are all refused, compared *before vs after* rather than "after ≥ 1" so a DB with no admin yet isn't frozen; and refusals are **loud** (4xx, French message). `person_id` (`user_<pk>`) is surfaced `readonly`. The section is only as protected as the dashboard itself. Tests: `test_comptes_acces.py` (34).

**Config write path** — record-list rows go through the same `_coerce` + `_validate` as scalar items, row CRUD invalidates the cache before notifying subscribers, `registry.register_replace()` invalidates each replaced key, and `config_service.set()` on a blank sensitive field returns a **redacted** marker rather than the decrypted current secret.

**CSRF is enforced.** `CsrfViewMiddleware` is installed, **no endpoint is `@csrf_exempt`** (24 decorators removed — a middleware every view opts out of protects nothing), and a test asserts the string never comes back. It matters because sessions gained authority: with a logged-in owner session, a forged POST to the configuration form rewrites provider API keys.

- Token plumbing: `/auth/whoami` carries `@ensure_csrf_cookie` (the client's *first* call) and the SPA reads it in `postJson()`. GestionSystème needs none of that: every write is a server-rendered form carrying `{% csrf_token %}`.
- `CSRF_TRUSTED_ORIGINS` mirrors `CORS_ALLOWED_ORIGINS`; `CSRF_COOKIE_HTTPONLY=False` because the SPA must read the token. The cookie is not the secret — the *matching pair* is what a cross-site page cannot produce.
- Tests use `Client(enforce_csrf_checks=True)`: the default test client disables CSRF entirely.

**WebSocket origin validation** — `OriginValidator` wraps the socket stack ([config/asgi.py](backend/config/asgi.py)), allow-listed against the same CORS origins. Necessary because **CORS does not apply to WebSockets**: any visited page could open `ws://…/ws` and the browser would attach the session cookie. A missing `Origin` header is rejected.

### GestionSystème — the server-rendered admin ([GestionSysteme/](backend/GestionSysteme/))

Mounted at `/gestion/`. Replaces the `dashboard` app, **now deleted** (along with `ModuleView` — both shipped modules declare panels). The old dashboard assembled every page in the browser by string concatenation: 125 `innerHTML` against 28 DOM-API uses and 260 hand-written `escapeHTML` calls, across 4 284 untyped JS lines with no tests. [utils/sanitize.py](backend/utils/sanitize.py) exists solely to compensate for that rendering choice.

- **Rendering is Django templates.** Autoescaping is on and there is nothing left to sanitize.
- **Writes are forms + POST + redirect.** No `fetch` to sign; `{% csrf_token %}` does it.
- **URL is the state.** Tab, page, filters and sort live in the address — shareable, bookmarkable, back-button-correct.
- **9 destinations instead of 23.** The old menu mirrored the DB schema; the seven memory views are seven tabs. A test caps top-level entries.
- **One JSON endpoint** (`/gestion/api/vitaux`), feeding only the top bar. `gestion.js` is ~120 lines of progressive enhancement (theme toggle, confirm dialogs, filter auto-submit, vitals refresh) and renders nothing — a test asserts `innerHTML` never reappears in it.

**Layout**: `nav.py` (menu + tabs spec), `shell.py` (page context, badge counts, vitals — every read isolated, since this is the screen you open *because* something is broken), `tables.py` (pagination/filters; cell markup stays in the page template), `forms.py` (ConfigItem → HTML and back), `panels.py` (module spaces), `formatting.py` + `templatetags/gestion.py` (text only, never markup).

**Configuration is three spaces.** *Fixed* (`/gestion/configuration/`) holds the core sections, grouped Accès / IA / Communication / Cœur. *Dynamic* lives in each module's own space, *forged* in each app's own space. `core_sections()` draws the line by excluding the `module_` and `forge_` prefixes; old section URLs redirect rather than 404. Nothing in the view knows any module — the registry describes the fields and the same form engine renders them, so a new `ConfigItem` appears with no code change. Secrets **never reach the browser**: the field ships empty, blank means unchanged. A `__champ` marker per rendered field distinguishes an unchecked box (absent from POST but on screen → save `False`) from a setting simply not in the form (don't touch).

**Projects are the one thing you *create* here** ([project_forms.py](backend/GestionSysteme/project_forms.py)) — plain Django `ModelForm`s, deliberately **not** the `ConfigItem` engine (a project is a real ORM model with relations, choices and JSON fields). Three rules the form adds: an **invalid schedule rule is refused** (`schedule.parse_rule` never raises — right for LLM-supplied text, but from a form `interval:5min` would silently mean "manual" forever); `allowed_modules` is a **closed multi-select** of registered modules (a typo quietly *closes* access); and `next_run_at` is **recomputed on every save**. List fields (`instructions`, `keywords`, …) are one-value-per-line textareas. Tasks are added from the project fiche, with the task id checked against its project.

**Dynamic choices** ([choices.py](backend/GestionSysteme/choices.py)) — a field whose options depend on *another field* plus a network call, which the registry cannot express. A `DynamicField` names the driving field and a loader; `ai.models`/`model_id` is driven by `provider` and dispatches to the provider's own `list_models()`. Three properties: **loading is explicit** (a button, not every page render), it is a **plain server round-trip** carrying the in-progress input in the POST (no JS, and `__charger` never writes a row), and the field **stays typeable when loading fails** — an unreachable provider is exactly when you come to repair the config. A current value missing from the loaded list is re-injected as an option.

**Module spaces.** Each module owns `/gestion/modules/<name>/`: state, lifecycle, configuration and panels under one sub-nav, present as soon as the module is **registered** (not only while running — the settings of a broken module must stay reachable).

`ModulePanel` handlers return **typed blocks** (`Table` / `Fields` / `Stats` / `Note` / `Prose` / `Template`) built from **typed cells** (`text`/`badge`/`emotion`/`meter`/`link`/`mono`/`num`/`bool`). A module declares an *intent*; it never emits markup, so the stored-XSS class is **removed rather than filtered**. A `Table` carries its own `FilterSet` (URL-driven filters + pagination for free). `Template` is the honest escape hatch: the module ships its own Django template, still autoescaped. Handlers may be sync or async. Legacy `get_views()` modules are adapted automatically (`_adapt_legacy_view`), including 0-based → 1-based page conversion.

**The email module is the reference implementation** ([modules/plugins/email/panels.py](backend/modules/plugins/email/panels.py)). It keeps `get_views()` and adds `get_panels()`; `panels_for()` prefers native panels. Three things the old views could not do: an **account selector** (hidden below two accounts; it also drives the contacts list, whose `accounts` is M2M), a **detail-as-URL** (`?message=<id>` — shareable, and back closes the fiche keeping the filters), and **no duplicate "Comptes" panel** (accounts are edited in the space's Configuration tab, writing the same `EmailAccount` table). `body_html` is deliberately never rendered, in any form.

**Theme** ([static/gestion/css/](backend/GestionSysteme/static/gestion/css/)): four files, strict split — `tokens.css` is the only place a literal colour appears. Sober: system sans-serif (the content is long French prose), light **and** dark via `prefers-color-scheme` plus a `data-theme` override that wins both ways, no glow, no grid. The 29 emotion colours are desaturated (they only ever appear as an 8px dot). No module-specific CSS in the core.

**Form fields align by row, not by field.** A `.form-grid` field has three tracks — label, description, control — and the *row* carries their heights (`grid-template-rows: subgrid`, `grid-row: span 3`), because descriptions have different heights (none, one line, two). Both field templates (`partials/field.html` for a registry `ConfigItem`, `partials/django_field.html` for a `ModelForm` field) emit all three slots **always**, description included when empty — a missing slot shifts the control one track up. A checkbox occupies the *label* track (`.check-row`). `@supports not (grid-template-rows: subgrid)` falls back to pushing the control to the bottom of the field.

**Emotion names are stored in English and displayed in French.** The canonical `emotion/types.py` value is what the model emits, what the DB keeps, and what composes `--emo-<name>` — so it cannot be translated at the source. It is translated at the single point of render, `formatting.emotion_fr` (`|emo_fr` in templates, applied by `panels.emotion()` for every module panel at once). The colour deliberately stays on the canonical name in the same `<span>` (`var(--emo-curieuse)` does not exist). A test asserts the table covers *exactly* the 29 emotions.

**Temperament is a dashboard setting, not a YAML block** (Configuration → Émotion → Tempérament). The five values — `default_mood`, `volatility`, `intensity_base`, `recovery_speed`, `global_bleed` — are values you try while watching the mood move, so all five are `hot_reload`, and `EmotionEngine._reload_temperament` re-runs `_recompute_params()` because the loop reads the derived `OscillatorParams`, not the dataclass. The YAML block was **removed**, not kept as a fallback (two declared defaults for one knob is the mistake the `env_fallback` bridge cost to clean up). `personality.temperament` delegates to `emotion.state.load_temperament()`, which never raises — a config read can precede a reachable database. Registry defaults reproduce the old YAML values exactly, pinned by a test.

`ConfigItem.choices` accordingly accepts either a bare value or a `(value, label)` pair (`configs/types.py::choice_values` / `choice_options`) — the mood select stores `mischievous` and shows `malicieuse`. Validation compares against the values, rendering against the pairs.

**The person fiche is tabbed** (`/gestion/social/personnes/<id>/<tab>/` — Synthèse / Souvenirs / Connaissances / Échanges / Affect / Engagements, declared in `nav.py::PERSON_TABS`). The fallback rule for an unknown tab segment is `nav.resolve_tab()`, shared with the menu tabs. Three things the split made visible:
- **The live affect panel could never display anything.** It read `emotion_engine.person_moods[str(entity_id)]`, but that dict is keyed by *transport handle* (`web_…`) — the entity's primary key matches no key, ever. Now one oscillator card per handle, resolved through the identity layer.
- **An empty tab is not the same fact as an unresolvable one.** Messages, snapshots and moods are stored by handle; with no `Identity` bound there is nothing to join on, and a blank table reads as "they never spoke". Those tabs say so and name the missing link — including the homonym hint ("a handle by this name exists, carries N messages, is bound to nothing") **without** using name equality to resolve, since that equality is the bug the identity layer replaces.
- **Disclosure is stated on the fiche.** Below `PRIVATE_CONTEXT_THRESHOLD` none of the profile reaches the prompt, so a complete fiche and a never-read one looked identical.

**The identity fiche is tabbed the same way** (`/gestion/social/identites/<id>/<tab>/` — Verdict / Handles / Échanges / Preuves / Actions, `nav.py::IDENTITY_TABS`). The two fiches are two sides of one question and link to each other: the person fiche starts from the memory Entity, this one from the handle.
- **The verdict shows the arithmetic that produced it** — stored value → channel floor → channel ceiling → threshold, served from `identity/trust.py` rather than transcribed. It states when the ceiling *bites* and when the floor *raises*.
- **The evidence ledger** is its own tab, filterable by status and kind, with pending claims resolvable inline (it was silently truncated at 100 rows with no filter).
- **The `handles` tab shows each handle's floor/ceiling and message volume**, making `_best_handle`'s rule legible: the *primary* handle is the one with the highest channel ceiling, not the most recent.
- **`retour` was an open redirect.** Both write endpoints took it straight from POST into `redirect()`. Now validated with `url_has_allowed_host_and_scheme` against the request's own host.

Two rendering traps, both guarded by tests:
- **`{# … #}` is single-line only.** Django's lexer regex has no `re.DOTALL`, so a multi-line `{#` isn't a comment: the text renders and any `{% tag %}` quoted inside is *compiled for real*. Multi-line comments must be `{% comment %}`.
- **`position: sticky` scopes to the nearest scroll container.** `.table-scroll` carries `overflow-x: auto`, which forces `overflow-y: auto` too, so a sticky `<thead>` rendered 52px down inside the table. Table headers are deliberately not sticky; lists are paginated to 25 rows.

Tests: `test_gestion_systeme.py` (165) — every nav destination and tab derived from `nav.py` / `PERSON_TABS` / `IDENTITY_TABS`, the entity↔handle bridge end-to-end, live affect keyed on the handle, the homonym hint named but never used to resolve, the `handle` filter constrained to *this* person's handles, the floor/ceiling verdict branches, the primary handle chosen by ceiling, `/action/` not swallowed by `<slug:tab>`, the open-redirect guard, an orphan identity browsable with writes refused loudly, config sections and record-list forms, pagination elision and clamping, closed-list guards on every URL value reaching the ORM, `emotion_var` refusing anything outside the 29 names, secrets absent from rendered HTML, checkbox-marker semantics, a legacy `html` payload rendering nothing, a raising panel degrading to an error block, module spaces surviving a stopped module, the dynamic-choice loader, the email account selector, a hostile email body escaped end-to-end, the auth gate's four cases, and the two traps above. ### Identity screen ([GestionSysteme/views/social.py](backend/GestionSysteme/views/social.py))

`/gestion/social/identites/` — the handle side of "who is this person". The person fiche answers *what does Mika know about Thomas*; this answers *is the person speaking actually Thomas, how sure is she, and what does that unlock*. It sits **before** "Personnes" in the Social tabs, mirroring the prompt.

- **The column that matters is "Divulgation"**, not the certainty number: below `PRIVATE_CONTEXT_THRESHOLD` the person fiche is not injected at all. Measured on the dev DB when the page landed: 9 durable identities, **0 bound, 0 clearing the bar**.

### Forge — AI-self-managed modules ([modules/plugins/forge/](backend/modules/plugins/forge/))

Confined space where **Mika creates/edits/tests/deletes her own mini-modules** at runtime (hot reload, no restart). Full doc: [modules/plugins/forge/README.md](backend/modules/plugins/forge/README.md).

- **Layout**: each forged module lives in `data/forge_modules/<slug>/` — `manifest.yaml` (title, `schedule`, `events` patterns, `views`, `config` fields, `allowed_domains`, `context`) + `module.py` (sandboxed code) + `state.json` (host-managed: enabled, disabled_reason) + `_versions/` (auto-snapshots, rollback); erased modules go to `_trash/`.
- **Sandbox** ([sandbox.py](backend/modules/plugins/forge/sandbox.py)): AST validation at write time (no `import`, no async, no `_`-prefixed attribute access, no `eval/exec/open/getattr/type/...`, no `.format`), curated builtins + read-only safe modules (`math json re datetime random statistics collections itertools functools hashlib base64 uuid copy string`) at exec time, per-handler deadline via `sys.settrace` in a dedicated 2-worker thread pool. Handlers are sync; the host wraps them async.
  - **Two escapes closed**, both verified exploitable: *frame walk* — `f_* / gi_* / cr_* / ag_* / tb_*` attributes are not `_`-prefixed, so `gen.gi_frame.f_back` climbed into host frames whose `f_builtins` holds the real `__import__` → RCE; those prefixes are now `FORBIDDEN_ATTR_PREFIXES`. *Catchable deadline* — `ForgeTimeout` derived from `Exception`, so `while True: try: … except Exception: pass` swallowed its own timeout and pinned a worker forever; it now derives from `BaseException`, and the validator rejects bare `except:` plus references to `BaseException`/`ForgeTimeout`/`SystemExit`/`KeyboardInterrupt`/`GeneratorExit`.
  - Hot reload calls `_unregister_config()` before re-registering (`register_replace` can only add/replace, so a dropped config field lingered until restart). `_trash/` capped at `MAX_TRASH_KEPT = 20`. `ForgeLog` pruning amortized every 50 inserts per module.
- **Capability API** ([api.py](backend/modules/plugins/forge/api.py)): `api.storage` (per-module JSON KV by collections in the shared `ForgeRecord` table, quotas — forged modules never get DDL), `api.config` (reads `forge.<module>.<key>` from the standard config service, dashboard-edited, secrets decrypted, `record_list` supported), `api.log/warn/error` + `print` → `ForgeLog`, `api.notify_ai` (rate-limited by `forge.notify_cooldown_s`), `api.emit` → `forge.<module>.<type>` on the bus, `api.http_get` (manifest `allowed_domains` only, redirects off, private/loopback IPs blocked, size-capped), `api.state` (RAM dict).
- **Circuit breaker**: `forge.max_consecutive_failures` (5) tick/event failures → module auto-disabled (persisted in `state.json`), unloaded, Mika notified once with the error so she can `forge_read_module` → fix → `forge_command(enable)`.
- **Dynamic config**: the host registers a `ConfigSection` "Forge · <title>" + items via `registry.register_replace()` (`registry.unregister()` on erase only). Registered **from the manifest, before any load**, so a disabled or broken app keeps editable settings — without a registered section `config_service.set` refuses the key and the form would render but write nothing. Values persist in `ConfigValue` across reload/disable.
- **Views**: each app's declared-and-implemented views become panels of *its own* space (`panels_for_app`), not of the host's. Payloads go through typed cells — `html`/`js`/`template` keys are never read.
- **MCP tools** (in every tools-enabled conversation): `forge_list_modules`, `forge_read_module`, `forge_write_module` (create/update: manifest merge + AST validation + version archive + hot reload; on failure the old version keeps running), `forge_command` (`enable|disable|reload|rollback|erase|reset_storage`), `forge_test_module` (run any handler NOW, returns result + logs — the iteration loop), `forge_read_logs`.
- **HTTP routes**: `GET /api/modules/forge/`, `POST /api/modules/forge/command`, `GET /api/modules/forge/source?name=`, `GET /api/modules/forge/logs`.
- **Two screens, deliberately** ([GestionSysteme/views/forge.py](backend/GestionSysteme/views/forge.py)): the *workshop* at `/gestion/modules/forge/` (all apps at a glance, filterable journal, storage by collection, reload-all) and the *apps* at `/gestion/forge/` — a menu entry **"Forge apps" immediately below "Forge"**, the only sidebar entry in the Espaces group that is not a module (apps are written at runtime, so no destination can be declared per app in `nav.py`). One space per app (`/gestion/forge/<app>/`) carrying state, source, journal, commands, configuration and pages. The per-app fiche and its commands **moved** there from the workshop's `?module=…` query string: a destructive button should not depend on an invisible parameter. The sidebar iterates `shell.sidebar_spaces()` (uniform `SpaceLink`s), so no template knows a module name.
- **Scheduling** reuses [projects/schedule.py](backend/projects/schedule.py) (`interval:`/`cron:`/`idle:`/`manual`); event-driven wake-up goes through manifest `events`, not `schedule`.
- Models `ForgeRecord`/`ForgeLog` are shared host tables (migration `modules/0010`); threat model is accident-prevention + prompt-injection hardening, not OS-grade isolation (in-process execution).

### Conscience Layer ([conscience/](backend/conscience/))

Mika's **waking brain** — a layer above modules that observes, interprets, memorizes, and decides. Django app at the same level as `ai/`, `memory/`, `emotion/`, `drives/`. **Metaphor**: Conscience = waking state, Consolidator = dreaming state.

- **Engine** [conscience/engine.py](backend/conscience/engine.py) — `ConscienceEngine` singleton: decision loop (every `CONSCIENCE_DECISION_INTERVAL`s), memory maintenance, action execution. `_act()` builds an `INTERNAL_TRIGGER` Perception and routes it through the processor (never calls `process_message` directly). It subscribes `observe` to the bus at `initialize()` (`PRIORITY_OBSERVER`, AWAIT — she files her `Observation` before any module reacts, and downstream code reads that row) and unsubscribes at `shutdown()`. The high-pertinence fast-path (`p > 0.85`) is **scheduled**, not awaited (`_spawn_decision()`): `observe()` runs on the emitter's await chain, so an inline decision blocked the emitting module's loop for two LLM calls. Tasks are held in a set so they aren't GC'd mid-flight.
- **Scoring** [conscience/scoring.py](backend/conscience/scoring.py) — pure functions. **11 weighted factors**: pertinence, accumulated urgency, mood overflow, idle time, time greeting, scheduled actions, pressure (consecutive waits), ignored-acts penalty, **drives** (signed: REST subtracts), **rumination pressure**, **fatigue penalty** (energy < 0.5 subtracts up to 0.25). Threshold: `CONSCIENCE_ACT_THRESHOLD` (0.5).
- **Interpreter** [conscience/interpreter.py](backend/conscience/interpreter.py) — `SignalInterpreter` classifies events. **Every event outside the fast-path costs a Haiku call**, in series inside the emitting module's tick (the subscription is AWAIT for the ordering guarantee downstream relies on). The fast-path therefore covers everything high-volume: `chat.*`, `telegram.message`, `rss.new_entry`, and any `forge.*` prefix (`heuristic_for()` matches exact types then prefixes) — before it, a first poll of 5 RSS feeds meant ~75 sequential LLM calls with the scheduler frozen. RSS pertinence is scored from theme keyword matches; forged-module events are low-pertinence by default (a forged module wanting attention uses `api.notify_ai`). `email.received` deliberately still goes through the LLM.
- **MemoryBridge** [conscience/memory_bridge.py](backend/conscience/memory_bridge.py) — R/W interface to long-term memory: create souvenirs, boost importance, check/invalidate connaissances, recall for context.
- **conscience_tools** [conscience/module.py](backend/conscience/module.py) — SYSTEM module (registered in `conscience/apps.py`) exposing the `ScheduledAction` lifecycle: `schedule_action`, `list_scheduled_actions`, `cancel_scheduled_action`, plus the prompt line counting what is pending. They used to live in the `wake` plugin, which owns none of it: stopping that accessory removed Mika's ability to schedule, list and cancel a deferred action **while the conscience kept scoring and executing the ones already stored**. Half the lifecycle vanished, the other half carried on, and nothing said so. `_pick_relevant_modules()` therefore loads `conscience_tools` alongside `wake`.
- **Models** [conscience/models.py](backend/conscience/models.py):
  - `Observation` — interpreted signal buffer with state machine (`pending`/`acted`/`skipped`/`failed`)
  - `ConscienceLog` — decision audit trail
  - `ScheduledAction` — deferred actions (`schedule_action` tool)
  - `Rumination` — persistent unresolved thoughts (promoted from stale pertinent Observations). Each cycle: decays 5%, bleeds emotional charge into global mood, halved when Mika acts. States: `active`/`resolved`/`faded`.

**Greeting state is committed only on "act"** — `check_time_trigger` marks a period greeted inside the scoring pass, but the greeting factor is worth 0.35 against a 0.5 threshold, so committing immediately spent the day's greeting on a cycle that stayed silent. `_compute_score()` stashes the tentative state and `_commit_greeting()` persists it from the `act` branch only.

**Memory powers**: the Conscience reshapes memory without speaking — boost souvenir importance for pertinent signals, invalidate contradicted connaissances, promote stale pertinent observations to Ruminations, decay ruminations over time.

### Emotion + Drives + Rumination (the "inner life")

Three complementary systems feed the conscience scoring and the system prompt:

- **Emotion** (`emotion/`): physics-based affective state. Two separate prompt blocks — `emotion_context` = Mika's **global mood** only + drives descriptions; `person_context` = her **affective stance toward the current person** (`get_person_affect_context`), alongside her semantic profile and pending commitments.
- **Drives** (`drives/`): intrinsic motivational tensions (CURIOSITY, SOCIAL, EXPRESSION, REST). Grow with time, assuaged by actions. Contribute signed to the conscience score (REST subtracts). Inject a French description into the prompt.
- **Rumination** (`conscience/models.py::Rumination`): short-term persistent thoughts — signals that were pertinent but unactioned. Decay, bleed emotion into global mood, and can push the conscience to eventually speak up.

### Identity & trust ([identity/](backend/identity/))

Who Mika is talking to, **how sure she is**, and what that certainty allows her to say. Everything per-person downstream — theory of mind, commitments, emotional history, concern-based routing — resolves through this layer.

**The bug it replaces**: `Identity.entity` was never populated, and per-person memory was looked up with `PersonProfile.filter(entity__name=person_id)`. That only matches when a person's memory Entity happens to be named after their transport handle, which never happens (the consolidator names entities "Thomas" while handles are `web_6f3e22ccb0ae`). The whole theory-of-mind layer returned `""` on every turn, silently.

**Two orthogonal notions** ([identity/trust.py](backend/identity/trust.py), pure functions, no DB):

- **`ChannelTrust`** — what the *transport* proves. `AUTHENTICATED` (verified Django session) > `ACCOUNT` (stable platform id: a Telegram DM proves the same account came back, not who holds it) > `PUBLIC` (group chat, unknown transport) > `INTERNAL` (not a person). Each grants a **floor** and imposes a **ceiling**.
- **`Certainty`** — how sure she is that *this handle is that person*: `UNKNOWN` 0.0 → `SUSPECTED` 0.25 → `CLAIMED` 0.45 → `CORROBORATED` 0.70 → `BOUND` 0.85 → `VERIFIED` 1.0. Moves with evidence, clamped by the channel ceiling. **No amount of talking makes a public-room claim as good as a login.**

**Three ways an identity gets established:**

1. **Authenticated** — `bind_authenticated()` on connect. The memory Entity is created eagerly under the account's display name so profile/commitments resolve from the first turn.
2. **Passive** — [identity/detection.py](backend/identity/detection.py) reads "moi c'est Thomas" off an ordinary turn (pure regex, no LLM: it runs on *every* inbound message). Files an `IdentityClaim` as `PENDING` and **binds nothing**. `_NOT_NAMES` rejects states and roles ("je suis fatigué", "je suis développeur"), and a greedy two-word capture falls back to one word so "je ne suis pas Thomas en fait" still reads as a denial.
3. **Active** — Mika's own MCP tools. Accepting a claim is what actually binds the handle to an Entity.

**Se laisser convaincre** — on a channel with no login, recognition is earned. `EVIDENCE_WEIGHTS` is calibrated against the disclosure bar (0.70): `self_declared` 0.20 alone never clears it, `shared_memory` 0.50 alone never clears it (knowing a fact about Thomas doesn't make you Thomas), but **claim + corroboration lands exactly on it**. `corroboration_score()` measures lexical overlap between what was just said and what memory holds about the claimed person (≥3 distinct content words). Counter-evidence subtracts: `contradicted` −0.35, `denied` −0.50, `revoked` −1.0.

**Disclosure gating** — `may_disclose_private_context()` decides whether per-person memory reaches the prompt at all: authenticated → always; account channel → needs `CORROBORATED`; **public room → never, at any certainty** (the risk in a group isn't mistaken identity, it's the audience — she can greet someone warmly, she just doesn't read out their file). `_fetch_person_context()` returns only the affective stance below the bar — her own feeling toward the handle is hers, the other person's history is not.

**Denial applies immediately**, without waiting for deliberation: if she's calling a stranger by a friend's name, everything downstream is already wrong. It unbinds when it targets the current binding.

- **Models** ([identity/models.py](backend/identity/models.py)): `Identity` (+`certainty`, `bound_at`, `bound_via`, `binding_reason`), `IdentityHandle` (+`trust`, `is_ephemeral`), `IdentityClaim` (audit ledger: every reason to believe or stop believing, with what it was worth). Migrations `identity/0002`, `identity/0003`.
- **MCP tools** ([identity/module.py](backend/identity/module.py), registered via `identity/apps.py`): `identity_whoami_with`, `identity_check_story`, `identity_accept_claim`, `identity_reject_claim`, `identity_record_evidence`, `identity_forget_binding`. The current person is ambient via a ContextVar ([pipeline/tracing.py](backend/pipeline/tracing.py)).
- **Prompt**: `--- QUI TU AS EN FACE ---` sits immediately before `--- CE QUE TU SAIS DE CETTE PERSONNE ---`, because it qualifies it. Never prints a number — prompt text reads as a feeling, or the model starts quoting percentages back at the user.
- **Consolidator**: souvenirs are linked to the *interlocutor's* entity, not only to entities the extractor happened to name.
- **Retention**: ephemeral `anon_*` handles expire after 7 days, orphan `Identity` rows are swept, resolved claims kept 180 days (pending ones protected).

**One definition of "is this a person?"** — `identity/trust.py` owns `INTERNAL_PERSON_IDS`, `is_internal_person()`, `is_ephemeral_person()` (`anon_*`) and `is_identifiable_person()`. The rule used to be stated in three places and had already drifted (only one excluded `anon_*`).

**Frontend is authenticated** — `CONSUMER_REQUIRE_AUTH` defaults to `True`; the WebSocket refuses anonymous connections. Three pieces have to line up, each silently breaking the whole app on its own:
1. **`AuthMiddlewareStack`** on the WebSocket router ([config/asgi.py](backend/config/asgi.py)) — it populates `scope["user"]`. Without it the key is *absent*, so every connection is refused with 4401.
2. **`CORS_ALLOW_CREDENTIALS=True`** — the SPA sends `credentials: "include"`; without `Access-Control-Allow-Credentials: true` the browser discards the response (login failed with "invalid credentials" even when correct).
3. **`@ensure_csrf_cookie` on `/auth/whoami`** — the first call plants the token the subsequent POSTs echo.

Tested through the real ASGI stack (`TestAsgiAuthWiring`), including that a **valid session is accepted** — asserting a door is locked proves nothing about the key. `GET /auth/whoami` reports `auth_required` + `needs_bootstrap`; `POST /auth/bootstrap` creates the **first** account (409 forever after). `AUTH_PASSWORD_VALIDATORS` is configured — without it `validate_password` was a no-op.

### Self-concept and theory of mind

Two layers built on the memory system, regenerated during consolidation:

- **Self-narrative** (`memory/narrative.py` → `SelfNarrative`): first-person paragraph "Je suis quelqu'un qui…" synthesized from recent souvenirs + connaissances + emotional summary. Every ~24h if ≥5 new souvenirs. Injected between personality and person-context.
- **Person profile** (`memory/person_profile.py` → `PersonProfile` + `Commitment`): per-person model — summary, closeness (stranger/acquaintance/friend/close), preferred tone, topics of interest, sensitive topics, pending commitments. Regenerated per active person (seen in last 14 days, ≥3 new souvenirs, ≥24h since last).

Commitments are a 3rd type of extraction produced by the same consolidator LLM call.

### Sleep Cycle ([memory/sleep.py](backend/memory/sleep.py))

Counterpart to the Conscience. The consolidator runs all day doing maintenance; the Sleep Cycle runs **only at night** doing creative, narrative and healing work the reactive pipeline cannot.

**Triple gate** — all must pass:
1. Current hour ∈ [23h, 6h) (`_is_night()`)
2. `conscience.get_idle_seconds() ≥ 900` (15 min) — always applies: an interaction wakes her mid-night
3. `drive_engine.states[REST].tension ≥ 0.5` — **entry only**: once asleep for the night (`_asleep_night` hysteresis) the REST gate is skipped, because each sleeping tick *relieves* REST and draining it must not bounce her awake

**Three phases** (invoked by `run_if_due()` from its **own dedicated loop** started at ASGI lifespan — `memory.sleep_check_interval`, default 60s; decoupled from the consolidator so a 45s sleep LLM call never delays consolidation):

1. **Light sleep** — `_write_journal_if_due()`. One LLM call produces a `DailyJournal` for the date just ended: 1st-person recap (2-4 sentences), key moment ids, dominant emotion, persons interacted, unresolved rumination snapshots. One row per date; re-runs refresh in place.
2. **REM** — `_maybe_dream()`. Picks 2-3 souvenirs of **distinct themes** (greedy anti-duplicate) + optionally one active rumination ≥ 0.3. Classifies: `nightmare` (dominant negative or strong negative rumination), `pleasant`, `associative` (mixed), `mundane` (weak signal). `DREAM_PROBABILITY = 0.6`, `MAX_DREAMS_PER_NIGHT = 2`.
3. **Deep sleep** — `_digest_ruminations()` (03h-06h, once per night). For active ruminations older than 120min: decay ×3, forced emotion drift via `DIGESTION_DRIFT` (`frustrated → relieved`, `anxious → relieved`, `angry → thinking`), intensity ≥ 0.4 → a **reflective Souvenir** ("Après y avoir repensé cette nuit: …"), intensity < 0.15 post-decay → marked `faded`.

**Observable phase state** (`SleepPhase`): `awake | light_sleep | rem | deep_sleep`. Transitions call `_set_phase()`, pushing a `broadcast_inner_state_update` so the frontend reacts immediately. Singleton `sleep_cycle` at module level. A phase is entered **only when it has work to do**, and the tick ends by settling into `DEEP_SLEEP` (announcing LIGHT_SLEEP then REM every tick made the frontend replay its 1.2–1.8s eases twice a minute all night). REM attempts are spaced by `DREAM_ATTEMPT_INTERVAL_S` (45 min).

**Prompt integration** — morning recall (6h-14h): a non-recalled `Dream` with `vividness ≥ 0.6` for last night is injected as `--- CE QUE TU AS REVE CETTE NUIT ---`, then auto-marked `recalled_at`. Framed as "tu peux le mentionner si ça tombe". Yesterday's `DailyJournal` is injected all day as `--- TON FIL D'HIER ---`; any journal is re-readable via `memory_read_journal`. The journal is dated the day it **covers**, so readers query most-recent-of-{today, yesterday}.

**Frontend integration** (end-to-end, live):
- `sleep_phase`, `today_journal`, `last_dream` in every `inner_state` payload
- `AnimationMixer.setSleepPhase()` — eyes close (0.85-1.0), breath × 0.45-0.7, REM flicker, head tilt 0.12-0.25 rad, 1.2s eased transitions
- `Environment.setSleepPhase()` — lights × 0.22-0.55, background tint toward dark blue, 1.8s eased
- `TTSService.requestWakeUpDelay(ms)` — first reply after waking gets 1.3s of silence
- `InnerLifePanel` — "Rêve de cette nuit" + "Journal d'aujourd'hui", sleep badge when not awake

**Debug endpoints** ([communication/debug_views.py](backend/communication/debug_views.py)) — all gated by `settings.DEBUG`:
- `POST /api/dev/sleep/phase {phase}` — force a phase, bypasses gates
- `POST /api/dev/sleep/journal` / `dream` / `digest` — run that LLM call NOW
- `POST /api/dev/sleep/wake` — reset to AWAKE
- `GET  /api/dev/sleep/status` — phase + today's journal + last dream

**Metaphor recap**: Conscience = waking state (observe + act). Consolidator = maintenance bookkeeper. Sleep Cycle = dreaming state — creativity (dreams), narrative coherence (journal), emotional healing (digestion).

### Voice output — a routed modality ([pipeline/voice.py](backend/pipeline/voice.py))

Speech is **not** a frontend detail: text and audio leave Mika through the *same* channels, and whether she speaks is a routing decision made backend-side.

**Presence is per connection, not per person** ([communication/presence.py](backend/communication/presence.py)). The registry is keyed `(person_id, channel)`, but an entry carries the set of live connections backing it, and `unregister(..., connection_id=)` only drops the entry when the last one goes. Without that, the key *was* the bug: two tabs shared one entry, so closing the first erased it and the second went permanently silent (`broadcast_to_websocket` deliberately says nothing when an identifiable person resolves to no target). The single-tab version is worse: `reconnectNow()` opens the replacement socket before the dying one's `disconnect` is dispatched, so the stale unregister killed the new registration — and the client's own liveness watchdog triggers that path. Modules pass no `connection_id` (their reachability is a stored handle, not a socket), so their unregister still evicts outright.

**Delivery registry** ([communication/delivery.py](backend/communication/delivery.py)) — `presence_registry` says *where* a person is reachable; this says *who can send* there. Needed because a communication channel isn't necessarily a module: `TelegramChannel` is never registered with `module_manager`, so `get_module("telegram")` always returned `None` and the caller fell back to a global broadcast (leaking a message composed for one person to every browser). `get_channel(name)` resolves registered channels first, then modules. Targeted messages that cannot be delivered are **logged and dropped**, never broadcast.

**Three sinks**, with genuinely different context rules:

| Sink | Where | Policy |
|------|-------|--------|
| `SCREEN` | frontend app (browser TTS) | speaks by default; silent with no client connected |
| `MESSAGE` | async voice note (Telegram voice, SMS) | time of day is irrelevant — the recipient plays it when they choose. Only an explicit mute suppresses it |
| `SPEAKER` | open-air speaker in a shared room | strictest: silent during quiet hours (22h–8h), while Mika sleeps, and (for addressed speech) when nobody's in the room |

`decide_voice(sink, *, hour, sleep_phase, person_present, muted, persona) -> VoiceDecision(speak, reason)` is a **pure function** — the whole policy is unit-testable without a running system. The reason string is logged and shipped to the frontend so silence is never mysterious.

**Two voice personas** — `VoicePersona.SPEAKING` (addressed to a person) and `VoicePersona.INNER` (thinking out loud). Her inner monologue gets its own vocal identity via `VOICE_PROFILES`: quieter (gain 0.45), slower (rate ×0.9), slightly lower (pitch ×0.94). Two policy consequences: an inner thought is **never** sent as a voice note, and it **may** be spoken to an empty room. `persona_for_source(source, addressed=)` classifies a turn: `INNER_SOURCES = {conscience, drive, rumination}` unless the turn deliberately targets a person.

**Audible inner monologue** ([pipeline/inner_voice.py](backend/pipeline/inner_voice.py)) — when Mika acts on her own she murmurs *"oh tiens, si j'envoyais un message à Alice..."*. That murmur is **generated, not reused**: `generate_inner_thought(action, result, *, mood)` makes a dedicated small-model call (`AIRole.INNER_VOICE`, 12s timeout) from *what she's about to do* + *what just came back*. Output is cleaned (quotes/prefixes stripped) and capped at 160 chars. Every failure path returns `None`: **silence is a valid outcome**, an error is never surfaced as a thought. Wired into `project_runner._murmur()`; broadcast with `source="conscience"` so the INNER persona applies.

**Pluggable synthesis** — `register_synthesizer(synth)` installs a `SpeechSynthesizer` (Piper, edge-tts, an API). **None is registered by default**: the frontend does its own TTS, so `MESSAGE`/`SPEAKER` delivery falls back to text until one is installed. `synthesize()` never raises. Telegram declares `VOICE_SINK = MESSAGE` and implements `deliver_voice()` (OGG/Opus → `send_voice`, anything else → `send_audio`, captioned with the text).

**Frontend contract** — the `speech` payload carries `speak` (bool), `voice_reason`, `voice_persona`, `voice_profile` ({pitch, rate, gain}). [main.ts](frontend/src/main.ts) honours `speak: false` by showing the text and animating without speaking; `TTSService.speak(text, emotion, profile)` applies the persona multipliers **on top of** the emotion modulation, clamped to the Web Speech API ranges.

### System prompt structure

Assembled by `build_system_prompt()` ([pipeline/prompt.py](backend/pipeline/prompt.py)) in this order:

1. **Personality** (static, from `personality.yaml`) — includes a `--- VARIABILITÉ NATURELLE ---` sub-block encouraging variable response length, backchannels ("hmm", "attends"), hesitations, selective echo, non-mandatory relances, and prosodic tokens (`[SIGH]`, `[LAUGH]`, `[PAUSE:ms]`, `[BREATH]`). *Stripped* when an active project has `emotion_policy=OFF`.
2. **`--- QUI TU ES DEVENUE ---`** (self-concept, evolving paragraph)
2bis. **`--- QUI TU AS EN FACE ---`** (identity certainty + pending claims). Qualifies the block below; silent for internal person_ids.
3. **`--- CE QUE TU SAIS DE CETTE PERSONNE ---`** (person profile + affect + weekly trend + commitments). **Gated on identity certainty**: below the disclosure bar only the affective stance is injected.
4. **`--- CE QUE TU PERCOIS DE SON ETAT ---`** (heuristic read of the user's tone: caps, punctuation, lexique, emojis, length — `detect_user_mood_hint` in `pipeline/context.py`)
5. **`--- TON RYTHME ---`** (circadian phase + energy level)
6. **`--- ETAT COGNITIF ---`** (fatigue fog: 4 tiers below energy 0.5 shaping the TONE, not just the act/wait threshold)
7. **`--- CE QUI TE TROTTE DANS LA TETE ---`** (active ruminations, every turn)
8. **`--- CE QUE TU AS REVE CETTE NUIT ---`** (non-recalled dream, vividness ≥ 0.6, 6h-14h only, auto-marked recalled)
8bis. **`--- TON FIL D'HIER ---`** (yesterday's `DailyJournal`, capped ~450 chars + persons + dominant emotion; skipped for internal person_ids)
9. **`--- PROJET EN COURS ---`** (matching engagement — title, tone_directive, instructions, out_of_scope, emotion_policy, todo tasks). When `emotion_policy=OFF`, suppresses the emotion block below.
10. **`--- CONTEXTE MODULES ---`** (email backlog, RSS unread, etc.)
11. **`--- TON ETAT EMOTIONNEL ACTUEL ---`** (global mood with ambivalent blend phrasing + drives). *Suppressed* in professional mode.
12. Memory context (semantic retrieval of relevant souvenirs/connaissances)

Personality + self-concept + person-context + circadian are the "slow" layers; module/emotion/memory/user-mood/fatigue/ruminations/dream/project are recomputed every turn. Recency bias places the latter last.

**Speech flow**: WebSocket `speech` event → `isEmotionName` validation → face (`EmotionController`) + body (`AnimationSystem.setEmotion`: gaze bias, hand mood, head-pose overlay, gated gesture) + UI → TTS + lip-sync. Deliberately the same path as a reply, with one flag: the difference between "what she just said" and "where her mood drifted" is which gestures are allowed, not which controllers are written.

**Sleep visual flow**: backend `SleepCycle._set_phase()` → `broadcast_inner_state_update` → `WebSocketClient` dispatches `inner_state_update` → `InnerLifePanel` applies state → `onSleepPhaseChange` fans out to `AnimationSystem.setSleepPhase()` + `Environment.setSleepPhase()`. A `.vrm` file at [frontend/public/models/default.vrm](frontend/public/models/default.vrm). Without it, a placeholder capsule+sphere is rendered.

## Key Conventions

- **29 emotions**: `neutral` | `happy`, `excited`, `love`, `proud`, `grateful`, `playful`, `amused`, `hopeful`, `relieved` | `sad`, `angry`, `scared`, `disgusted`, `frustrated`, `lonely`, `anxious`, `bored`, `jealous` | `surprised`, `thinking`, `confused`, `embarrassed`, `nostalgic`, `dreamy`, `determined`, `mischievous`, `curious`, `melancholic` — in `emotion/types.py::Emotion`
- **Emotion tag**: `[EMOTION:name:intensity]`. Legacy `[EMOTION:name]` = intensity 0.7
- **WebSocket protocol** — a *synchronised* protocol, not fire-and-forget. `group_send` drops silently when a group has no member, and nothing ever replayed it: every reply produced while a tab was disconnected was recorded in the database and **invisible in the UI forever**, while the user's own message stayed on screen because it is painted *before* it is sent. Frames:
  - Client → server: `{"type":"chat","message":"...","person_id":"...","client_msg_id":"...","attachments":[...]}`
  - Server → client (reply): `{"type":"speech","text":"...","emotion":"...","emotion_intensity":0.75,"emotion_blend":[{"emotion":"...","weight":0.x}, ...],"emotion_state":{...},"source":"...","inner_state":{...},"speak":true,"voice_reason":"screen_ok","voice_persona":"speaking|inner","voice_profile":{"pitch":1.0,"rate":1.0,"gain":1.0}}` — voice fields from [pipeline/voice.py](backend/pipeline/voice.py); `speak:false` means show the text but stay silent. Additionally carries `message_id` / `user_message_id` / `client_msg_id`, so the cursor advances during a normal conversation and an optimistically-painted bubble can be bound to its server row.
  - Client → server (identity handshake, first frame): `{"type":"identify","person_id":"...","display_name":"..."}`. A `person_id` smuggled in a later `chat` frame is **ignored** — identity is bound at connect/identify time only
  - Server → client (state refresh, no TTS): `{"type":"inner_state_update","inner_state":{...}}` — pushed by `broadcast_inner_state_update()` when inner state changes outside a turn (sleep transitions, project action queued). Goes to the **global** group because it is about Mika, not about anyone; passing a `person_id` sends it to *that person's* group instead, since `_collect_inner_state` then attaches their profile and commitments.
  - Server → client (emotion refresh, no TTS): `{"type":"emotion_update","person_id","emotion","emotion_intensity","emotion_blend":[...],"emotion_state":{...}}` — pushed to that person's group by `emotion.sync`. Applied as ambient drift (face + gaze + hand mood + idle posture, never a body one-shot, never TTS).
  - Server → client (project report, no TTS): `{"type":"project_report","project_id","project_title","text"}`
  - **Server → client (history)**: `{"type":"history","mode":"initial"|"catchup","messages":[{id, role, text, ts, source, emotion, emotion_intensity, attachments}],"last_id":N,"truncated":bool}` — sent unprompted at connect and in answer to a `sync`. Served by [communication/history.py](backend/communication/history.py), which asks two deliberately **separate** questions: `recent_for` ("what should I show a client that just opened?") and `after_for` ("what did this client miss?"). Ordered by `pk`, never `created_at` (`auto_now_add` collides on rapid inserts and a cursor must be totally ordered). Internal scaffolding excluded by the same `is_internal` rule the model's rehydrated buffer applies. `truncated` is reported rather than hidden: a silent cap would advance the cursor past messages never rendered.
  - **Client → server (catch-up)**: `{"type":"sync","after_id":N}` — the cursor is the highest `Message.pk` actually *rendered*, derived from the displayed thread, so it can never claim delivery of a frame a throwing handler dropped. `0` = "I have nothing trustworthy" → recent window instead of a diff.
  - **Keepalive**: `{"type":"ping","t":…}` → `{"type":"pong","t":…}`. A browser cannot send or observe protocol-level ping frames, and a socket killed by a sleeping laptop or a proxy often **never fires `onclose`**: it sits at `readyState === OPEN` and silently swallows everything written to it. The client pings every 20s and force-reconnects after 50s of silence (two missed pongs), and also on `visibilitychange`/`online`/`focus`.
  - **Server → client (ack)**: `{"type":"ack","client_msg_id":"…","status":"accepted"|"rate_limited"|"empty"|"overloaded"|"too_long"|"attachments_rejected"}` — emitted **after the submission and before the answer**. "The server has it" and "she answered" are different facts; but `turn_queue.submit` does not block, so acking *before* it bought nothing and cost a lie. Every refusal is said out loud and says **which** one. `too_long` and `attachments_rejected` exist because those messages used to disappear: the text was silently cut to `MAX_MESSAGE_LENGTH` (browser and DB then held two different sentences), and the empty-message guard tested the *raw* attachment list, so five oversized files with no caption passed it, validated down to zero, and sent `User: ` into the pipeline while the sender was told "accepted". **An `accepted` may carry `rejected_attachments: [{name, reason}]`** (`too_many` / `too_large` / `invalid`, capped at `MAX_REJECTED_REPORTED` so the ack cannot amplify a tiny frame into a large one): the all-or-nothing refusal only covers the case where *nothing* survives, and a partial send left the same divergence one rung lower — three captures typed, two described, and both sides believing they agreed. `validate_attachments` therefore returns `(retenues, écartées)` rather than the survivors alone, and the client paints the missing files under the bubble.
  - `inner_state` payload shape: `{person_scope, drives, energy, circadian, sleep_phase, today_journal?, last_dream?, projects?, pending_project_actions?, self_narrative?, ruminations, identity?, person_profile?, pending_commitments?}`. **`person_scope` says which question the payload answers.** A section with nothing to report is *omitted*, so "she knows nothing about you" and "this frame is not about anyone" arrived byte-identically — and the panel clears a section it is handed nothing for, which is right for the first and wrong for the second (every sleep transition wiped the identity block from every browser). `false` means the per-person keys carry no information and must be left alone.
  - **A targeted reply is never dumped on the global group.** "No presence entry" means *they are not connected*, not *there is no recipient* — and the payload carries that person's `inner_state`, so falling back to `BROADCAST_GROUP` landed a message composed for Adrien in every other open browser. An identifiable person offline now gets silence; nothing is lost, since the turn is persisted and their client pulls it by cursor. The global group stays right for what belongs to no one — an `anon_*` socket with no durable thread, `conscience_mika` thinking out loud.
- **Perception Intent**:
  - `REQUEST_RESPONSE` — user/channel expects an answer (default)
  - `OBSERVATION` — passive stimulus (camera frame, ambient audio, file drop). No forced response; conscience observes.
  - `INTERNAL_TRIGGER` — Mika-driven (conscience `_act`, module `notify_ai`, drive overflow, rumination resurfacing). Broadcasts; `emit_event=False`.
- **Person identification**: transport handles (`user_{pk}`, `web_*`, `tg_{user_id}`, `anon_*`) are resolved to memory `Entity` rows **through the identity layer**, never by name equality. Internal IDs `conscience_mika`, `__global__`, `anonymous` are reserved and never identified.
- **Personality is config-driven**: edit [personality.yaml](personality.yaml) (name, language, tone, traits, quirks, values) — no code changes. The **temperament is not there**: it is five dashboard sliders (Configuration → Émotion → Tempérament).
- **Singletons** (module-level, imported throughout): `ai_router` (`ai.router`), `ai_client` (`ai.client`), `memory_manager` (`memory.manager`), `emotion_engine` (`emotion.engine`), `drive_engine` (`drives.engine`), `personality` (`config.personality`), `module_manager` (`modules.manager`), `conscience_engine` (`conscience.engine`), `narrative_generator` (`memory.narrative`), `person_profile_generator` (`memory.person_profile`), `sleep_cycle` (`memory.sleep`), `project_runner` (`projects.runner`). Circadian is pure-function only — any caller passes the current `datetime` + the personality's `CircadianProfile`.
- **Background loops**: the four dedicated loops (consolidator, sleep cycle, project runner, emotion sync) share [utils/periodic.py](backend/utils/periodic.py)::`PeriodicLoop` — idempotent `start`/`stop`, first tick after one interval (never during startup), and a tick failure logged rather than propagated. That last property is load-bearing: **nothing supervises these loops**, so an escaping exception ends one for the lifetime of the process. Deliberately minimal — no jitter, no backoff, no supervision tree; the module cron scheduler has different needs (per-module intervals, detached ticks) and does not use it.
- **Django settings** in [config/settings.py](backend/config/settings.py): `PROJECT_ROOT` = repo root (where `.env` and `personality.yaml` live), `BASE_DIR` = `backend/`
- **INSTALLED_APPS**: `ai`, `communication`, `emotion`, `drives`, `memory`, `conscience`, `modules`, `projects`, `identity`, `files`, `GestionSysteme`, `configs`
- **Adding a new input source** (Discord, webhook): write an adapter that builds a `Perception` and calls `pipeline.router.perceive()`. No pipeline changes needed.
- **Adding a new modality** (ultrasound sensor): add a preprocessor in [pipeline/preprocessors/](backend/pipeline/preprocessors/) and register its dispatch entry. Router + processor pick it up automatically.

## Authentication

Provider credentials are **configured in the dashboard**, not in `.env`. `/gestion/` → Configuration → *IA · Claude*:

1. **OAuth Token** (recommended): `ai.claude.oauth_token`. Handed to the Claude Agent SDK as `CLAUDE_CODE_OAUTH_TOKEN` at call time.
2. **API Key**: `ai.claude.api_key` (requires a paid Anthropic account).

OAuth tried first, API key as fallback. OAuth tokens start with `sk-ant-oat01-`; API keys with `sk-ant-api`. Values are encrypted at rest (`configs/secrets.py`) and redacted in every read path.

**The credential never touches `os.environ`.** `claude_agent_sdk` reads it only from the environment it hands its CLI subprocess, built as `{**os.environ, **options.env, …}` — so `ClaudeProvider` carries it in `ClaudeAgentOptions(env=…)` and *pops* both variables from the process environment at `__init__`. A variable set there is global and outlives the instance, so the credential-change eviction (`_PROVIDER_CONFIG_PREFIXES`) did not reach it: after a rotation OAuth → API key, the revoked `CLAUDE_CODE_OAUTH_TOKEN` stayed and kept priority CLI-side. Every tool-enabled turn 401'd while `test()` — which uses the freshly-built `AsyncAnthropic` client — answered `{"ok": true}` and the config page showed green. The pop also means a secret deleted from the database stops existing in clear in the process and in every subprocess it spawns.

A credential alone is not enough: declare a model under *IA · Modèles* and map the roles under *IA · Rôles*, or every turn answers "Mon IA n'a pas de modèle associé".

## Configuration

**Everything applicative is configured in the dashboard** (`/gestion/` → Configuration), stored in `ConfigValue`, read at runtime through `config_service.get("<key>")`. `.env` holds infrastructure only — the things Django needs before a database exists.

The `ConfigItem.env_fallback` **field** and `seed_from_env()` have been removed, along with ~31 `settings.py` constants that existed only to feed them. Reasons, in increasing severity:

1. **Two declared defaults per knob.** The settings one always won at seed time, so the registry default — the one a reader looks at — was decorative and free to drift.
2. **The bridge silently didn't work for seven keys** because it read a *settings attribute* nobody had declared: `GEMINI_API_KEY`, `GLM_API_KEY`, `AI_ROLE_VISION_CAPTION`, `AI_ROLE_INNER_VOICE`, `EMOTION_DECAY_RATE`, `SLEEP_CHECK_INTERVAL`, `PROJECT_RUNNER_INTERVAL`. Five were documented as supported.
3. **`AI_ROLE_*` could only ever seed a broken value** — they carried the legacy `provider:model` string while `AIRouter._resolve` looks the value up as an **internal name** from the `ai.models` record list, so the seeded value raised `UnconfiguredRoleError`.
4. Once seeded, `.env` was inert forever with no feedback.

**The two seed-on-first-boot paths are gone with it**, for the same reason wearing a different hat. `IMAP_*`/`SMTP_*` created an `EmailAccount` row and `RSS_FEEDS` created `RSSFeed` rows — both only against an *empty* table, so after the first boot the variable was inert with no feedback, and a credential rotated in `.env` silently did nothing. Accounts and feeds are ORM rows edited in the dashboard; there is no second way to declare one. Nothing migrates: an install that had been seeded already holds its rows in the database and is unaffected.

A fresh clone therefore starts **unconfigured, on purpose**. Every non-role knob carries a working registry default, so the background loops run regardless.

Guarded by tests: `ConfigItem` cannot even *declare* an `env_fallback` (the dataclass field is gone, so re-adding it is a deliberate edit rather than a line slipped into one schema), no `settings.py` constant shadows a config key, no `AI_ROLE_*` constant survives, no credential or module-config constant survives (asserted on prefixes — `POP3_USER` would be the same mistake under a new name), and every operational knob has a default.

### What `.env` still holds

| Variable | Default | Description |
|----------|---------|-------------|
| `DEBUG` | `True` | Django debug mode |
| `DJANGO_SECRET_KEY` | `dev-secret-change-me` | Session/CSRF signing key |
| `CONFIG_ENCRYPTION_KEY` | derived from `DJANGO_SECRET_KEY` | Fernet key (32 base64-urlsafe bytes) encrypting every `sensitive` config value. Read straight from `os.environ` by [configs/secrets.py](backend/configs/secrets.py), **not** through `settings` — it was declared nowhere, so the `getattr` always read `""` and the PBKDF2-on-`SECRET_KEY` path was the only one ever taken: on a default install the at-rest encryption reduced to a documented derivation of `dev-secret-change-me`. Set it to decouple the two, so rotating `DJANGO_SECRET_KEY` (ordinary session hygiene) doesn't make every stored secret undecryptable. A malformed value is refused at startup by `ConfigsConfig.ready()` rather than at the first `encrypt` |
| `API_HOST` | `127.0.0.1` | Bind address. Loopback by default — the dashboard reads conversations and edits provider keys |
| `API_PORT` | `8000` | Backend port |
| `ALLOWED_HOSTS` | loopback names | Host-header allow-list. Not `*`; adds the machine's hostname/IP when `API_HOST` is not loopback |
| `VTUBER_NAME` | `Mika` | Display name at startup |
| `TIME_ZONE` | `Europe/Paris` | Aligns ORM `__date` bucketing with the naive local clock the circadian/sleep/journal logic uses |
| `DB_LOCK_TIMEOUT` | `30` | SQLite busy timeout (s) |
| `DASHBOARD_REQUIRE_AUTH` | `False` | Require an authenticated **staff** user for `/gestion/*` |
| `CONSUMER_REQUIRE_AUTH` | `True` | Refuse unauthenticated WebSocket connections |
| `LOGIN_URL` | `/admin/login/` | Where the dashboard gate redirects |
| `OWNER_PERSON_IDS` | `[]` | Extra person ids treated as the operator (read via `getattr`) |
| `CORS_ALLOW_ALL_ORIGINS` | `False` | Not wildcarded: the dashboard API would otherwise be readable by any visited page |
| `CORS_ALLOWED_ORIGINS` | dev frontend ports | Explicit allow-list |
| `CORS_ALLOW_CREDENTIALS` | `True` | Required — the SPA authenticates by session cookie |
| `CSRF_TRUSTED_ORIGINS` | = `CORS_ALLOWED_ORIGINS` | Origins allowed to submit a CSRF-protected request |
| `CHROMA_PERSIST_DIR` | `data/chromadb` | ChromaDB on-disk location |
| `EMBEDDING_MODEL` | `paraphrase-multilingual-MiniLM-L12-v2` | Sentence-transformer for ChromaDB |
| `FORGE_DIR` | `data/forge_modules` | Confined directory for AI-forged modules |
| `SESSION_COOKIE_SAMESITE` | `Lax` | Also the default for `CSRF_COOKIE_SAMESITE` |
| `AI_QUOTA_ROLE_<ROLE>_DAILY` / `_MONTHLY` | `0` | Per-role token caps. Read by **computed name** in `ai/quota.py`, so they are settings constants rather than config keys |

That table is the whole list — `.env.example` reproduces it and declares nothing else. Everything else lives in the dashboard: AI providers and their credentials, model declarations, role mapping, timeouts, all loop cadences, memory/emotion/conscience/project tuning, the Telegram token, email accounts, RSS feeds.
