# 0026 — Claude Code comme moteur (la CLI, son login, un relais MCP)

**Contexte.** On veut pouvoir faire penser Mika avec la vraie CLI `claude -p`, sur l'abonnement de sa propriétaire, avec accès à tout ce qu'elle sait faire (souvenirs, image de soi, buts, forge, modules), rôle par rôle. La v1 avait réutilisé un jeton OAuth hors de la CLI ; ce chemin a été retiré et reste interdit. La v2, elle, a une règle : la boucle d'outils vit une seule fois, dans le runtime (validation, plafonds par épisode, preuve de `report_step`, écritures corrélées à l'épisode, traces, préemption). Une CLI qui exécuterait elle-même les outils contournerait tout ça.

**Décision.**
1. *La CLI est le cerveau, le runtime reste les mains.* Un fournisseur `claude_code` (`adapters/llm/claude_code.py`) implémente le port LLM comme les autres. Au premier tour d'une boucle (même `call_id` d'un tour à l'autre), il lance `claude -p` ; quand la CLI appelle un outil, le **relais MCP** (`adapters/mcp/relay.py`) met l'appel en attente et le backend le rend au runtime (`stop="tool_use"`) ; le runtime l'exécute avec toutes ses gardes ; au tour suivant, le résultat revient à la CLI, qui continue. Rien ne change dans le pipeline, les gardes ou les baux.
2. *Aucun jeton ne passe par Mika.* Mode `abonnement` : la CLI s'authentifie comme pour son utilisatrice (sans `--bare`, qui ignore le login). Mode `cle_api` : une clé Console, scellée comme les autres. L'environnement du sous-processus est reconstruit sur liste blanche ; `CLAUDE_CODE_OAUTH_TOKEN` (et `ANTHROPIC_AUTH_TOKEN`) n'y passent jamais, même présents chez le parent ; `claude setup-token` n'est ni utilisé ni proposé.
3. *Isolation de la CLI* : `--setting-sources ""` (ni CLAUDE.md, ni réglages, ni hooks de l'utilisatrice), `--strict-mcp-config`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `ENABLE_CLAUDEAI_MCP_SERVERS=false` (sans lui, un login claude.ai charge ses connecteurs — Gmail, Drive — dans la tête de Mika), `--permission-mode dontAsk`, un dossier de travail vide. **Aucun outil natif** (`--tools ""`, ou `ToolSearch` seul quand des outils sont à la demande) : l'atelier et la Forge exécutent sous bubblewrap sans repli (ADR 0020, 0023), la CLI n'a pas de Bash.
4. *Le relais* : un serveur MCP par épisode (JSON-RPC « streamable HTTP », réponses JSON, `adapters/mcp/protocol.py`), monté sous `/mcp/relais`, qui ne sert que la boucle locale, avec un jeton aléatoire par session ; une session fermée répond 404 et libère ses appels en attente par une erreur. Écrit à la main plutôt qu'avec le SDK `mcp` : son gestionnaire de sessions ne s'ouvre qu'une fois (gênant pour une passerelle rechargée à chaud) et un appel tenu dont le client disparaît y finissait sur un flux fermé.
5. *Outils à la demande* (le contrat v1 des `ModuleCapability` : un catalogue, des outils chargés seulement si utiles) : chaque politique d'épisode dit ses lots « en main » (`EpisodePolicy.core_bundles` : conversation → mémoire, identité, buts ; initiative → mémoire, identité ; travail → tout) ; les autres lots offerts sont déclarés à la demande (`ToolDecl.deferred`). Le prompt stable porte un catalogue d'une ligne par lot (`Faculty.bundle`). Sur l'API Claude : `defer_loading` et la recherche d'outils BM25 ; avec la CLI : un serveur `mika` (`alwaysLoad`) et un serveur `mika_plus` que sa recherche d'outils charge. La sélection (qui a droit à quoi) ne change pas ; seule la présentation change.
6. *Accès à tout, sous la même porte* : ce qui n'était que poussé dans le prompt se relit aussi par outil (`self_read`, `self_yesterday`, `self_dream`, `attention_thoughts`, `social_about`, `goals_list`, `memory_promises`) — chaque outil appelle l'enrichisseur et la section de sa faculté, puis `kernel.prompt.readable` applique la seconde barrière du composeur. Un outil n'en dit jamais plus que le prompt.
7. *Repli et réserve* : chaque fournisseur peut nommer un repli (`fallback`) ; un échec (non connectée, CLI absente, délai, panne) repart une fois dessus, deux traces. La CLI rend l'usage de l'abonnement (`rate_limit_event`) : au-delà de `quota_ceiling` (0,8), les appels de fond sont retenus (`QuotaHeld`) et passent au repli ; la conversation n'est jamais retenue. Coût compté 0 $ en abonnement, au tarif Claude en mode clé.
8. *Arrêts* : une annulation (préemption, supplantation, délai) arrête le groupe de processus (SIGINT, puis SIGKILL) ; une session laissée sans suite (un rôle qui lit les appels d'outils comme sortie structurée) est fauchée après `idle_s` (900 s : plus que le programme d'atelier le plus lent).
9. *Correctifs trouvés en chemin* : `email_send` et `ws_network` émettaient `effect.proposed` au nom de leur faculté alors que le runtime en est propriétaire — `Mind` refusait : les deux outils ne pouvaient pas marcher. `ToolContext.propose` l'écrit au nom du runtime, pour une capacité de la faculté seulement. Les outils réservés aux propriétaires (`owner_only`) ne sont plus offerts à quelqu'un d'autre (`Audience.owner`), `forge_call` compris.

**Mesures (CLI 2.1.282, haiku, sur l'abonnement).** Lancement → `init` : 0,8 s ; premier appel d'outil : 2,2 s ; un `check` sans outils : 2,6 s. Appels d'outils partis en parallèle, regroupés en un tour. Un appel tenu 45 s passe (`MCP_TOOL_TIMEOUT`). SIGINT pendant un appel en attente : sortie en 0,7 s. Non connectée : sortie en 0,4 s, « Not logged in ». Essai réel de bout en bout : un outil en main appelé directement, un outil à la demande trouvé par la recherche d'outils de la CLI, les deux exécutés par la boucle du runtime, trois tours. Avec la recherche d'outils active, la CLI n'a lu ni écrit de cache sur ces essais.

**Conséquences.** Chaque rôle se route vers `claude_code` ou vers l'API dans la console, comme avant. Réserves : Mika et sa propriétaire partagent le quota de l'abonnement (d'où la réserve) ; le prompt en zones est aplati en un message (l'historique n'est plus relu depuis le cache d'un tour à l'autre) ; la doc annonce que `--bare` deviendra le défaut de `-p` — `mika claude-code check` le verrait aussitôt (« Not logged in ») et le repli prendrait le relais. Contrats : `tests/contract/test_claude_code.py` (une fausse CLI réelle, relais servi en HTTP) ; `tests/unit/test_tool_gates.py`.
